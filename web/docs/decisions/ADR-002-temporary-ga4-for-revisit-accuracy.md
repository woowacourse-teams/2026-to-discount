# ADR-002. 재방문 측정 정확도를 위해 GA4를 임시로 병행 도입한다

- 날짜: 2026-07-30
- 상태: 임시 채택 (재검토 필요)

## 맥락

delivery-discount-api의
[ADR-005](../../../delivery-discount-api/docs/decisions/ADR-005-first-party-analytics.md)는
외부 분석 도구(GA4 등)를 안 쓰기로 결정했다 — 제3자에게 데이터가 안
넘어가야 고지도 단순해지고, 이 프로젝트의 "비영리·개인정보 안 다룸"
성격과도 맞기 때문이다.

그런데 실제로 재방문을 재는 두 수단 다 정확도에 한계가 있다는 게
드러났다:

- **자체 분석(`src/analytics.js`)**: `visitCount`가 `localStorage`
  값이라, 사용자가 브라우저 데이터를 지우거나 다른 기기·브라우저로
  오면 같은 사람이어도 신규 방문자로 다시 잡힌다. 시크릿 모드나
  사파리 ITP 환경에서는 사실상 항상 신규로만 잡힐 수 있다.
- **Vercel Analytics**: 쿠키를 아예 안 쓰는 구조라 신규/재방문 구분
  기능 자체가 없다(Vercel 공식 문서·API·CLI 어디에도 이 세그먼트가
  없음을 확인함).

기획서(`docs/README.md`, delivery-discount-api)의 1차 목표가 "가설을
세우고 실험하고 관찰한 뒤 반영"인데, 그 중 재방문 여부가 가장 중요한
신호 중 하나다. 지금 시점엔 이 신호의 정확도·무결성이 프라이버시
최소화 원칙보다 우선한다는 판단.

## 결정

**GA4를 임시로 병행 도입한다** (측정 ID `G-7T4DN0NXV5`, `src/ga4.js`).

- 자체 분석·Vercel Analytics는 그대로 유지 — GA4가 이들을 대체하지
  않는다. 신규/재방문 구분만 GA4에 기댄다.
- ADR-005의 원칙을 최대한 지키려고:
  - `allow_google_signals: false`, `allow_ad_personalization_signals: false`
    — 광고 개인화용으로는 안 쓴다.
  - `src/analytics.js`의 `optedOut()`(DNT/GPC 신호)을 그대로 재사용 —
    추적 거부 시 GA4 스크립트 자체를 안 띄운다.
- `SiteFooter`(`src/App.jsx`) 고지 문구에 GA4를 추가하고, **다른 둘과
  달리 쿠키를 쓰고 데이터가 Google로 전달된다는 사실을 그대로 밝힌다**
  — README의 "법적 성격을 밝히는 자리라 임의로 축약하지 않는다"는
  원칙을 따름.

## 대가

- ADR-005가 피하려던 것(제3자 데이터 전달, 쿠키)을 GA4 범위 안에서는
  그대로 감수한다.
- "쿠키를 안 쓴다"는 기존 포지셔닝이 부분적으로 깨진다 — GA4만 예외라고
  고지문에 명시했다.
- 광고 신호를 껐어도 Google이 자사 정책하에 집계 데이터를 어떻게 쓰는지는
  우리가 완전히 통제할 수 없다 — 그래서 고지문에 "광고 목적으로 쓰지
  않는다"를 GA4에는 적용하지 않고, "저희 쪽에서 광고 개인화 신호는
  껐다"로 한정해서 썼다.

## 제거 조건 (임시 조치이므로)

아래 중 하나가 되면 제거를 검토한다:

- 재방문 정확도를 확인하려던 목적(가설 검증에 필요한 최소 기간의 데이터
  확보)을 달성했을 때.
- 자체 분석(`analytics.js`)의 재방문 측정 방식이 개선돼(예: 기기 간
  연동 없이도 충분한 정확도 확보) GA4 없이도 신뢰할 수 있는 수치가 나올 때.
- 트래픽 규모가 작아 GA4 없이도 표본으로 충분하다고 판단될 때.

제거 시 함께 되돌릴 것: `src/ga4.js`, `main.jsx`의 `startGa4()` 호출,
`SiteFooter`의 GA4 관련 문단, 이 README의 "세 가지" 서술.
