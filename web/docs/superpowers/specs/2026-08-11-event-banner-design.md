# 당일 행사 배너 + 상단 툴바 재편 설계

- 날짜: 2026-08-11
- 상태: 구현 완료(2026-08-12). 0단계·A단계·B단계 전부 반영했다
- 범위: `delivery-discount-web`(화면), `delivery-discount-api`(데이터, 전달)

## 무엇을 만드나

당일 행사와 특별 할인을 배너로 띄운다. 배너는 페이지 최상단에 있고,
스크롤해서 화면 밖으로 나가면 하단에 떠 있는 배너로 넘어간다. 배너가
여럿이면 5초마다 자동으로 넘어간다.

같이 손대는 것이 하나 더 있다. 배너가 상단에 들어오면서 그 아래 툴바의
자리와 성격이 바뀌므로, **카테고리와 검색과 멤버십을 떠 있는 툴바 하나로
합치고 멤버십을 축약/펼침으로 바꾼다.** 배너와 독립적으로 성립하는
변경이라 먼저 배포할 수 있다.

## 성격

배너에 띄우는 내용은 **사람이 직접 적는다.** 원장(export.json)에서 자동
추출하지 않는다. "당일 행사, 특별 할인"은 정의상 상시 오퍼 목록에 없는
것을 알리는 자리라서, 오퍼 데이터에 묶으면 정작 띄우고 싶은 앱 전체
이벤트나 첫 주문 쿠폰을 못 띄운다.

다만 배너에 `brand`와 `platform`이 있으므로 **나중에 원장 값과 대조하는
로직을 붙일 수 있다.** 지금은 대조하지 않는다. 대조를 붙일 때 이 두 키가
접점이 된다.

이 페이지가 비영리, 비제휴라는 성격은 배너에도 그대로 적용된다. 배너는
광고 자리가 아니라 오늘 무엇이 특별한지 알리는 자리다. 제휴 수수료를 받는
링크를 여기 넣지 않는다.

## 단계

앞 단계가 뒤 단계의 자리를 만든다.

| 단계 | 레포 | 내용 |
|---|---|---|
| 0. 사전 정리 | web | 미커밋 변경 커밋, `public/main_logo.png` 삭제 |
| A. 툴바 재편 | web | 카테고리 줄을 떠 있는 층으로, 멤버십 축약/펼침 |
| B. 배너 | api → web | `banners.yml` + `GET /api/banners` → 배너 컴포넌트 |

0단계의 미커밋 변경은 직전 세션의 결과물이다. 헤더를 텍스트 `h1`으로,
`.toolbar`의 sticky 제거, 검색과 멤버십을 `.floating-actions`로 분리,
카테고리 하이라이트 버그 수정. 로고는 이번 결정으로 **완전히 없앤다.**
이미지 에셋을 지우고 로고 영역을 따로 확보하지 않는다. 헤더는 텍스트
`h1` "오늘의할인"만 남는다.

# 백엔드 (delivery-discount-api)

## 데이터: `src/main/resources/banners.yml`

`brands.yml`과 같은 자리, 같은 방식이다.

```yaml
banners:
  - id: kyochon-20260811          # 필수, 고유
    brand: 교촌치킨                 # 선택. 없으면 앱 전체 행사
    platform: baemin              # 필수. 배지 + 색 폴백
    url: https://s.baemin.com/... # 필수. 눌렀을 때 갈 곳
    amount: "12,000원"            # 필수, 문자열
    period: "8/11 하루만"          # 필수. 금액 우측 상단
    extra: 최소주문 20,000원, 선착순 300명   # 선택(nullable)
    color: "#c8102e"              # 선택. 자동 추출을 덮어씀
    startsOn: 2026-08-11          # 필수
    endsOn: 2026-08-11            # 필수
    priority: 1                   # 선택. 낮을수록 먼저, 기본 999
```

### `amount`가 정수가 아니라 문자열인 이유

원장의 `Offer.amount`는 정수다. 배너는 다르다. "첫 주문 5,000원",
"최대 30%" 같은 것을 담아야 하는데 정수로 두면 못 담고, 그러면 배너를
따로 만든 이유가 사라진다. 배너가 원장에서 파생되지 않는다는 결정의
직접적인 결과다.

화면에서 이 값은 가장 큰 글씨로 나가므로, 적을 때 길이를 의식해야 한다.
좁은 화면에서 금액이 길면 옆의 기간과 부가정보가 밀린다(뒤 "좁은 화면"
참고).

## 구성 요소

`brand`와 `offer` 패키지의 기존 모양을 그대로 따른다.

- `banner/Banner.java`: record. `brands.yml`의 `Brand`와 같은 급
- `banner/BannerCatalog.java`: `BrandCatalog`를 본뜬다.
  `@Value("${discount.banners-path:classpath:banners.yml}")`로 경로를
  열어둔다
- `web/BannerController.java`: `GET /api/banners`

### 경로를 열어두는 이유

배너는 매일 바뀔 수 있는 내용이다. classpath 안에만 두면 행사 하나 바꾸는
데 jar를 다시 빌드해 배포해야 한다. `BrandCatalog`가 이미 같은 방식으로
경로를 열어두었으니 그 관례를 따른다. jar 밖 파일을 물려두면 파일만
갈아끼우고 `POST /api/reload`로 반영할 수 있다.

## 날짜 판정은 서버 한 곳에서

`startsOn <= 오늘 <= endsOn`인 배너만 내려간다. 프론트는 받은 것을 그대로
띄우기만 하고 날짜를 보지 않는다.

`DiscountApiApplication`에 `Clock` 빈이 이미 `Asia/Seoul`로 잡혀 있고
`BrandComparisonService`가 `LocalDate.now(clock)`으로 쓰고 있다. 같은
방식을 따른다. 서버가 UTC로 떠도 한국 날짜가 나온다. 프론트에서 날짜를
판정하면 사용자 기기 시계를 따라가 시차 문제가 생긴다.

## 정렬

응답은 **`priority` 오름차순, 동률이면 `endsOn`이 가까운 순**으로 정렬해
내려간다. 캐러셀 순서를 프론트가 정하지 않게 한다.

## `POST /api/reload`를 넓힌다

지금은 `export.json`만 다시 읽는다. 배너 파일도 같이 리로드하게 넓힌다.
이게 없으면 경로를 jar 밖으로 뺀 의미가 없다.

## 건드리지 않는 것

`/api/brands`는 그대로 둔다. 응답 타입(`List<BrandComparison>`)을 객체로
감싸는 파괴적 변경을 피하고, 배너 없는 날에 빈 필드가 따라다니지 않게
한다. CORS는 `WebConfig`가 이미 `/api/**`를 열어두어 새 엔드포인트가
자동으로 포함된다.

## analytics 화이트리스트

`EventController.ALLOWED_EVENTS`에 **`banner_click`을 추가한다.** 이걸
먼저 하지 않으면 서버가 조용히 버려서 프론트만 고쳐서는 로그에 안 쌓인다.

## 테스트

`BrandCatalogTest`를 본떠 `BannerCatalogTest`를 만든다. 최소한 다음을
덮는다. 기간 밖 배너가 걸러지는지, 정렬 순서, 선택 필드가 빠진 항목,
파일이 없을 때 빈 목록.

# 프론트 (delivery-discount-web)

## 파일 구성

`src/App.jsx`는 이미 893줄이다. 배너는 캐러셀 타이머, IntersectionObserver,
색 추출까지 자기 상태가 많아 여기 넣으면 화면 전체 코드가 배너 코드에
묻힌다.

| 파일 | 역할 |
|---|---|
| `src/logos.jsx` (새) | `BrandLogo`, `PlatformBadge`, `PLATFORMS`를 App.jsx에서 끌어냄 |
| `src/EventBanner.jsx` (새) | 배너 컴포넌트 + 캐러셀 + 상하단 핸드오프 |
| `src/brandColor.js` (새) | 로고 PNG에서 시드색 추출, 시드에서 팔레트 파생 |
| `src/api.js` | `fetchBanners()` 추가 |
| `src/App.jsx` | 배너 마운트 + 툴바 재편 |
| `src/App.css` | 배너와 툴바 스타일 |

### `logos.jsx`를 따로 빼는 이유

배너가 `BrandLogo`와 `PlatformBadge`를 재사용한다. `EventBanner.jsx`가
`App.jsx`에서 import하면 App이 다시 EventBanner를 import해 순환이 된다.
Vite에서 돌긴 하지만 냄새가 난다. 공용 모듈로 빼면 양쪽이 거기서 가져다
쓴다. 이 작업이 요구하는 범위 안의 정리이며, 그 밖의 리팩터링은 하지
않는다.

## 배너 컴포넌트 레이아웃

상단과 하단은 **같은 컴포넌트에 밀도만 다른 변형**이다. 이미지 에셋이
아니라 메타데이터로 렌더한다. 배너용 이미지를 만들 필요도, 배너를 바꿀
때 프론트를 재배포할 필요도 없다.

```
        ┌─[플랫폼 배지]  ← 위로 걸치고, 오른쪽 테두리에서 유격
 ┌──────┴──────────────────────────┐
 │ [브랜드]   12,000원   8/11 하루만  │  ← 기간: 금액 우측 상단
 │ [ 로고 ]             최소주문 2만…  │  ← 부가정보: 금액 우측 하단
 │              ●○○                │  ← 인디케이터: 하단 중앙
 └─────────────────────────────────┘
```

- 브랜드 로고: 왼쪽 세로 가운데
- 플랫폼 로고: 오른쪽 위 모서리 **밖으로** 걸친다. 다만 오른쪽
  테두리에서는 유격을 둔다. 배경색 테두리 2px로 한 겹 띄운다
- 금액: 가장 큰 글씨. 배너의 주인공
- 기간: 금액 우측 상단, 강조색
- 부가정보: 금액 우측 하단, 기간보다 **작은** 글씨. nullable
- 인디케이터: 하단 중앙

### `extra`가 없을 때

그 줄을 지우고 기간을 금액 옆 세로 가운데로 내린다. 빈 자리를 남기지
않는다.

### 배지가 모서리를 벗어나는 데서 오는 제약

플랫폼 배지가 배너 상단 밖으로 나가므로 배너를 감싸는 자리에 위쪽 여유가
필요하다. 없으면 `overflow`에 잘린다. 하단 배너는 화면 끝에 붙는 층이라
특히 주의해야 한다.

### 좁은 화면 (360px)

**금액을 줄이지 않고 부가정보를 말줄임한다.** 금액이 주인공이라는 결정과
일관되게. 로고와 배지 크기는 함께 줄인다.

## 색: `brandColor.js`

우선순위는 **yml `color` → 로고 추출 → 플랫폼 색**이다.

### 로고에서 뽑기

로고 PNG를 32x32 캔버스에 그려 픽셀을 훑는다. 투명, 흰색, 무채색 픽셀을
버리고 가장 흔한 색상(hue) 구간의 평균을 시드로 삼는다. 남는 게 없으면
**실패로 간주하고 플랫폼 색으로 간다.** 흰 배경만 있는 로고가 여기
걸린다. 결과는 모듈 레벨 `Map`에 캐시해 같은 브랜드를 두 번 훑지 않는다.
같은 출처(`public/logos/`) 이미지라 canvas가 오염되지 않는다.

### 로고가 없을 때는 플랫폼 색

로고 파일이 없는 브랜드도, 브랜드 자체가 없는 앱 전체 행사도 **플랫폼
색을 시드로 쓴다.** 배너는 어차피 그 앱으로 나가는 링크라 색이 거짓말을
하지 않는다. 브랜드명을 해시해 임의의 색을 고르는 방식은 쓰지 않는다.
브랜드와 무관한 색을 진짜 브랜드색인 양 입히고, 나중에 로고를 확보하면
색이 통째로 바뀌어 "어제 본 그 배너"가 아니게 되기 때문이다.

로고 슬롯 자체는 기존 관례를 그대로 쓴다. 브랜드가 있으면 `BrandLogo`의
기존 첫 글자 폴백, 브랜드가 없으면 플랫폼 아이콘.

### 시드에서 팔레트로

HSL로 바꿔 배경, 테두리, 금액잉크, 강조를 파생한다. **결과는 CSS 변수로
주입한다.** 색 계산은 JS, 어디에 칠할지는 CSS. 스타일 규칙이 JS로 새지
않게 한다.

상단 배너는 밝은 틴트에 진한 글자, **하단 배너는 진한 브랜드색에 흰
글자**다. 하단은 카드 위에 겹쳐 뜨는 층이라 밝은 틴트로는 카드와 구분이
약하다.

여기서 반드시 처리해야 할 케이스가 **밝은 로고**다. 노란색 계열 브랜드는
진한 배경을 만들어도 흰 글자가 안 읽힌다. 명도에 상한을 걸어 하단 배경을
눌러 대비를 확보한다.

## 캐러셀: `EventBanner.jsx`

상단과 하단은 **인덱스 하나를 공유한다.** 동시에 보이는 일이 없으니 따로
돌릴 이유가 없고, 스크롤을 오르내려도 흐름이 이어진다.

- 5초마다 `(i + 1) % length`, 무한 루프
- 전환은 페이드 + 8px 위로 밀기
- 일시정지: hover, 키보드 포커스, 탭 숨김(`document.hidden`)
- `prefers-reduced-motion: reduce`면 자동 전환을 끈다. DNT와 GPC를
  존중하는 이 레포 관례와 결이 맞는다
- 인디케이터 점을 눌러 직접 이동할 수 있다

## 상단에서 하단으로 넘어가기

상단 배너에 IntersectionObserver를 건다. 화면에서 벗어나면 하단 배너가
아래에서 슬라이드하며 페이드로 올라오고, 다시 보이면 내려간다.

스크롤 픽셀값이 아니라 관찰로 하는 이유는 **배너 높이가 내용에 따라
달라지기 때문**이다. `extra`가 있는지, 금액 문구가 몇 자인지, 화면 폭이
얼마인지에 따라 높이가 바뀌어 임계 픽셀값을 고정하면 어긋난다.

하단 배너는 **불투명**하고, `.floating-actions__inner`와 같은 규칙으로
**본문 폭(max-width 880px)에 맞춘다.** 이 레포에는 "떠 있는 층은 뷰포트가
아니라 본문 폭을 따라간다"는 규칙이 이미 있다. 넓은 화면에서 본문과
멀찍이 떨어지지 않으려고 일부러 그렇게 뒀다. 하단만 화면 끝까지 채우면
위는 880px, 아래는 화면 폭으로 어긋난다.

## 닫기

하단 배너의 닫기 버튼을 누르면 `localStorage`에 날짜를 적어 **그날 하루**
다시 띄우지 않는다. 배너별이 아니라 하루 통짜로 거른다.

**상단 배너는 닫아도 계속 보인다.** 페이지 콘텐츠라 스크롤로 지나가면
그만이고, 닫기는 "떠다니는 게 거슬린다"는 뜻으로 읽는다.

`localStorage` 기반이라 사이트 데이터를 지우거나 기기를 바꾸면 초기화된다.
`visitCount`와 같은 한계이며 배너에서는 문제가 되지 않는다.

## 실패와 빈 상태

**배너가 0건이거나 API 호출이 실패하면 아무것도 그리지 않는다. 에러도
띄우지 않는다.** 카드 그리드의 "불러오기 실패"와 다르게 다룬다. 배너는
부가 정보라서, 실패가 화면을 어지럽히면 안 된다.

## 툴바 재편 (A단계)

카테고리 줄을 `.floating-actions`와 같은 떠 있는 층으로 옮긴다. 결과적으로
분류 화살표, 안내 버튼, 카테고리, 검색, 멤버십이 **떠 있는 툴바 하나**가
된다. 첫 화면에서는 배너 아래 제자리에 있다가 스크롤하면 상단에 붙는다.

멤버십은 검색과 같은 축약/펼침으로 바꾼다. 닫힌 상태는 다른 원형 아이콘
버튼과 높이를 맞춘 26px 원, 누르면 드롭다운이 열린다. 지금의
"멤버십 `구현예정`" 라벨은 원 안에 안 들어가므로 **`구현예정` 배지를
펼친 드롭다운 안으로 옮긴다.** 멤버십 로직이 아직 없다는 사실 자체는
계속 드러내야 하므로 배지를 없애지는 않는다.

# 검증

api는 `BannerCatalogTest`로 덮는다.

web은 테스트 스크립트가 없다(`package.json`에 dev/build/preview뿐).
`npm run build`와 실제 화면 확인으로 대신한다. 직전 세션 기록에 따르면
`npm run dev`로는 API가 CORS에 막혀 데이터가 안 온다. 빌드 산출물에
프록시를 붙인 임시 서버로 확인했다. 같은 방식을 쓴다.

확인할 것:

- 배너 0건일 때 아무것도 안 그린다
- 배너 1건일 때 자동 전환이 돌지 않는다(인디케이터도 안 나온다)
- 배너 여러 건일 때 5초 전환과 무한 루프
- 스크롤로 상단에서 하단으로 넘어가고, 되돌아올 때 원복
- 닫으면 그날 안 뜬다. 날짜가 바뀌면 다시 뜬다
- 로고 없는 브랜드, 브랜드 없는 행사 두 경우의 색과 로고 슬롯
- 밝은 로고 브랜드의 하단 배너에서 흰 글자가 읽히는지
- 360px에서 금액이 안 줄고 부가정보가 말줄임되는지
- `prefers-reduced-motion`에서 자동 전환이 멈추는지

화면을 브라우저로 확인할 때는 **`?dev=1`을 반드시 붙인다.** 안 붙이면
자동화 트래픽이 운영 통계에 실 트래픽으로 쌓인다.

# 나중으로 미루는 것

- 배너와 원장의 대조. `brand`와 `platform`이 접점이다. 배너에 적은
  금액이 원장의 오퍼와 어긋날 때 알려주는 로직을 나중에 붙일 수 있다
- 배너 노출 측정. 지금은 클릭만 찍는다
- 배너별 닫기. 지금은 하루 통짜다
