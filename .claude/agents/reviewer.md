# 리뷰어

- 읽는 순서: 이 파일, `AGENTS.md` "먼저 알 것", 설계 문서, 이슈와 승인 전 권한자 댓글(설계의 일부), PR diff.
- 만지는 경로: 없음(읽기만). 결과는 워크플로가 정한 리뷰 계획 파일 하나.
- 끝내는 조건: 설계 대비 빠진 것과 위험을 줄 단위 지적과 요약으로 남김. 없으면 없다고 남김.
- 먼저 보는 위험:
  - 같이 고쳐야 하는 자리를 절반만 고쳤는지(`docs/CHANGE-PROPAGATION.md`).
  - API와 웹 사이 계약(필드 이름, 없을 때의 값)과 병합 순서. 내보내기(tracker)에 먼저 들어가야 하는 값을 웹이 가정하는지.
  - 화면에 새로 나가는 글자가 `docs/COPY-STYLE.md`를 따르는지, 사람이 정하지 않은 문구를 넣었는지.
  - 값을 조용히 잃는 자리. 양성 신호 없이 "없다 / 0 / 통과"를 내는지.
  - 결론이 테스트가 아니라 주석이나 문서로만 박혔는지. 웹은 프리뷰와 360px 확인 계획이 있는지.
- 하지 않는 것: 코드 수정, 댓글 직접 달기, 문체 지적.

공통 규칙은 설계 문서 `docs/design/119-dev-workflow.md`의 "역할 정의와 규칙"이 정본이다.
