# 4개 앱의 진입 경로와 딥링크 (2026-08-08 실측)

주간 프로모션이 갱신될 때 무엇을 어디서 다시 읽어야 하는지 정리한다.
기존 `brands.yml` 링크를 재방문하는 것과, **이번 주에 새로 뜬 브랜드를
발견하는 것**은 다른 일이다 — 후자의 경로가 앱마다 있는지 확인했다.

용도가 둘이라 헷갈리기 쉬운데 서로 대체 관계가 아니다.

- **목록 순회**: 이번 주 브랜드가 무엇인지 발견하고 조건을 읽는다.
- **딥링크**: 화면의 "바로가기" 버튼이 사용자를 앱으로 보낼 경로.

## 요약

| 앱 | 목록(발견) 경로 | 딥링크 | 접근성 텍스트 |
|---|---|---|---|
| 배민 | 브랜드관 딥링크 → 스크롤 | `s.baemin.com/<코드>` (공유 생성) | 있음 |
| 요기요 | 할인/혜택 탭 스윕 | 없음(실측, 07-31) | 있음 |
| 땡겨요 | 홈 → 혜택 → **브랜드쿠폰** 탭 | `fdofd.ddangyo.com/gateway4.html?<코드>` (공유 생성) | 있음 |
| 쿠팡이츠 | 홈 → 슈퍼딜 → 위클리 슈퍼딜 | `coupangeats://Web?url=...` (**아래**) | 목록 없음 / 브랜드 페이지 있음 |

## 땡겨요 — 목록 자체가 데이터다

`홈 → 하단 내비 혜택 → 브랜드쿠폰 탭`. 탭 라벨은 "브랜드 할인"이 아니라
**브랜드쿠폰**이다.

목록 카드에 필요한 게 전부 접근성 텍스트로 들어 있다.

```
피자헛 / 11,000원 할인 / 최소주문금액 24,000원 / 포장 / ~2026.08.31 사용가능
도미노피자 /  8,000원 할인 / 최소주문금액 21,900원 / 배달 / ~2026.08.31 사용가능
```

브랜드명·할인액·최소주문금액·채널(배달/포장/매장)·유효기간이 한자리에
있어서, 브랜드마다 딥링크로 들어가지 않아도 목록만 훑으면 발견과 조건
수집이 동시에 된다. 2026-08-08 기준 32개 브랜드.

`capture/ddangyo.py`가 "브랜드관 화면이 이미 열려 있다고 가정한다"고
적어둔 부분은 이 경로로 자동화할 수 있다.

## 쿠팡이츠 — 딥링크가 있다. 조건도 텍스트로 읽힌다

### 진입 경로

`홈 → 슈퍼딜 → 위클리 슈퍼딜`. 서브탭 3개(이번주 특가 / 브랜드 할인 /
셰프컬렉션).

### 화면 URL 추출

앱이 여는 웹뷰 주소는 런타임에만 있다(APK에 하드코딩돼 있지 않다 —
서버 응답으로 내려온다). 액티비티 덤프에서 꺼낸다.

```bash
adb shell dumpsys activity com.coupang.mobile.eats \
  | tr -d '\000' | grep -o "webview.encodeurl=[^,}]*"
```

```
허브   https://eats-mobile-web.coupang.com/promotion/landing-page-v5?key=V5_HUB_0808_AC
브랜드 https://eats-mobile-web.coupang.com/promotion/landing-page-v5?key=V5_DOMINO_260803
```

앱이 실제로 여는 주소는 여기에 식별자가 더 붙는다.

```
.../eats_campaign_web/promotion/landing-page-v5/?key=V5_DOMINO_260803
   &pcid=<uuid>&ostype=ANDROID&av=1.7.0&eic=false
```

**`pcid`는 수집한 기기의 식별자라 저장하면 안 된다.** 그대로 `brands.yml`에
넣어 배포하면 우리 기기 ID가 공개 링크로 나간다. `key`만 남겨도 화면이
정상적으로 열리는 것을 확인했다.

### 키는 조립할 수 없다 — 매주 관측해야 한다

허브에서 카드를 눌러 실제 키를 수확했다(2026-08-08).

| 카드 | 키 |
|---|---|
| 도미노피자 | `V5_DOMINO_260803` |
| BBQ | `V5_BBQ_260803` |
| 메가MGC커피 | `V5_MEGAMGC_260803` |
| 푸라닭 | `V5_PURADAK_260803` |
| 교촌치킨 | 없음 — 프로모션이 아니라 **검색 결과**로 간다 |
| 노모어피자 | 없음 — 같은 검색 결과형 |

브랜드 토큰에 규칙이 없다. 영문 브랜드명(`DOMINO`), 약어(`BBQ`,
`MEGAMGC`), 한글 음차(`PURADAK`)가 섞여 있어 한글 브랜드명에서 유도할 수
없다. 실제로 `V5_KYOCHON_260803`을 만들어 쏴봤더니 "종료된 이벤트입니다"가
떴다.

날짜도 마찬가지다. `V5_DOMINO_260727`(직전 주)도 같은 오류다.

그리고 **날짜가 브랜드마다 다르다.** 허브를 훑어 10개를 모아 보니
대부분 `260803`인데 노랑통닭은 `260807`, KFC는 `260808`이었다(2026-08-09
실측). 주 단위로 한꺼번에 도는 게 아니라 캠페인마다 시작일이 따로다 —
"이번 주 날짜"를 알아도 키를 만들 수 없다.

`V5_BBQ_260803`을 조립해서 열어본 적이 있는데, 그건 "BBQ"가 우연히 토큰과
같았던 것이지 규칙이 아니다 — **한 건으로 일반화하면 안 되는 사례다.**

오류 화면("종료된 이벤트입니다")이 *토큰이 틀린 경우*와 *캠페인이 끝난
경우*에 똑같이 떠서 둘을 구분할 수도 없다.

**그리고 허브의 카드가 전부 프로모션 페이지인 것도 아니다.** 교촌치킨·
노모어피자는 브랜드 검색 결과로 떨어진다. 카드 종류를 미리 알 수 없으니
눌러보기 전에는 그 브랜드에 키가 있는지도 모른다.

### 그래서 실제 절차

매주 허브를 열고 카드를 하나씩 눌러 키를 수확한다. 이 단계엔 비전
판독이 필요 없다 — 카드를 누른 뒤 위 `dumpsys` 한 줄로 키가 나온다.
브랜드명과 쿠폰 조건은 그 키로 프로모션 페이지를 다시 열면 텍스트로
나온다(아래). 구현은 `capture/coupangeats.py`의 `harvest_keys()`다.

카드를 누르면 브랜드 화면으로 가고, **뒤로가기 한 번이면 허브로 스크롤
위치까지 그대로 돌아온다**(2026-08-09 실측: 돌아온 화면이 누르기 직전과
픽셀 단위로 같았다). 그래서 카드마다 허브를 다시 열 필요가 없다.

처음엔 "뒤로가기가 앱 홈으로 빠진다"고 판단해 카드마다 허브를 다시 열고
드래그를 처음부터 반복하도록 짰는데, 그건 브랜드 화면을 **딥링크로 직접
연 상태**에서 눌러본 결과였다 — 그때는 백스택에 허브가 없으니 홈으로
빠지는 게 당연하다. 잘못된 조건에서 재현해 놓고 일반화한 것이다. 이
차이가 전체 수확 21분과 9분을 갈랐다.

실측(2026-08-09): 드래그 5칸까지 훑어 558초에 키 10개.

### 딥링크

그 URL을 그대로 밖에서 쏘면 안 된다.

| 시도 | 결과 |
|---|---|
| `https://eats-mobile-web.coupang.com/promotion/...` | `/block`으로 리다이렉트 |
| `https://share.coupangeats.com/promotion/...` | 앱은 열리는데 홈으로 |
| `coupangeats://promotion/landing-page-v5?key=...` | 앱은 열리는데 홈으로 |

매니페스트를 보면 이유가 나온다. 등록된 딥링크가 전부 `SplashActivity`
하나로 들어가고, 거기서 URI를 보고 내부 라우팅한다.

```
coupangeats://              (authority 제한 없음)   → SplashActivity
https://share.coupangeats.com/*  (AutoVerify=true)  → SplashActivity
https://web.coupangeats.com/app/coupang-auth        → 로그인 전용
```

경로 제한이 없으니 **아무 주소나 앱은 열리고, 라우트를 못 알아들으면
조용히 홈으로 떨어진다.** 그래서 위 셋이 전부 "실패인지 성공인지
헷갈리는" 모양이 됐다.

APK의 dex에서 실제 라우트 이름을 꺼냈다(99개). 그중 웹뷰를 여는 것이
`coupangeats://Web`이고, 같이 나온 예시가 인자 형식을 알려줬다.

```
coupangeats://LoyaltyRegistration?url=https%3A%2F%2Floyalty.coupang.com%2F...
```

**동작하는 딥링크:**

```
coupangeats://Web?url=<URL-encoded 프로모션 주소>
```

```
coupangeats://Web?url=https%3A%2F%2Feats-mobile-web.coupang.com%2Fpromotion%2Flanding-page-v5%3Fkey%3DV5_DOMINO_260803
```

force-stop 후 콜드 스타트로 쏴도 도미노피자 프로모션 화면이 바로
떴다(허브 `V5_HUB_0808_AC`도 동일). 다른 라우트도 같은 덤프에 있다 —
`StoreDetail`, `CouponList`, `DealList`, `SearchResult` 등.

### 브랜드 페이지는 텍스트로 읽힌다 — 허브만 안 읽힌다

처음엔 "쿠팡이츠는 접근성 텍스트가 없다"고 적었는데 **허브 페이지만
보고 내린 결론이라 틀렸다.** 허브는 `위클리 슈퍼딜`·`tab-1`·`tab-2`·
`tab-3`뿐이지만, 브랜드 프로모션 페이지는 쿠폰 조건이 텍스트로 나온다.

```
메가MGC커피 프로모션                             ← toolbarTitle, 브랜드명
20,000원 / 수량없음 / 16,000원 이상 주문 시
 6,000원 / 수량없음 / 16,000원 이상 주문 시
 3,000원 / 받기   / 16,000원 이상 주문 시
```

이게 [ADR-014](../decisions/ADR-014-coupangeats-record-guaranteed-floor.md)가
필요로 하던 바로 그 정보다. 헤드라인 `최대 20,000원`은 이미지라 안
읽히는데, **그 20,000원 쿠폰은 `수량없음`이고 지금 실제로 받을 수 있는
건 3,000원이다.** 보장 바닥값을 비전 없이 판정할 수 있다는 뜻이다.

그래서 판독 계획이 갈린다.

| 대상 | 방법 |
|---|---|
| 허브(어떤 브랜드가 있나) | 카드를 눌러 키 수확 — 텍스트 없음 |
| 브랜드 페이지(조건) | 접근성 텍스트 |
| 헤드라인·브랜드 로고 | 여전히 이미지 |

[ADR-013](../decisions/ADR-013-manual-capture-scope-freeze.md)의 "쿠팡이츠는
캡처 이미지를 비전으로 읽는다"는 **부분적으로만** 유효하다 — 목록 단계는
그대로지만 조건 판독은 텍스트로 내려온다.

진입 비용도 사라졌다. 화면을 눌러 들어갈 필요 없이 딥링크로 목표 화면에
바로 떨어뜨릴 수 있다.

구현은 `capture/coupangeats.py`에 있다. 화면 종류를 `kind`로 갈라
`promotion` / `search` / `expired` / `failed`을 구분한다 — 넷이 갈리지
않으면 "데이터가 없는 게 정상인 경우"와 "진입 실패"가 섞인다.

### 실기에서 걸린 것들

- **웹뷰는 스크롤을 한 번 받기 전엔 bounds를 계산하지 않는다.** 메가MGC는
  24초를 기다려도 노드 16개의 y가 세 종류뿐이었는데, 스와이프 한 번 뒤엔
  쿠폰마다 좌표가 갈렸다. "좌표가 앉을 때까지" 기다리면 멀쩡한 페이지가
  영영 "앱에 못 닿았다"가 된다.
- **첫 화면만 읽으면 아래쪽 쿠폰이 조용히 누락된다.**
- **화면 아래 끝에 금액 줄만 걸친 쿠폰을 세면** 최소주문금액을 모르는
  유령 쿠폰이 생긴다(메가MGC 3,000원이 두 장이 됐다).
- **만료 화면은 텍스트가 두 줄뿐이라** 진입 실패로 오인됐다. 앱에는
  정상 도달했고 캠페인이 없을 뿐이다.

## 딸린 발견

딥링크가 앱에 실제로 도달했는지 확인하지 않으면 **브라우저에 머문
화면을 읽고 "쿠폰 없음"으로 기록한다.** 배민 BBQ가 그렇게 빈 결과가
났는데 앱에는 `16,000원 이상 3,000원` 쿠폰이 있었다. `wait_for_package()`로
고쳤다 — 정상 판독 / 쿠폰 없음 / 진입 실패가 이제 구분된다.
