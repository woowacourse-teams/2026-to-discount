# 용어

"카드"가 서로 다른 세 가지를 가리키며 섞여 쓰이고 있었다. 어느 쪽인지
문맥으로 짐작하게 두면 코드 주석과 문서가 조용히 어긋난다.

## 브랜드 할인 카드

**우리 서비스 화면(웹)에 뜨는 카드.** 브랜드 하나에 대해 앱별 할인
금액과 조건을 모아 보여주고, 눌러서 펼치면 상세가 나온다. 웹 구현은
`BrandCard` / `.brand-card`다.

여기에 뜨는 값은 **지금 실제로 받을 수 있는 것만**이다 — 만료된 쿠폰,
금액을 못 읽은 관측, 품절된 액면가는 카드의 대표값이 될 수 없다.
무엇을 내보내고 무엇을 거르는지는 `export_data.py`가 결정한다.

## 앱 브랜드 카드

**배달앱 화면 안의 카드.** 배민 브랜드관, 땡겨요 브랜드쿠폰 탭, 요기요
브랜드 혜택 목록, 쿠팡이츠 위클리 슈퍼딜 허브에 줄지어 있는 것들이다.
`capture/` 아래 코드가 찾아 누르는 대상이며, 판독의 입력이지 출력이
아니다.

같은 목록에 브랜드가 아닌 타일이 섞여 있다 — 쿠팡이츠의
`WOW! 와우 컬렉션`이 그렇다. 카드처럼 생겼다고 브랜드가 아니다.

## 쿠폰 카드

**앱의 브랜드 상세 화면 안에서 쿠폰 한 장을 나타내는 블록.** 금액,
최소주문금액, 수령 가능 여부가 한 덩어리로 붙어 있다. 한 브랜드에
여러 장이 있을 수 있고, 원장에서는 `tiers`가 된다.

2026-08-12 재연결 실험에서 판독 절차의 말들이 즉석 조어로 흩어졌다
("중립 경로", "잠금"). 증거를 다루는 절차는 앞으로도 반복되므로 여기
박는다.

## 증거 화면

**원장 한 행이 주장하는 사실의 근거가 되는 캡처 이미지.** 행의
`screenshot_path`가 가리킨다. 스크린샷 파일 일반이 아니라 "이 행의
근거"라는 관계가 본질이다.

파일이 존재한다고 증거 화면이 되는 게 아니다. 내용이 행의 앱, 브랜드,
금액과 맞아야 한다. 실제로 2026-08-01 땡겨요 상세 캡처 25개가 브랜드만
다른 동일 내용으로 저장된 적이 있다. 이름과 존재가 아니라 내용이 증거를
만든다.

## 블라인드 판독

**판독자가 원장 값을 모른 채 증거 화면의 내용을 기록하는 절차.** 원장
값을 먼저 보면 기대한 대로 읽는 확증 편향이 생기므로 정답지를 가린다.
가리는 대상은 이미지가 아니라 원장이다.

절차의 요소는 셋이다. 부품에 별도 용어를 만들지 않고 문장으로 둔다.

- 판독자는 원장을 포함한 프로젝트 파일 접근이 금지된다.
- 건네는 폴더명은 앱 정체가 드러나지 않게 A, B 같은 무의미한 이름으로
  바꾼다.
- 판독 기록이 전부 제출되어 굳은 뒤에만 원장 값을 공개해 대조한다.
  순서 자체가 장치다: 기록이 정답 열람보다 먼저.

임상시험의 눈가림(blinding)과 같은 원리다. 문헌 표준어는 눈가림이지만
우리 표준어는 블라인드 판독이고, 과거 문서의 "눈가림 판독"은 같은
뜻으로 읽는다.

## 쓸 때

- 우리 화면 얘기면 **브랜드 할인 카드**. 그냥 "카드"라고 쓰지 않는다.
- 앱 화면 얘기면 **앱 브랜드 카드**.
- 앱 상세 안의 쿠폰 한 장이면 **쿠폰 카드**.
- 행의 근거 이미지는 **증거 화면**. 파일 존재와 증거는 다른 말이다.
- 원장을 가리고 읽으면 **블라인드 판독**. "잠금", "중립 경로" 같은
  즉석 조어를 만들지 않는다.
