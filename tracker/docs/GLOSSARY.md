# 용어

"카드"가 서로 다른 세 가지를 가리키며 섞여 쓰이고 있었다. 어느 쪽인지
문맥으로 짐작하게 두면 코드 주석과 문서가 조용히 어긋난다.

## 브랜드 할인 카드

**우리 서비스 화면(웹)에 뜨는 카드.** 브랜드 하나에 대해 앱별 할인
금액과 조건을 모아 보여주고, 눌러서 펼치면 상세가 나온다. 웹 구현은
`BrandCard` / `.brand-card`다.

여기에 뜨는 값은 **지금 실제로 받을 수 있는 것만**이다 — 만료된 쿠폰,
금액을 못 읽은 관측, 품절된 액면가는 카드의 대표값이 될 수 없다.
무엇을 내보내고 무엇을 거르는지는 `export_data.py`가 결정한다.

## 앱 브랜드 카드

**배달앱 화면 안의 카드.** 배민 브랜드관, 땡겨요 브랜드쿠폰 탭, 요기요
브랜드 혜택 목록, 쿠팡이츠 위클리 슈퍼딜 허브에 줄지어 있는 것들이다.
`capture/` 아래 코드가 찾아 누르는 대상이며, 판독의 입력이지 출력이
아니다.

같은 목록에 브랜드가 아닌 타일이 섞여 있다 — 쿠팡이츠의
`WOW! 와우 컬렉션`이 그렇다. 카드처럼 생겼다고 브랜드가 아니다.

## 쿠폰 카드

**앱의 브랜드 상세 화면 안에서 쿠폰 한 장을 나타내는 블록.** 금액,
최소주문금액, 수령 가능 여부가 한 덩어리로 붙어 있다. 한 브랜드에
여러 장이 있을 수 있고, 원장에서는 `tiers`가 된다.

## 쓸 때

- 우리 화면 얘기면 **브랜드 할인 카드**. 그냥 "카드"라고 쓰지 않는다.
- 앱 화면 얘기면 **앱 브랜드 카드**.
- 앱 상세 안의 쿠폰 한 장이면 **쿠폰 카드**.
