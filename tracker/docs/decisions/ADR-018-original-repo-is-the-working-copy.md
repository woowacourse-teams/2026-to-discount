# ADR-018. 개발은 이 저장소에서만 하고, 모노레포에는 정해진 것만 옮긴다

- 날짜: 2026-08-09
- 상태: 확정
- 관련: 모노레포 [ADR-001](https://github.com/woowacourse-teams/2026-to-discount/blob/main/docs/decisions/ADR-001-monorepo-consolidation.md)

## 맥락

모노레포(`woowacourse-teams/2026-to-discount`)에도 `tracker/`가 있다. 다만
ADR-001이 정한 대로 **부분집합**이다 — 판독 자동화(`capture/`), 실행
진입점(`tracker.py`·`dashboard.py`), 캡처 설정(`config/`), 캡처 원본
(`ref/`)이 빠져 있다. 그쪽에서는 수집을 돌릴 수 없다.

그런데 어느 쪽에서 작업할지가 정해져 있지 않아 사고가 났다.

2026-08-09, 낡은 워크트리에서 작업하다 `tiers[].expires_at`를 새로
구현했는데 `main`에 이미 같은 것이 있었다(`5f9fffc`). 워크트리가 16커밋
뒤처져 있었고, 그걸 확인하지 않은 채 "없으니 만들자"로 갔다. 머지할 때
같은 파일 네 곳이 충돌했고, 더 나은 쪽을 고르는 일이 통째로 덤으로
붙었다.

## 판단

**개발은 이 저장소(원본)에서만 한다.** 모노레포 `tracker/`는 읽는 곳이지
고치는 곳이 아니다. 옮기는 범위는 파일 단위로 못 박는다.

| | 파일 |
|---|---|
| **이 저장소 전용** | `capture/`, `tracker.py`, `dashboard.py`, `config/`, `ref/` |
| **양쪽에 반영** | `schema.py`, `store.py`, `export_data.py`, `ingest.py`, `check_deploy.py`, `backfill_export.py`, `tests/`, `docs/`, `data/` |

"양쪽" 파일을 고쳤으면 **같은 작업 안에서** 모노레포에도 옮긴다. 나중에
몰아서 하면 그게 곧 ADR-001이 없애려던 드리프트다.

## 근거

- **실행에 필요한 것이 전부 여기 있다.** 실기 연결, 좌표 상수, 캡처
  원본, 앱별 진입 경로. 모노레포에서는 애초에 돌릴 수 없으니 수집
  작업은 여기서 할 수밖에 없다.
- **소스가 둘이면 중복 구현이 난다.** 위 사고가 그 예다. 어느 쪽이
  최신인지 매번 확인해야 하는 비용이 붙고, 확인을 빠뜨리는 순간
  같은 것을 두 번 만든다.
- **모노레포의 목적은 공개와 열람이지 실행이 아니다**(ADR-001). 그
  목적에는 계약·데이터·문서면 충분하다.

## 대가

- 모노레포가 낡을 수 있다. "같은 작업 안에서 옮긴다"는 규율에 기대는
  구조라, 그 규율이 깨지면 드리프트가 그대로 돌아온다.
- 옮길 때 경로가 다르다(`schema.py` → `tracker/schema.py`). 자동화는
  하지 않았다 — 옮길 일이 잦지 않고, 자동 동기화는 원본 전용 파일이
  섞여 들어갈 위험이 있다.

## 작업 전에 할 것

낡은 채로 시작하는 것이 이 ADR이 막으려는 사고다.

```bash
git fetch origin
git status -sb        # 몇 커밋 뒤처졌는지
git log --oneline HEAD..main
```

워크트리에서 작업한다면 특히 그렇다 — 워크트리는 만든 시점에 멈춰
있고, 본 체크아웃이 앞서가도 알려주지 않는다.
