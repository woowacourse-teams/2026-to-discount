# ADR-011. 화면 진입은 딥링크로, 딥링크가 없으면 수동 캡처

- 날짜: 2026-07-27
- 상태: 확정
- 관련: [ADR-003](ADR-003-vision-over-selectors.md), [ADR-008](ADR-008-manual-fallback-parity.md)

## 맥락

[ADR-003](ADR-003-vision-over-selectors.md)은 판독에 선택자를 쓰지 않기로 하면서, **화면 진입까지의 고정 탭 경로**는 예외로 허용했다. 배민에서 그 탭 경로를 실제로 구현해보니 다음이 드러났다.

- 앱을 콜드 스타트하면 그날의 프로모션·타임세일 모달이 뜬다. 무엇이 언제 뜰지 알 수 없다.
- 모달이 뜬 상태에서 고정 좌표를 누르면 엉뚱한 곳이 눌린다. 실제로 `monkey` 실행이 조용히 실패해 런처 화면에 탭이 들어간 적이 있다.
- 모달 종류를 하나씩 식별해 닫는 방식은 끝이 없다. 새 이벤트가 생길 때마다 깨진다.

반면 배민 APK에서 딥링크 라우터를 찾았고, 임의의 웹 URL을 앱 웹뷰로 여는 형식이 확인되었다.

```
baemin://./webview?webview_url=<URL 인코딩된 https 주소>
```

이 방식은 **현재 화면이 무엇이든** 목표 화면으로 간다. 모달이 떠 있어도 무관하다.

## 판단

1. 앱 화면 진입은 **딥링크를 우선**한다. 고정 탭 경로는 딥링크가 없을 때만 쓴다.
2. 딥링크가 없고 탭 경로가 모달에 취약하면, 그 화면은 자동화하지 않고 [ADR-008](ADR-008-manual-fallback-parity.md)의 수동 캡처로 내린다.

## 근거

- 딥링크는 화면 상태에 의존하지 않으므로, 실패 시 **무엇이 화면을 가렸는지 알 필요 없이 그냥 다시 쏘면 된다**. 복구가 재시도 한 줄로 끝난다.
- 좌표는 해상도·앱 레이아웃 변경에 깨지지만 딥링크는 URL이 유지되는 한 안정적이다.
- 모달을 패턴화하려는 시도는 유지보수가 무한히 늘어나는 방향이다. 이길 수 없는 싸움을 시작하지 않는다.

## 적용 결과 (2026-07-27 기준)

| 앱 / 화면 | 진입 방법 | 상태 |
|---|---|---|
| 배민 `브랜드관 > 오늘의 할인` | 딥링크 `https://inapp-webview.baemin.com/brand-lounge` | 자동 |
| 배민 `배짱할인` | **없음** | 수동 ([ADR-008](ADR-008-manual-fallback-parity.md)) |
| 쿠팡이츠 `와우컬렉션` | 미조사 | — |
| 땡겨요 `오늘 땡길만한 브랜드` | 미조사 | — |

배짱할인을 수동으로 내린 근거: APK에 담긴 페이지 URL 182개를 전수 확인했으나 배짱할인에 해당하는 고정 주소가 없다. 화면에 `7월 5주차`로 표기되는 데서 보듯 주차별로 서버가 주소를 내려주므로 딥링크가 성립하지 않는다.

## 남는 한계

딥링크로 열어도 액티비티 이름은 배민의 모든 웹뷰가 공유한다(`WebViewActivity`). 따라서 `current_activity()` 헬스체크는 "홈이 아닌 웹뷰에 도달했다"까지만 확인하며, **엉뚱한 웹뷰에서 캡처하는 것은 막지 못한다.** 이 검증은 판독 단계가 사람/비전으로 수행하는 것에 맡긴다.

## 뒤집을 조건

딥링크 라우터가 막히거나(앱이 외부 URL 주입을 차단), 탭 경로를 안정화할 다른 수단이 생길 때.
