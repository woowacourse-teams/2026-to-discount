# ADR-005. 1차 범위는 메인 할인 페이지까지

- 날짜: 2026-07-26
- 상태: 확정

## 맥락

쿠팡이츠 `와우컬렉션` 하단에는 이미지 배너와 `보러 가기` 버튼이 있고, 이를 누르면 `이츠셰프컬렉션`·`장보기 쿠폰북` 같은 **하위 프로모션 페이지**로 이어진다. 여기에도 할인 정보가 있다. 즉 할인 데이터는 한 페이지가 아니라 페이지 트리에 흩어져 있다.

## 판단

1차 범위는 각 앱의 **메인 할인 페이지 1개**로 한정한다. 하위 프로모션 페이지는 수집하지 않는다.

## 근거

- 핵심 가치는 브랜드별 할인금액 비교이고, 그 대부분이 메인 페이지에 모여 있다.
- 하위 페이지는 개수·구성·존재 여부가 마케팅 일정에 따라 계속 변한다. 트리 탐색을 1차부터 넣으면 가장 불안정한 부분이 파이프라인 검증과 뒤엉킨다.
- 페이지 트리 탐색은 캡처 계층만의 확장이다. 표준 레코드에 `page` 필드가 이미 있으므로, 나중에 추가해도 저장·대시보드 계층은 변경되지 않는다.

## 대가

수집 결과가 해당 앱의 전체 할인을 대표하지 않는다. **대시보드에 "어느 페이지까지 수집했는지"를 명시**하여 완전성을 오인하지 않게 한다.

## 뒤집을 조건

메인 페이지 수집이 안정화된 뒤, 하위 페이지에만 있는 할인이 실제로 의사결정에 필요하다고 판단될 때 확장한다.

## 갱신 (2026-08-09): 앱마다 메인이 둘이다

"메인 할인 페이지 1개"라고 적었는데, 세어 보니 앱이 **범용 할인**과
**멤버십 할인**을 각각 다른 화면에 두고 있었다. 둘 다 메인이다 — 어느
한쪽이 다른 쪽의 하위 페이지가 아니다.

| 앱 | 범용 할인 | 멤버십 할인 |
|---|---|---|
| 쿠팡이츠 | 슈퍼딜(위클리 슈퍼딜) | 최대 할인(와우 라운지) |
| 배민 | 브랜드관 | 배짱할인(단독할인 = 배민클럽) |
| 땡겨요 | 혜택 > 브랜드쿠폰 | — |
| 요기요 | 할인/혜택 > 브랜드 혜택 | — |

멤버십 할인을 빼면 비교표가 한쪽으로 기운다 — 같은 브랜드가 한 앱에서는
멤버십가로, 다른 앱에서는 일반가로 잡혀 "어디가 싼가"가 뒤집힌다.

이 ADR이 막으려던 것은 여전히 유효하다. `보러 가기`로 이어지는 하위
프로모션 페이지(이츠셰프컬렉션·장보기 쿠폰북 등)는 수집하지 않는다.

### 아직 안 잡는 것

- 배민 배짱할인의 **브랜드 특가 버튼** — 누르면 그 브랜드의 매장 목록이
  나온다. 브랜드가 아니라 매장 층위(`scope: store`)라 브랜드 할인 카드에
  그대로 못 올린다.
- 쿠팡이츠 허브의 **검색형 카드** — 프로모션 페이지가 아니라 브랜드
  검색 결과로 떨어진다. 카드에 적힌 헤드라인 금액만 있고 조건이 없다.

대시보드가 어디까지 수집했는지 함께 적는다.
