# ADR-004. 금액 수식어를 분리 보존, 단일 숫자 정규화 금지

- 날짜: 2026-07-26
- 상태: 확정

## 맥락

할인금액을 비교 가능한 하나의 숫자로 정규화하는 것이 자연스러워 보인다. 그러나 실물 표기를 확인한 결과 수식어가 의미를 결정한다.

관찰된 표기:

```
배민   "10,000원 브랜드 할인"        수식어 없음(정액)
쿠팡   "최대 6,000원"                상한
쿠팡   "최소 4,000원"  (반올림피자)   하한 ← 상한과 정반대
쿠팡   "최대 7천원"    (노랑통닭)     한글 수사 표기
땡겨요 "최대 9,000원 할인"            상한
```

`최대`와 `최소`는 큰 숫자 옆에 아주 작은 2줄 글자로 렌더링되어 시각적으로 오독하기 쉬운 반면, 의미는 정반대다.

## 판단

- `qualifier`(`최대`/`최소`/`null`)를 `amount`와 별도 필드로 보존한다.
- `raw_text`에 화면 원문을 항상 그대로 남긴다.
- 할인이 아닌 형태(사은품 등)는 `offer_type`으로 구분하고, 판단이 안 서는 항목은 `needs_review: true`로 표시한다.

## 근거

- `최소 4,000원`을 `4000`으로만 저장하면 `최대 4,000원`과 구별이 사라진다. 두 브랜드를 나란히 비교하는 것이 이 서비스의 목적이므로, 이 손실은 결과를 직접 왜곡한다.
- 비전 판독은 작은 글자에서 오류 가능성이 있다. `raw_text` 원문이 남아 있어야 사후 검증이 가능하다.
- 실제로 `BBQ 필릭스 PICK 주문 시 한정판 굿즈 증정 + 4천원 쿠폰까지` 같은 사례가 존재한다. 이를 억지로 금액 필드에 끼워 넣으면 데이터가 조용히 오염된다.

## 뒤집을 조건

없음. 이 결정은 데이터 손실을 막는 성격이므로 되돌릴 이유가 생기기 어렵다. 다만 수식어 종류가 늘어나면(`최대`/`최소` 외) `qualifier` 허용값을 확장한다.
