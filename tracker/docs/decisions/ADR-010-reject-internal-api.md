# ADR-010. 앱 내부 API를 쓰지 않고 화면 캡처를 유지한다

- 날짜: 2026-07-27
- 상태: 확정
- 관련: [ADR-003](ADR-003-vision-over-selectors.md)

> **2026-07-27 추가 조사:** 배민 하나가 아니라 1차 대상 앱 전체에 대해 API
> 가능성을 정적 분석으로 확인했다. 결론은 동일 — **네 앱 모두 정적 분석만으로는
> API를 쓸 수 없다.** 아래 §전체 앱 조사 결과 참고. 캡처+판독 유지 결정이
> 배민만의 사정이 아니라 대상 전체에 걸친 사실로 뒷받침된다.

## 맥락

배민 딥링크를 찾으려고 APK 문자열을 뒤지다가, 브랜드관 `오늘의 할인`의 데이터 소스로 보이는 엔드포인트를 발견했다.

```
https://baemin-brand-external-api.baemin.com/v2/brands/today-benefits
```

이것이 동작한다면 캡처와 비전 판독 전체가 불필요해진다. 명세 §6이 "판독이 유일한 실질 비용"이라 한 그 비용이 0이 되고, 최대/최소 오독 위험([ADR-004](ADR-004-preserve-qualifier.md))도 사라진다. 그냥 넘기기엔 큰 차이라 실제로 호출해 확인했다.

## 확인한 것

파라미터를 하나씩 채워가며 호출한 결과, 서버가 요구한 순서는 다음과 같았다.

| 호출 | 응답 |
|---|---|
| 파라미터 없음 | 400 — `latitude` 없음 |
| + latitude, longitude | 400 — `dvcid` 없음 |
| + dvcid | 400 — `dongCode` 없음 |
| + dongCode | 400 — **`Authorization` 헤더 없음** |

즉 인증 없이는 접근할 수 없다.

## 판단

내부 API를 쓰지 않는다. 캡처 + 비전 판독([ADR-003](ADR-003-vision-over-selectors.md))을 유지한다.

## 근거

- **토큰을 앱에서 꺼내야 한다.** 세션 토큰 추출·보관·만료 갱신이 전부 새 문제로 붙는다. 판독 비용을 없애는 대신 인증 유지 비용을 떠안는 교환이다.
- 문서화되지 않은 비공개 API라 스펙이 예고 없이 바뀌고, 약관 위반 소지와 차단 위험이 있다. 화면 캡처는 사람이 앱을 쓰는 것과 같은 경로다.
- 나머지 앱에도 같은 API가 있다는 보장이 없다. 배민만 API, 나머지는 캡처가 되면 계층 계약이 둘로 갈라진다([ADR-007](ADR-007-unified-app-pipeline.md)이 피하려던 상황).
- 캡처 파이프라인은 이미 동작한다. 지금 바꾸면 만든 것을 버린다.

## 전체 앱 조사 결과 (2026-07-27)

태블릿에 깔린 앱 4개의 APK(base.apk)를 받아 평문 문자열을 훑었다. 대상은 배민 외에 요기요·쿠팡이츠·땡겨요, 참고로 먹깨비까지.

| 앱 | API 호스트 | 콘텐츠 경로 노출 | 인증 없이 접근 | 결론 |
|---|---|---|---|---|
| 쿠팡이츠 | `api.coupangeats.com` | ❌ 평문에 없음(런타임 조립) | — | 정적 분석 불가 |
| 요기요 | `api.yogiyo.co.kr` + 쿠폰 경로 다수 | ✅ `api/v1/couponbox/`, `api/v2/shop-coupons/shops/{id}/`, `v1/aggregation/download-shop-coupon` 등 | ❌ **403 Forbidden** | 게이트웨이/WAF 차단 |
| 땡겨요 | `*.ddangyo.com`(dev 호스트만 평문) | ❌ 콘텐츠 경로 없음 | — | 정적 분석 불가 |
| 배민 | `baemin-brand-external-api.baemin.com` | ✅ `v2/brands/today-benefits` | ❌ `Authorization` 필요 | 위 §확인한 것 |
| (참고) 먹깨비 | `mukkebi.com/app/*.php` | ✅ 전부 평문 | ✅ 일부 200 | 1차 범위 밖 |

- **요기요**: `X-ApiKey`/`X-ApiSecret` 헤더를 쓰고 앱에 키 값(`OAYA…`)까지 박혀 있으나, 그 키를 넣어도 403이 그대로다. 403은 API 키 문제가 아니라 서버 밖 요청을 게이트웨이 단에서 막는 것으로 보인다(`{"message":"Forbidden"}`).
- **쿠팡이츠·땡겨요**: 평문에 인증·광고·분석 SDK 엔드포인트만 있고 콘텐츠 경로가 없다. 호스트는 있으나 경로를 런타임에 조립한다.

**정적 분석만으로는 1차 대상 3개 앱 모두 API를 쓸 수 없다.** 넘으려면 런타임 트래픽 가로채기(mitmproxy로 실제 앱 요청의 헤더·토큰·서명 복제)가 필요하고, 요기요·쿠팡이츠는 인증서 피닝 가능성이 높다. 정적 분석과는 난이도가 다른 작업이라 1차에서는 하지 않는다.

## 뒤집을 조건

비전 판독의 정확도나 비용이 실측으로 감당 못 할 수준임이 드러나고, 동시에 토큰을 안정적으로 얻는 합법적 경로(공식 API 제공, 또는 런타임 트래픽 가로채기가 비용을 감당할 만하다고 판명)가 생길 때.

## 남기는 이유

이 문서의 목적은 **같은 길을 다시 파지 않게 하는 것**이다. 엔드포인트가 존재한다는 사실은 다음에 APK를 열어보는 사람에게 또 매력적으로 보일 것이고, 그때 여기서 이미 인증 벽을 확인했음을 알아야 한다.
