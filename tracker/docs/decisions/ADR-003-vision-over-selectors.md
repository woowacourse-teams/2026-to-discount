# ADR-003. 판독은 비전, 선택자 기반 레시피 폐기

- 날짜: 2026-07-26
- 상태: 확정

## 맥락

유지보수성을 위해, 화면 요소를 좌표가 아니라 구조(resource-id·텍스트)로 찾고 그 절차를 선언적 YAML 레시피로 관리하는 안을 검토했다. 앱 화면이 바뀌어도 레시피만 고치면 되도록 하려는 의도였다.

실물 화면을 확인한 결과 이 안의 전제가 성립하지 않는 것으로 판명되었다.

## 판단

선택자 기반 레시피를 채택하지 않는다. 매 실행마다 캡처된 화면을 비전으로 판독한다. 어떤 선택자도 사전에 저장하지 않는다.

## 근거

실물 캡처(`ref/delivery/`)에서 확인된 사실:

- **땡겨요 `오늘 땡길만한 브랜드`는 모든 카드가 통째로 이미지 배너다.** 브랜드명·금액·`할인` 문구가 전부 이미지에 구워져 있어 `uiautomator dump`로 추출할 텍스트가 존재하지 않는다. 선택자로 찾을 대상 자체가 없다.
- **쿠팡이츠 `와우컬렉션`은 WebView 프로모션 페이지다.** 페이지 타이틀이 `와우컬렉션_COPIED`로 내부 CMS 복제 흔적이 그대로 노출되어 있고, 섹션 구성(`위클리 슈퍼딜`/`인기 브랜드 할인`/`치킨·버거`/`피자`/`기타 인기`)이 주 단위로 교체될 성격이다. 안정적인 선택자가 존재한다고 가정할 수 없다.
- 배민만 네이티브 텍스트라 선택자가 성립하지만, 앱 3개 중 1개만 되는 방식을 공통 구조로 삼을 수 없다.

비전 판독은 사람이 눈으로 보고 판단하는 것과 같은 원리이므로 이미지든 네이티브든 WebView든 구애받지 않는다. 레이아웃이 바뀌어도 "이번 화면에서 다시 읽으면" 되는 문제라 사전 정의가 깨질 여지가 없다.

## 대가

- 매 실행 판독 비용이 발생한다. 하루 2회 × 앱 3개 규모에서는 수용 가능하다고 판단했다.
- 판독 정확도를 코드로 보장할 수 없다. 이에 대응해 `raw_text` 원문 보존(`ADR-004`), 실물 캡처 기반 판독 회귀 검증(명세 §11), 반자동 전환 경로(`ADR-008`)를 함께 둔다.

## 뒤집을 조건

대상 앱들이 모두 네이티브 텍스트 UI로 전환되어 `uiautomator dump`만으로 안정적으로 데이터를 얻을 수 있게 될 때. 부분적으로는 배민에 한해 저비용 교차검증 수단으로 `uiautomator dump`를 **보조 활용**하는 것은 이 결정과 충돌하지 않는다.
