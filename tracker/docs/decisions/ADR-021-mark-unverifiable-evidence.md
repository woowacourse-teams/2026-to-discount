# ADR-021. 검증 불가 증거는 원장 행에 `evidence_status`로 표시한다

- 날짜: 2026-08-13 (번호 재배정 2026-08-16)
- 상태: 확정
- 관련: [ADR-004](ADR-004-preserve-qualifier.md),
  실험 [원장-스크린샷-재연결](../experiments/2026-08-12_원장-스크린샷-재연결.md),
  실험 [보존군-내용-일치](../experiments/2026-08-12_보존군-내용-일치.md)

## 맥락

2026-08-12의 실험 사슬로 원장 363행의 증거 상태가 처음으로 전수 확정됐다.
경로가 실존하는 291행은 표본 검증(이동군 30/30, 보존군 29/30)을 통과했고,
나머지는 영구 검증 불가다.

- **디스크 없음 62행**: 같은 이름의 파일이 프로젝트 어디에도 없다. 과거
  화면은 재수집이 불가능하므로 영구적이다.
- **경로 null 10행**: `screenshot_path`가 비어 있다. 무엇을 가리켰는지
  자체가 없다.
- **커버리지 결손 4행** (145, 154, 217, 220): 파일은 실존하고 열리지만,
  캡처의 스크롤 범위에 그 행의 브랜드가 없다. 땡겨요 혜택탭 캡처 한 장이
  6행의 증거인데 화면에는 쿠폰 카드 4장뿐이었다.

문제는 이 세 유형의 가시성이 다르다는 것이다. 없음과 null은 경로만 봐도
알 수 있지만, 결손은 파일을 열어 사람이 대조해야만 보인다. 실험이 끝난
지금 이 지식은 실험 문서에만 있고 원장에는 없다. 다음 분석자가 같은
비용을 다시 내지 않으려면 지식이 데이터에 붙어 있어야 한다.

선례가 있다. `capture_mode: backfill`은 "출처 신뢰도가 다른 행을 필드로
구분해 남긴다"는 같은 문제의 같은 해법이다(schema.py 주석).

## 판단

**원장 행에 선택 필드 `evidence_status`를 둔다.** 값은 셋.

- `missing_file`: 파일이 디스크에 없다 (62행)
- `no_path`: 경로가 기록되지 않았다 (10행)
- `not_in_capture`: 파일은 있으나 화면에 이 행의 브랜드가 없다 (4행)

필드 부재가 기본값이며 "경로 실존, 표본 수준 검증 통과 군"을 뜻한다.
`schema.py`에 열거값 검증을 추가하고, export 필드 매핑에는 넣지 않는다
(웹, api 모두 증거 상태를 소비하지 않는다). 적재는 일회 스크립트로 하고
수집 파이프라인은 건드리지 않는다. 새 수집은 캡처와 동시에 기록되므로
이 필드의 대상이 아니다.

## 기각한 대안

- **사이드카 파일**: 행에 안정된 ID가 없어 행 번호 참조는 원장 append에
  취약하다. 지식이 데이터와 떨어져 있으면 결국 잊힌다.
- **`needs_review` 재사용**: review는 "다시 보면 고칠 수 있다"는 함의다.
  영구 검증 불가는 조치 불가능이므로 의미가 오염된다.
- **행 삭제**: 관측 자체는 참일 수 있다(결손 4행의 수치는 당시 화면을 본
  사람이 적은 값이다). 증거 연결이 끊겼다는 사실과 관측이 틀렸다는 판단은
  다르다. 원문 보존 원칙(ADR-004)과 같은 이유로 데이터는 남긴다.

## 결과

- 원장 기반 분석은 `evidence_status` 유무로 신뢰 등급을 가른다.
- 검증 불가 76행의 내역이 데이터 안에서 자기 서술된다.
- 이후 커버리지 결손이 또 발견되면 같은 필드에 같은 값으로 적는다.
