# ADR-026. 화면 판독은 모양의 합집합으로 읽고, 모양마다 회귀 사례를 남긴다

- 날짜: 2026-09-07
- 상태: 확정
- 관련: [ADR-003](ADR-003-vision-over-selectors.md),
  [ADR-011](ADR-011-deeplink-entry-over-tap-path.md),
  `capture/brand_links.py`, `tests/capture/test_baemin_coupon_shapes.py`,
  커밋 f7b7d99

## 맥락

배민은 **같은 쿠폰을 화면마다 다른 모양으로 준다.** 2026-09-07 하루에
실기에서 확인한 것만 넷이다.

| 모양 | 실측 | 어떻게 오나 |
| --- | --- | --- |
| 이어붙임 | 피자헛 | 한 노드에 넉 장이 이어붙는다 |
| 쪼갬 | 치킨마루 | `"3,000원 할인 쿠폰"` / `"17,000원 이상 주문 시 사용 가능"` 두 노드 |
| content-desc | bhc | `text`가 아니라 `content-desc`에 실려 온다 |
| 구 분리형 | 2026-08-17 | `"4,000"` / `"원"` / `" 할인"` / 조건 |

이날 두 번 연달아 틀렸다.

**1차.** 시트 정규식이 XML 원문에만 걸려 있었다. 쪼갬형은 두 값 사이에
XML 속성이 끼어 영영 안 맞는다. 치킨마루가 화면에 3,000원 쿠폰을 띄운 채
`tiers 0`으로 적혔다.

**2차.** 그것을 고치려고 `text` 노드만 이어붙인 문자열로 **바꿨다.** 그러자
bhc가 `tiers 1` → `0`으로 되레 줄었다. 앞 모양을 고치면서 뒤 모양을 깼다.

2차는 순전히 운으로 잡혔다. 1차 순회 로그에 `3/110 bhc: tiers 1`이 남아
있었고, 2차 순회에서 같은 자리가 0인 것을 눈으로 비교했다. 로그가 없었으면
110곳을 다 돌고 "성공 110 / 실패 0"을 본 뒤 그대로 원장에 넣었을 것이다.

## 판단

**하나. 새 모양을 만나면 기존 판독을 바꾸지 말고 합집합에 더한다.**

```python
pairs  = list(RE.findall(xml))            # 원문
pairs += RE.findall(_node_strings(xml))   # 노드를 이어붙인 문자열
# 겹침만 제거한다
```

어느 모양이 올지 화면을 열기 전에는 알 수 없다. 한쪽을 고르는 것은 그
자체가 추측이고, 추측이 틀리면 **값이 틀리는 게 아니라 사라진다.**

**둘. 모양마다 회귀 사례를 남긴다.** `tests/capture/test_baemin_coupon_shapes.py`에
넷을 한 파일에 묶었다. 하나를 고치다 다른 하나를 깨면 여기서 걸린다.
새 모양을 만나면 실기 문자열을 그대로 넣어 사례를 하나 더 붙인다.

**셋. 못 읽은 것은 지어내지 않는다.** 금액을 못 찾은 조건 문구는
`exceptions`에 원문 그대로 남긴다(ADR-003과 같은 태도). 그 규칙도
테스트로 박아 뒀다.

## 왜 "모양을 통일해 달라"고 못 하나

우리 화면이 아니다. 앱은 예고 없이 바뀌고, 실제로 8월에 한 번, 9월에 또
한 번 바뀌었다. 통일을 전제로 짠 판독은 다음 개편에서 또 통째로 0이 된다.

## 이 실패를 빨리 알아채는 법

`tiers 0`은 **정상일 수도 있다**(쿠폰이 없는 브랜드가 실제로 26곳이었다).
그래서 0 자체로는 경보가 안 된다. 대신 이렇게 본다.

1. **순회 로그를 남기고 직전 회차와 비교한다.** 어제 1이던 곳이 오늘 0이면
   화면이 바뀐 것이거나 판독이 깨진 것이다. 이번 회귀가 그렇게 잡혔다.
2. **`exceptions`가 있는데 `tiers`가 빈 곳을 먼저 본다.** 시트는 읽혔는데
   금액만 못 뽑은 상태다. 치킨마루가 정확히 그 모양이었다.
3. **연속으로 비면 멈춘다.** `BARREN_LIMIT`(기본 20)이 그 역할을 한다.
4. **의심되면 스크린샷을 연다.** 브랜드마다 한 장 찍어 두는 이유다.
   기영이숯불두마리치킨은 페이지에 쿠폰 영역 자체가 없어 0이 옳았다.
