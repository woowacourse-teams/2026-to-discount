# ADR-008. 수동 캡처를 자동과 동일 산출물로 정의

- 날짜: 2026-07-26
- 상태: 확정

## 맥락

판독 정확도가 보장되지 않으므로, 언제든 반자동(사람이 판독)으로 전환할 수 있어야 한다는 것이 요구사항이다. 통상 이런 대비책은 "수동 모드"를 별도로 구현하는 방식이 되고, 쓰이지 않는 동안 방치되어 정작 필요할 때 동작하지 않는다.

## 판단

수동 경로를 별도 모드로 만들지 않는다. **자동 캡처의 산출물과 수동 캡처의 산출물을 동일한 것으로 정의한다** — 대상 페이지의 롱스크롤 이미지 1장.

- 자동: `adb screencap` + `swipe` 반복 + 이어붙이기
- 수동: 폰의 스크롤 캡처 기능으로 촬영

## 근거

- 본 설계의 근거가 된 실물 자료(`ref/delivery/baemin.jpg`, `coupangeats.jpg`, `ddangeyo.jpg`)가 이미 수동 스크롤 캡처다. 즉 수동 산출물이 자동 산출물과 같은 형태라는 것이 가정이 아니라 **확인된 사실**이다.
- 산출물이 같으면 반자동 전환은 구현이 아니라 "캡처 단계를 사람이 수행"으로 끝난다. 판독·저장·대시보드 계층은 코드 변경 없이 그대로 동작한다.
- 전환 단위가 앱별로 독립적이다. 한 앱만 수동으로 내리고 나머지는 자동 유지할 수 있다.

## 전환 절차

1. `config/target.json`에서 해당 플랫폼의 `capture_mode`를 `manual`로 변경
2. 대상 페이지를 스크롤 캡처하여 `captures/<platform>/<timestamp>/full.png`에 저장
3. 이후 파이프라인은 자동과 동일하게 동작

## 전환 트리거

아래 중 하나면 반자동 전환을 검토한다.

- 판독 오류가 1주 내 2회 이상 발생
- 앱 UI 변경으로 페이지 진입이 2회 연속 실패
- 에뮬레이터 탐지로 앱 실행 자체가 차단

땡겨요는 화면이 100% 이미지라 저비용 교차검증 경로가 없으므로(명세 §6.2), 정확도 문제 발생 시 1순위 전환 후보다.

## 뒤집을 조건

없음. 이 결정은 대비책을 구현이 아니라 정의로 확보하는 성격이다.
