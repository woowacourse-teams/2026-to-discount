# ADR-001. 구현 언어는 Python, ADB는 CLI 호출

- 날짜: 2026-07-26
- 상태: 확정

## 맥락

ADB로 안드로이드를 제어하는 구조라면 Kotlin/Java가 더 적합하지 않냐는 검토가 있었다.

## 판단

Python으로 구현하고, ADB는 `adb` CLI를 서브프로세스로 호출한다.

## 근거

- ADB 연동 방식은 두 갈래다. (a) `adb` CLI 호출, (b) ddmlib 등으로 ADB 프로토콜에 직접 접속. 본 프로젝트가 필요한 것은 "명령 몇 개 실행하고 결과 받기" 수준이므로 (a)로 충분하다. (a)는 어떤 언어에서 호출하든 동일한 바이너리를 실행하는 것이라 언어가 결과를 바꾸지 않는다.
- Kotlin/Java가 실질적으로 유리해지는 지점은 **on-device 계측(UiAutomator/Espresso)** 으로, 요소를 resource-id로 찾을 수 있게 된다. 그러나 별도 테스트 APK 빌드·설치 파이프라인이 필요하고, 무엇보다 `ADR-003`에 따라 선택자 기반 접근 자체를 채택하지 않으므로 그 이점이 발생하지 않는다.
- 실행 환경이 Windows PC와 리눅스 서버 양쪽이어야 하는데(명세 §8), Python 스크립트는 JVM·빌드툴 없이 양쪽에서 그대로 실행된다.

## 뒤집을 조건

on-device 계측이 필요해지는 경우 — 즉 `ADR-003`이 먼저 뒤집혀 선택자 기반 접근으로 회귀할 때. 그 경우 캡처 계층만 Kotlin + UiAutomator로 교체하고, 산출물 계약(롱스크롤 이미지)이 같으므로 나머지 계층은 유지한다.
