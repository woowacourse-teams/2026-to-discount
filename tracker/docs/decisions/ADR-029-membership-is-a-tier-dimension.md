# ADR-029. 멤버십은 레코드의 값이 아니라 구간(tier)의 차원이다

- 날짜: 2026-09-14
- 상태: 확정
- 관련: [ADR-016](ADR-016-confirmed-beats-recency-on-dedup.md),
  [ADR-019](ADR-019-cumulative-tiers-and-domain-judged-amount.md),
  [ADR-028](ADR-028-today-expiry-is-not-an-observed-end-date.md)

## 맥락

한 브랜드에 쿠폰이 여러 장 걸린다. 배민 쿠폰함에는 "3,000원 누구나"와
"8,000원 배민클럽"이 나란히 있고, 쿠팡이츠 쿠폰함에는 `[와우회원전용]`
대괄호가 붙은 것과 안 붙은 것이 섞여 있다. 채널(배달/포장)이 다른
쿠폰이 같은 브랜드에 걸리는 것과 같은 모양이다.

채널은 이미 구간의 차원으로 풀어 뒀다 — `tier.channel`(2026-08-01,
땡겨요 바른치킨). 그런데 멤버십은 **레코드 하나에 값 하나**(`membership`)
였다. 그 결과 두 가지가 틀렸다.

1. **쿠폰함 빌더가 한 장만 남기고 나머지를 지운다.** 순위(비회원 우선,
   그다음 금액 큼)로 대표를 고르고 클럽 쿠폰은 레코드에서 사라진다.
   "클럽이면 8,000원"이라는 사실이 상세에도 안 남는다.
2. **화면에 따라 이 값을 볼 수 있는 곳과 없는 곳이 갈리는데, 기본값이
   "없음"이었다.** 쿠폰함엔 표시가 있고 위클리 슈퍼딜 허브 카드·브랜드관
   목록엔 없다. 표시 없는 화면의 빌더가 기본값 `"none"`을 찍으면, 그
   레코드가 최신이 되는 날 쿠폰함 관측을 덮는다. 2026-09-14 확인:
   허브와 쿠폰함이 겹치는 12곳이 다음 허브 갱신 때 그렇게 될 판이었다.
   만료일이 같은 경로로 덮이던 09-04 사고와 정확히 같은 모양이다.

## 판단

**멤버십을 구간의 차원으로 옮긴다. 레코드의 `membership`은 구간에서
유도한다.**

- `tier.membership` — `"none"` / `"baeminClub"` / `"coupangEats"` /
  `"yogiPass"`. 채널·조건(`note`)·만료일과 같은 자리다. 한 브랜드의 쿠폰
  전부가 각자 한 구간으로 산다 — 지우는 것이 없다.
- 레코드 `membership` — 구간이 있으면 **가장 덜 제한적인 구간의 값**
  (하나라도 `"none"`이면 `"none"`). 구간이 없으면 빌더가 적은 값 그대로.
  둘 다 없으면 `None` = **모름**.
- 레코드 `amount`(카드 대표값)는 지금 순위 그대로 — **누구나 받는 쿠폰이
  먼저**, 그다음 금액. 카드는 "누구나 얼마"를 말하고, 상세를 열면 "클럽이면
  얼마"가 한 줄 더 있다.
- `"none"`과 `None`을 가른다. `"none"`은 "봤는데 제한이 없더라"는 관측이고
  `None`은 "그 화면에선 안 보였다"다. 표시가 없는 화면(허브 카드·브랜드관
  목록)의 빌더는 이 값을 **안 적는다**.
- 병합(`store.MERGEABLE_DETAIL`, API `Offer.withDetailFrom`)이 `None`일 때만
  진 레코드에서 채운다. **같은 쿠폰(`_same_coupon`, 금액 동일)일 때만**
  돈다 — 다른 쿠폰의 멤버십을 가져오지 않는다. `"none"`은 관측이라 안
  덮인다. 구간은 원래 병합 대상이라 쿠폰함 구간이 허브 승자에게 따라온다.

### 왜 순위를 "비회원 우선"으로 두나

카드 대표값은 정렬과 "최고 할인"에 쓰인다. 클럽 8,000이 대표가 되면
클럽 없는 사람 절반이 카드와 다른 앱을 만난다 — 타겟딜을 "최대"로 가른
것과 같은 이유다(2026-09-12). 클럽 값은 상세 구간에 배지와 같이 있으면
된다.

### 화면

상세 구간 줄의 채널 옆에 멤버십 배지. 카드 하단에 이미 쓰는
`offer__status-badge--membership`(플랫폼 색)을 그대로 쓴다 — 새 표식을
만들지 않는다. 카드 하단 배지는 레코드 값(= 가장 덜 제한적인 값)을 따르니
구간 하나라도 누구나 받으면 안 뜬다.

## 용어

| 말 | 뜻 |
|---|---|
| 쿠폰함 | 앱에서 **받은** 쿠폰이 모이는 화면. 여기서만 멤버십 표시가 보인다 |
| 허브 카드 | 쿠팡이츠 위클리 슈퍼딜 목록의 브랜드별 카드. 금액은 있고 멤버십 표시는 없다 |
| 허브 빌더 | 허브 카드를 원장 레코드로 만드는 `scripts/coupangeats_weekly.py`. 쿠폰함 빌더(`build_ce_couponbox_records.py`·`build_couponbox_records.py`)와 갈라 부른다 |
| 브랜드관 | 배민 브랜드 목록 화면. 클럽 단독할인이 **별도 탭**으로 갈려 보이므로 거기서 나온 `"none"`은 관측이다 |

"지갑"이라는 말은 쓰지 않는다 — 쿠폰함이다.

## 검증에서 반드시 볼 것

**멤버십 표시가 명시적이지 않을 수 있다.** 쿠팡이츠 대괄호·배민클럽
배지는 지금까지의 실측이지, 앱이 늘 그렇게 보여 준다는 보장이 없다.
멤버십 계정으로만 수집하면 "표시가 없다"와 "제한이 없다"를 못 가른다.

- **두 계정으로 대조한다.** 멤버십 있는 계정과 없는 계정으로 같은 날
  쿠폰함·허브를 각각 수집해, 한쪽에만 보이는 쿠폰이 곧 전용 쿠폰이다.
  이 대조가 표시 판독보다 강한 근거다. 요기요(요기패스)는 표시 판독이
  아예 없어 이 방법이 유일하다.
- **배너에서 온 값도 같은 구분이 필요하다.** `BrandComparisonService.
  bannerRecords()`는 배너를 오퍼로 접을 때 멤버십을 `null`(UNKNOWN)로
  둔다 — 배너 문구엔 표시가 없기 때문이다. 배너가 멤버십 전용 행사를
  실을 때(배민클럽 데이 등) 사람이 `banners.yml`에 적어야 하고, 그 값이
  구간까지 내려가는지 검증에서 본다.
- **수집 뒤 확인 순서.** ① 한 브랜드에 구간이 `none`과 `baeminClub`/
  `coupangEats`로 갈린 것이 export에 있는가 ② 그 브랜드 카드 대표값이
  누구나 받는 쪽인가 ③ 상세 구간 줄에 배지가 그 구간에만 붙는가
  ④ 허브 재캡처 뒤에도 ①이 유지되는가(병합 검증).

## 안 하는 것

- **필터 UI.** `membership_toggle`은 준비중 스텁이고 누른 사람 1.3%다.
  데이터가 구간으로 자리 잡은 뒤 다시 본다.
- **요기요.** 요기패스 판독이 없다. 멤버십 있는/없는 계정으로 수집을 두 번
  돌려 대조하는 방법이 있지만 후순위.
- **땡겨요.** 멤버십이 없다. `"none"`이 맞다.
- **허브 빌더가 쿠폰함을 다시 읽는 것.** 허브 빌더는 발급 시점에 읽은
  쿠폰함 목록으로 와우/비회원을 적을 뿐, 쿠폰함에 없는 브랜드는 안 적는다.
