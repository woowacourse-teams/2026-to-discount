# 핸드오프: 최소주문 "없음"과 "미확인" 구분 (2026-10-01)

수집 스크립트를 맡은 세션에 넘긴다. 웹 화면은 이 세션이 고친다(mono `feat/card-minorder`).

## 결정 (사용자, 2026-10-01)

브랜드 카드의 대표 금액 아래에 최소주문을 적는다. 값은 둘로 가른다.

| 원장 값 | 화면 |
|---|---|
| `minOrderAmount: 0` | `최소주문금액 없음` |
| `minOrderAmount: null`(또는 키 없음) | `최소주문금액 미확인` |
| 양수 | `18,900원 이상` |

## 수집기가 할 일

- 판독이 "최소주문 조건 없음"을 **화면에서 확인한 경우**에만 0을 쓴다.
  - 예: 쿠폰함에 최소주문 줄이 없고 다른 조건 줄은 읽힌 경우
- 못 읽은 경우는 null로 둔다.
  - 예: 화면에 닿지 못함, 판독 실패, 해당 앵커 미검출
- 지금 0을 "못 읽음"의 뜻으로 쓰는 곳이 있으면 null로 바꾼다. 반대로 null을 "없음"으로 쓰는 곳도 찾는다.
- AGENTS.md "먼저 알 것" 1항(부재를 주장하려면 양성 신호가 있어야 한다)을 그대로 적용한다. "없음"은 관측이고, "미확인"은 미관측이다.
- 결론은 테스트로 박는다.
  - 0을 쓰는 경로는 "조건 줄을 읽었다"는 신호가 있어야만 지나가게 한다.
- 최소주문 재사용(`KEEP_DAYS` 14일)이 null을 옛 양수로 덮는 것은 지금처럼 둔다. 0을 덮을지는 따로 정한다.

## 확인 방법

- 원장에서 `minOrderAmount == 0`인 관측마다, 그날 캡처에 최소주문 줄이 없다는 판독 근거가 남아 있는지 본다.
- 웹 프리뷰에서 "없음"과 "미확인" 카드 수를 세어 원장과 맞춘다.

## 수집기 반영 (2026-10-01)

- 한 자리: `capture/min_order.py`. 0은 `is_no_min_order(text)`(화면 글자 "최소 주문금액 없음"류)를 지날 때만 쓴다.
- 쓰는 곳
  - 쿠팡이츠 프로모션(`capture/coupangeats.py`): 원래 그 글자를 읽을 때만 0이었다. 공통 판정으로 바꿨다.
  - 쿠팡이츠 쿠폰함(`capture/coupangeats_couponbox.py`): 그 글자를 읽으면 0, 줄이 안 보이면 None. 0이면 원문(`raw_text`)에 "· 최소주문금액 없음"을 붙여 근거를 남긴다.
  - 배민 쿠폰함, 배짱할인, 땡겨요, 요기요, 브랜드관 링크는 최소주문 줄을 읽어야 쿠폰을 세우거나 못 읽으면 None이다. "없음" 문구를 본 적이 없어 0 경로를 만들지 않았다(보수적으로 미확인).
- 점검 결과: 원장에 `min_order_amount == 0`은 한 건도 없다. 0을 "못 읽음"으로 쓰는 곳은 없었다. 확인용 출력(`build_ce_couponbox_records`, `open_ce_couponbox`)만 None을 "0원↑"로 찍고 있어 "최소주문 미확인"/"최소주문 없음"으로 고쳤다.
- 병합: `store.MERGEABLE_DETAIL`은 None만 채운다. 0(없음)은 관측이라 옛 양수로 덮이지 않는다. API `Offer.withDetailFrom`도 null만 채우므로 두 층이 같다(ADR-016, 목록 글자는 안 바꿨다).
- 최소주문 재사용(14일)이 0을 덮을지는 이번에 안 정했다. 지금 원장에 0이 없어 영향이 없다.
- 테스트: `tests/test_min_order_none.py`.
