# 개발 워크플로 로컬 규칙

mono 설계 [119](../../mono/docs/design/119-dev-workflow.md)(이슈에서 병합까지 개발 워크플로 자동화)의 역할 정의가 따르는 로컬 규칙이다. mono는 공개 저장소라서 로컬 PC, 폰, 하네스에 관한 규칙은 이 문서에 둔다. 역할 정의 파일은 규칙 문장을 옮겨 적지 않고 이 문서와 출처를 가리킨다.

## 규칙

아래 규칙은 2026-10 사고와 사용자 정정에서 나왔다. 커밋, push, 작업 폴더, 프로세스, 직접 push 예외는 [`WORKFLOW.md` 7절](../public/WORKFLOW.md#7-규칙과-가드-이-문서가-단일-진실)이 정본이다. 이 표는 역할별 적용과 출처만 적고, 7절과 다른 줄은 7절을 따른다.

| 규칙 | 적용 역할 | 출처 |
| --- | --- | --- |
| 요구사항을 받아 적지 않고 비판해 더 나은 안을 낸다 | 설계자 | 메모리 feedback_critique_my_ideas, 10-16 정정 |
| 새 스크립트, 도구, 절차를 제안할 때만 `find_prior.py`로 있는 것부터 찾는다. 기존 코드를 고치는 구현에는 돌리지 않는다 | 설계자, 구현자 | 하네스 `rules/recall.md`, 10-16 배민 쿠폰 정정, 10-21 노랑통닭 링크 건(`catch_link.py`를 못 찾음) |
| 설계 문서는 기존 `docs/design/` 형식을 따르고, "한 PR에서 리뷰 가능한 범위"가 아니면 이슈를 나눈다 | 설계자 | mono design 14, 16, 18, 20, 22 점검표 |
| 작업 폴더(worktree)는 저장소 밖에 둔다 | 로컬 러너 전부 | 10-15 15:55 수집을 통째로 건너뛴 사고 |
| 360px 스크린샷을 눈으로 본다. 고친 카드뿐 아니라 첫 화면의 다른 카드도 본다 | 웹 구현자, 리뷰어 | 메모리 feedback_verify_before_declaring, feedback_check_other_cards |
| 문서만 바꾸는 것은 PR로 묶지 않는다 | 요약자 | 10-16 12:42 정정 |
| 프론트 회귀(내가 낸 잘못된 정보가 운영에 나간 상태)는 프리뷰 승인 없이 병합한다 | 웹 구현자 | 메모리 regression-hotfix-direct |
| 병합된 브랜치와 프리뷰 브랜치는 병합 뒤 지운다. 사람이 올린 것과 워크플로가 만든 것을 가른다 | 병합 워크플로 | 10-17, 10-18 정정, 메모리 feedback_confirm_before_destructive |
| 띄운 개발 서버와 브라우저는 같은 작업 안에서 끈다. 창이 뜨는 브라우저는 알리고 띄운다(headless로 되는 일은 headless로). 작업 끝에 `leftover_procs.py --kill`을 돌린다 | 로컬 러너 전부 | 10-16 02:20 메모리 고갈 사고, 하네스 `rules/processes.md` |
| 운영 서버 직접 쓰기는 허용한다. 끝나면 운영 API로 확인해 PR이나 이슈에 기록한다. 자동 판정이 막으면 명령을 붙여 사람에게 재승인을 요청한다. 공유 하네스 설정(`settings.json`)은 건드리지 않는다 | 전부 | 10-21 사용자 결정, 메모리 feedback_settings_effort |
| 수집 구현자는 폰을 잡을 때 인계 파일의 `폰 시험:` 줄에 표시하고 놓을 때 지운다. 그 줄이 비어 있을 때만 시작한다. 다른 역할과 세션은 폰을 읽기만 하고, 조작이 필요하면 수집 구현자나 수집 세션에 요청한다 | 수집 구현자 | 10-21 사용자 결정, 메모리 handoff-* |
| 폰을 잡는 작업은 예약 수집 시각([`ROUTINE-SPEC.md`](../setup/ROUTINE-SPEC.md))을 피한다. 수집 시험은 `scripts/collect_trial.ps1`로 한다 | 수집 구현자 | `AGENTS.md`, `docs/setup/ROUTINE-SPEC.md` |

## 규칙을 고치는 방법

사용자 정정 집계(`claude-harness/reports/corrections-*.md`)를 주마다 입력으로 쓴다. 같은 정정이 두 번 나오면 해당 역할 규칙에 출처를 붙여 넣는다.
