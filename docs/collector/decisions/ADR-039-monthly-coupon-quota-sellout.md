# ADR-039. 월 1회 쿠폰은 한도가 차면 허브에서 사라진다: 읽기 실패와 소실로 보지 않는다

- 날짜: 2026-11-18
- 상태: 확정 (사용자 지시 2026-11-18: 월 1회 쿠폰도 한도가 있어 소진 처리, 한도 단위는 내일 확인)
- 관련: [ADR-033](ADR-033-sold-out-is-an-observation-with-evidence.md), [ADR-035](ADR-035-loss-guard-stays-targeted-skip-is-standing.md), [ADR-029](ADR-029-membership-is-a-tier-dimension.md), 커밋 `4b2a4bbd`(#285), `08d98d59`

## 맥락

2026-11-18 허브를 15:55 회차 로그와 18:12 직접 읽기(상한 60회, 바닥까지)로 대조했다. 월 1회 쿠폰 카드(왓더버거, 공차 등)가 고정 카드 목록에서 빠져 있었다.
처음에는 "허브에서 사라진다"고 읽었으나 **틀렸다.** 22:05 사전 훑기로 허브를 끝까지 읽어 보니 왓더버거, 공차, 청년피자, KFC, 버거킹, 쉐이크쉑, 노브랜드버거, 백억커피 8곳이
`수량소진`(`sold_out`)으로 허브에 있었다. 기존 리더(`_scan_hub`)가 소진 카드를 고정 카드 목록에서 빼서 목록에 안 보였을 뿐이다(사용자 말씀대로: 수량이 소진되면 위치가
바뀌고 눌리지 않는다). 그 결과 둘이 생겼다.

- 3b가 카드를 찾으려고 브랜드마다 허브를 두 번 훑어 카드 하나에 240~300초를 쓰고 `lost_hub`(읽기 실패)로 끝났다. 허브가 길어 상한(14회)이 양끝에 못 닿는 일도 있었다.
- 서버에 월 1회 구간이 있는데 들어오는 쪽에 없다는 이유로 소실 가드가 8단계를 막았다(최근 9일 중 6일 업로드 거부).

## 결정

1. **3b는 허브를 먼저 한 번 끝까지 훑는다.** 보이는 카드 이름(카드가 없는 바닥 화면은 화면 글자 집합)이 직전과 같음을 바닥과 맨 위에서 두 번씩 확인해야 "다 봤다"다. 다 봤고 그 브랜드의
   클릭 가능한 고정 카드가 없으면(카드가 없거나, 소진 또는 오픈 전이라 눌리지 않으면) 스크롤 없이 `absent_hub`로 적는다. 미관측(`ABSENT`)이며 읽기 실패가 아니다. 끝까지 못 봤거나 모은 카드가 `HUB_MIN_CARDS`(8) 미만이면 없다고 단정하지 않고 예전 방식으로 읽는다.
2. **소실 가드는 월 1회 구간이 오늘 허브를 읽은 행에서 안 보일 때 그 구간을 소실로 보지 않는다.** 오늘 허브를 못 읽은 날, 월 1회가 아닌 구간은 그대로 막는다. ADR-035의 "가드를 약하게 하지 않는다"는 유지한다: 면제는 양성 신호(오늘 허브 읽음)가 있을 때만 서고, 사람 승인(`--accept-loss`)은 그대로다.
3. **원인을 단정하지 않는다.** 한도 소진인지 받은 뒤 사라진 것인지(와우 월간쿠폰은 받은 뒤 허브에서 사라지는 것이 정상, ADR-029)는 이 계정의 화면만으로 못 가른다. 한도 단위(일 또는 월)는 내일 확인한다. 이 결정은 둘 다 같은 처리다.

## 남은 것

- **소진 월 1회 카드는 아직 원장에 행이 없다.** 리더가 소진 카드를 고정 목록에서 빼기 때문이다. 소진을 `sold_out` 관측으로 남기는 것(ADR-033 확장)이 다음 단계이고, export와 웹에 번지므로 `CHANGE-PROPAGATION.md`를 먼저 본다.
- 재고에 따라 금액이 내려가는 카드(2026-11-18 이마트에브리데이 7,000 -> 3,000, 롯데슈퍼 7,000 -> 1,500)는 이 ADR의 범위 밖이다. 같은 카드의 금액 하락을 소실로 볼지는 별도 결정이 필요하다.
- 허브 카드 급감 가드(직전의 80%, ADR-035)는 월간 카드를 이미 양쪽에서 세지 않는다. 변경하지 않았다.
