# 설계: 관측 경로 도메인으로 쿠폰함 단독 쿠폰을 내보내지 않는다 (이슈 #72)

- 상태: 구현됨 (2026-10-29, 구현자). 바뀐 것은 맨 끝 '변경 이력'
- 영역: **export** (폰 불필요. 수집 코드는 바꾸지 않는다)
- 읽은 것: 이슈 입력, `docs/specs/issue-46-coupangeats-couponbox-residual-offer.md`(변경 이력 포함), `export_data.py` 300~620행(`COUPONBOX_SECTION`, `_is_ce_hub`, `hub_read_rounds`, `couponbox_residual`, `build_export`)과 912~952행(`main`의 콘솔 출력), `store.py` 함수 목록, `tests/test_ce_couponbox_residual.py` 시험 이름, `mono/docs/CHANGE-PROPAGATION.md` 전체, 쿠폰함 빌더 세 곳의 `section` 값.
- **읽지 않은 것**: 땡겨요 쿠폰함 레코드가 원장에 있는지(빌더 파일을 못 찾았다), 배민과 요기요 브랜드 화면 행의 `section`/`page` 값 분포, `ROUTINE-SPEC.md`와 `reports/routine-<날짜>.md`를 만드는 코드, `check_routine.py`가 export 출력 줄을 읽는지, mono PR #208 초안. 해당 자리는 구현자가 먼저 열어 확인하고 이 문서의 해당 절을 고친다.

## 1. 지금 코드가 하는 일

- #47(`couponbox_residual`)은 **쿠팡이츠 한 앱**에만 걸린다. 허브를 정상으로 읽은 회차 D1, D2에 둘 다 없고, 전에 허브에 섰고, 승자가 쿠폰함 행일 때만 내린다(`export_data.py` 393~418행).
- 경로의 개념이 코드에 없다. "허브 출처"는 `_is_ce_hub`(함수), "쿠폰함 출처"는 `r.section == COUPONBOX_SECTION`(문자열 비교), "행사 카드"는 `_is_ce_event_card`(함수)로 흩어져 있고 쿠팡이츠 이름이 박혀 있다. 배민, 요기요는 쿠폰함 행이 같은 문자열(`"쿠폰함 보유쿠폰"`)을 쓰지만 판정이 없다.
- 콘솔: `build_export`가 경고를 `경고: ...`로 찍는다. `main`은 링크 집계와 `export.json N건(제외 M건: 만료·미관측·지난수집)`만 찍는다. 판정이 보류든 돌았든 줄이 있으나, **판정이 아예 호출되지 않은 경우**(쿠팡이츠 레코드가 없는 원장 등)와 "내보내기에서 뺀 건 0"은 줄 유무로만 갈린다. 또 `main`은 판정 줄을 `[경고]`로 걸러 싣지 않아(`"허브 탭 0건"`만 통과) 요약 줄에 안 나온다. 사용자가 짚은 결함이다.

## 2. 비판: 이슈를 그대로 받으면 안 되는 곳

1. **"쿠폰함에서만 확인되면 오퍼가 아니다"는 #47의 전제와 정면으로 부딪히는 곳이 하나 있다.** #47 시험 T4는 "허브에 한 번도 안 선 쿠폰함 전용 브랜드는 남는다"를 박았다(허브 밖에서 받은 쿠폰이 정상으로 있을 수 있음). 이슈는 기존 시험 통과와 "쿠폰함에만 있으면 안 나간다"를 둘 다 요구한다. 동시에는 안 된다. 이 설계의 기본안은 **T4를 유지**한다: 전에 다른 경로로 선 적이 있는 브랜드만 내리고, 한 번도 선 적이 없는 쿠폰함 전용은 유지하되 **콘솔에 따로 센다**(5번). 이유: 이 프로젝트의 실패는 조용한 소실이고, 되돌리기는 데이터 한 칸(`needs_prior_standing`)이면 된다. 사용자 결정이 "전부 내림"이면 그 칸을 끄고 T4를 뒤집는다(10번 질문 1).
2. **"앱 화면에 뜨는 경로가 쿠폰함보다 항상 이긴다"를 모든 앱에 한꺼번에 켜면 안 된다.** 배민은 브랜드 화면을 4a 전수에서 시간 예산을 두고 오래 안 본 곳부터 돈다(최근 커밋 6ff00f8). 브랜드 화면 관측이 "충분히 최근"이 아닌 브랜드가 많을 수 있고, 그걸 "단독"으로 읽어 내리면 살아 있는 배민 쿠폰이 대량으로 사라진다. 앱마다 경로 표에 `stands_alone`을 두되, **배민, 요기요, 땡겨요는 이번 PR에서 쿠폰함을 단독 근거로 유지**(= 지금과 같은 동작)하고, 판정은 돌려서 "쿠폰함 단독 N건"만 센다(그림자 계수). 실측 수를 보고 사용자가 앱별로 켠다. 쿠팡이츠만 이번에 켠다(허브 회차라는 검증된 신선도 신호가 #47에 있다).
3. **새 객체를 늘리지 않는다.** 경로 객체는 셋(허브, 브랜드 화면, 쿠폰함)이면 충분하고, 쿠팡이츠 행사 카드는 허브 경로의 **속성**(`extra_sections`)으로 접는다(이미 `hub_read_rounds`가 행사 카드를 허브 회차 창에 더하는 규칙, 이슈 #55). 쿠폰함이 앱마다 값만 다르면(구역 이름, 신선도 창) 속성이다.
4. **플랫폼 서브클래스를 만들지 않는다.** 요구대로 `PLATFORM_PATHS: dict[str, tuple[Path, ...]]` 데이터 한 장이다.
5. **응답과 화면에 아무것도 안 싣는다.** `쿠폰함에서만 확인됨` 표식은 `link_report`와 콘솔에만 있다. 오퍼 dict(`FIELDS`)에 칸을 더하지 않는다(mono #164 `receivedOnly` 폐기와 같다).

## 3. 도메인 모델

새 모듈 `observation_paths.py`(순수 함수와 작은 데이터. 파일, 네트워크를 읽지 않는다). 이름은 구현자가 정하되 구조는 아래를 따른다.

```
ObservationPath(
    name,                 # "hub" | "brand_screen" | "couponbox"
    matches(record) -> bool,          # 이 행이 이 경로의 관측인가 (구조로: hub_tab 유무, section/page 상수)
    stands_alone: bool,               # 이 경로 관측만으로 오퍼가 설 수 있는가
    needs_prior_standing: bool,       # 허브나 브랜드 화면에 선 적이 있어야 쿠폰함 단독을 뺀다(없으면 단독 유지)
    recent(ledger) -> Verdict,        # 관측이 충분히 최근인가 (3.2)
)
PLATFORM_PATHS = {
    "coupangeats": (HUB, BRAND_SCREEN, COUPONBOX),   # BRAND_SCREEN 포함 여부는 구현자가 원장에서 확인(읽지 않음)
    "baemin": (BRAND_SCREEN, COUPONBOX), "yogiyo": (BRAND_SCREEN, COUPONBOX),
    "ddangyo": (...),     # 쿠폰함 레코드가 원장에 있는지 확인 못 함. 없으면 쿠폰함 경로 없이 둔다
}
```

### 3.1 노출 판정은 경로의 답에서 도출한다

오퍼(앱, 브랜드, 자리)에 대해 그 앱의 경로마다 "관측이 있나"를 묻는다.

- `stands_alone`인 경로에 최근 관측이 있다 → **노출**.
- 쿠폰함(`stands_alone=False`)만 관측이 있다 → `쿠폰함에서만 확인됨`. 아래 중 하나로 가른다:
  - 쿠폰함 경로가 `stands_alone=True`로 선언된 앱(배민, 요기요, 땡겨요) → 노출(지금과 같음). 센다만.
  - 다른 경로가 판정할 수 없다(`Verdict.UNJUDGEABLE`: 허브를 정상으로 읽은 회차 2 미만 등) → **판정 보류**, 노출 유지.
  - 전에 선 적이 없다(`needs_prior_standing`) → **단독 유지**, 노출 유지(2번 1항).
  - 그 외(다른 경로가 판정 가능했고 거기에 없다) → **내보내기에서 뺀다**.
- 쿠폰함 경로가 없는 앱, 경로 하나뿐인 앱 → 이 판정을 거치지 않고 지금과 같다.

### 3.2 `recent` (관측이 충분히 최근인가)

경로마다 다른 값이라 객체 안에 둔다(속성 + 한 함수).

- 허브: #47 규칙 그대로. 허브를 정상으로 읽은 회차(`hub_read_rounds`, 문턱 `HUB_READ_MIN_BRANDS`, 회차 간격 `HUB_ROUND_GAP`, `HUB_ROUND_APART`)의 최근 둘 D1, D2에 그 브랜드가 있으면 최근이다. **함수 본체를 옮기고 새로 쓰지 않는다**(값이 갈라지는 일(같은 값을 두 곳에 두는 것)을 만들지 않으려고 상수는 한 곳에 둔다).
- 브랜드 화면: 이번 PR에서는 쿠팡이츠 경로 표에 넣지 않고, 배민과 요기요는 `recent`를 **계수용으로만** 구현한다. 창 길이는 이 설계가 정하지 않는다. 구현자가 `data/sweeps.jsonl`과 원장으로 브랜드 화면 관측 간격 분포를 재서 상수 주석에 적는다(근거 없는 숫자 금지).
- 쿠폰함: 승자 수집 시각이 D2 이상(#46 4.3의 5번). 이보다 오래됐으면 이 판정 대상이 아니고 만료, `is_stale_sweep`이 맡는다.

## 4. 기존 #47과 흡수

`couponbox_residual`, `hub_read_rounds`, `_is_ce_hub`, `_is_ce_event_card`는 **동작을 그대로 두고** 경로 객체 뒤로 옮긴다(허브 경로의 `matches`/`recent`가 이 함수를 부른다). 호출 한 줄(`build_export` 542행)이 `exposure_verdicts(records, winners)` 한 호출로 바뀐다. 내림 조건 5개(#46 4.3)는 쿠팡이츠에서 그대로이고, 새로 도는 것은 (a) 앱 표에 따른 일반화, (b) 보류, 단독 유지, 그림자 계수의 분류와 출력뿐이다. 그래서 `tests/test_ce_couponbox_residual.py` 전체(T1~T10, 55-T1~T7, 업로드 가드)가 **고치지 않고** 통과해야 한다. 하나라도 고쳐야 하면 설계 변동으로 PR에 적는다.

## 5. 콘솔과 보고서 (확인은 콘솔이 준다)

판정은 **항상** 앱마다 한 줄을 찍는다. 줄이 없으면 호출되지 않은 것(버그)이고, `0건`은 "돌았고 해당 없음"이다.

```
노출 판정 [coupangeats]: 실행 / 쿠폰함 단독 4건 = 내보내기에서 뺀 건 2 + 판정 보류 0 + 단독 유지(전에 선 적 없음) 2 / 허브 회차 D1 10-29 02:37, D2 10-28 02:41
  내보내기에서 뺀 건: 푸라닭 쿠폰함 10-29 02:50, 마지막 허브 10-21 09:18
노출 판정 [baemin]: 실행(계수만) / 쿠폰함 단독 N건
노출 판정 [coupangeats]: 미실행 / 사유: 쿠팡이츠 레코드 0건
노출 판정 [coupangeats]: 보류 / 사유: 허브를 정상으로 읽은 회차 1회(<2) / 쿠폰함 단독 4건 유지
```

- 구조: `link_report["exposure"] = {앱: {"ran": bool, "reason": str|None, "box_only": [...], "dropped": [...], "held": [...], "kept_no_prior": [...]}}`. 줄은 이 dict에서 만든다(출력이 계산을 가리지 않게).
- `main`이 지금 `[경고]` 거르기로 못 싣는 판정 줄을 요약에 싣는다(1번의 결함). `경고:` 줄 접두는 `build_export`가 모든 warn에 붙이니, 판정 줄은 `warn`이 아니라 별도 목록으로 두고 같은 자리에서 찍는다.
- 정리가 필요한 요약은 보고서에: 어느 코드가 `reports/routine-<날짜>.md`를 쓰는지 **읽지 않았다**. 구현자가 `reflect_daily.py`/`run_routine.py` 근처에서 export 단계 출력이 보고서에 어떻게 실리는지 확인하고 판정 줄을 같은 방식으로 싣는다. 판정기 `check_routine.py`가 export 출력 모양을 읽으면 같이 맞춘다(폭발 반경 6번).

## 7. "없다 / 0 / 통과"의 양성 신호

| 자리 | 조용히 거짓이 되는 때 | 양성 신호 |
| --- | --- | --- |
| "다른 경로에 없다" | 허브를 못 읽은 회차를 "없음"으로 셈 | 허브 회차의 브랜드 수가 문턱 이상(#47 그대로). 아니면 `판정 보류` |
| "다른 경로에 없다" (브랜드 화면, 배민, 요기요) | 4a 시간 예산으로 안 본 브랜드를 "없음"으로 셈 | **이번엔 계수만, 내리지 않음.** 켤 때의 신호는 "그 브랜드의 브랜드 화면을 그 창 안에 열었다"(`sweeps.jsonl` 항목 또는 판독 실패 키)이고, 실측 뒤 후속에서 정한다 |
| "쿠폰함 단독 0건" | 판정이 안 돌아 0 | `ran` 칸과 `노출 판정` 줄이 앱마다 항상 있다. 줄이 없으면 호출 실패. 시험 T7 |
| "내보내기에서 뺀 건 0" | 보류와 해당 없음이 섞임 | 분류 넷(뺀 건, 판정 보류, 단독 유지, 해당 없음)을 줄에 따로 센다 |
| "쿠폰함 경로 없음" 앱 | 경로 표에 앱을 빠뜨려 판정 없이 지나감 | 원장에 나온 모든 `platform`이 `PLATFORM_PATHS`에 있다는 시험(T11). 없는 앱이 나오면 시험이 깨진다 |
| 구조 판별 | 구역 문구가 바뀌어 `matches`가 조용히 빗나감 | 문구가 아니라 `hub_tab` 유무와 구역 상수로 짚고, 빌더의 `section` 상수와 `COUPONBOX_SECTION`을 맞대는 시험(#55 T7처럼). 지금 빌더 세 곳이 같은 문자열을 상수 없이 적고 있다 |

## 8. 테스트 (결론을 박는 곳)

`tests/test_observation_paths.py`를 새로 만든다. 구현 전에 T1이 빨갛게 나오는 것을 먼저 본다. 쿠팡이츠 픽스처는 `tests/test_ce_couponbox_residual.py`의 것을 재사용한다(복사하지 않고 import 또는 conftest로).

- **T1 끝 조건 1**: 전에 허브에 섰던 쿠팡이츠 브랜드가 쿠폰함에만 있고 허브 회차 D1, D2에 없다 → `build_export`에 오퍼가 없고, `link_report["exposure"]["coupangeats"]["dropped"]`에 브랜드가 있고 콘솔 줄에 `쿠폰함 단독`과 `내보내기에서 뺀 건`이 찍힌다.
- **T2 끝 조건 2**: 같은 브랜드가 D1이나 D2 허브에도 있다 → 정상 오퍼로 나간다. 브랜드 화면 행이 있는 경우도 같다(브랜드 화면 `matches`가 노출 근거로 세는지).
- **T3 끝 조건 3**: 쿠폰함 경로가 없는 앱(경로 표에서 쿠폰함을 뺀 가짜 앱 한 줄을 `PLATFORM_PATHS`에 주입)과 경로 하나뿐인 앱 → 이전과 같은 출력(`build_export` 결과가 이 변경 전 결과와 완전히 같은 픽스처 비교).
- **T4 (= #47 T4) 단독 유지**: 한 번도 선 적 없는 쿠폰함 전용은 남고, 콘솔에 `단독 유지(전에 선 적 없음)`으로 센다.
- **T5 끝 조건 4**: 판정 미실행(쿠팡이츠 레코드 0건), 판정 보류(허브 회차 1회), 돌았고 뺀 건 0, 뺀 건 N의 네 가지 줄이 서로 다르다. 줄 없음은 시험이 실패로 본다.
- **T6 응답 비오염**: `build_export` 결과의 모든 오퍼 dict 키가 `FIELDS`에서 온 것뿐이고, 직렬화한 export.json 문자열에 `쿠폰함에서만` 이 없다.
- **T7 계수만 켜는 앱**: 배민, 요기요는 같은 조건(쿠폰함 단독)에서 **오퍼가 남고**, `exposure`에 단독 건수가 센다. (그림자 계수 고정. 켜는 것은 후속)
- **T8 다시 허브 복귀**: 내보내기에서 뺀 대상이 허브에 돌아오면 원장 수정 없이 오퍼가 되살아난다(#46 T8 일반화).
- **T9 업로드 가드**: 내보내기에서 뺀 오퍼가 `losing_detail`로 막히지 않는다(기존 시험 통과).
- **T10 이름 맞댐**: 빌더 세 곳의 `section` 값과 `COUPONBOX_SECTION`, 행사 카드 구역 상수와 수집기 상수가 같다(문구 갈림 방지).
- **T11 앱 누락**: 원장 픽스처의 `platform` 전부가 경로 표에 있다.
- 기존 `tests/test_ce_couponbox_residual.py`, `tests/test_export_data.py`, `tests/test_store.py`, `tests/test_same_day_other_source.py`, `tests/test_check_deploy.py`, `tests/test_export_fields.py`가 **고치지 않고** 통과한다.

## 9. 원장 append-only

원장 `data/log.jsonl`을 읽기만 한다. 쓰지 않고 `excluded`도 기계가 찍지 않는다(ADR-030). 내림은 export 단계의 걸름이라 같은 원장에서 같은 결과가 나온다. 정정은 더 늦은 시각의 새 관측(다른 경로 행)으로 자연히 된다. `data/offer_seen.json`(상태 파일)은 원장이 아니므로 10번 질문 3의 결정에 따라 쓰지만, 이 PR이 원장 소급 정정을 하지는 않는다.

## 10. 사용자에게 물을 것

1. **(닫힘, 변경 이력) T4(허브에 한 번도 안 선 쿠폰함 전용)**: 기본안은 유지 + 콘솔에 따로 셈. "쿠폰함에만 있으면 전부 내림"이면 `needs_prior_standing`을 끄고 T4를 뒤집어야 하고, 이 경우 기존 시험 하나가 바뀐다.
2. **(닫힘, 변경 이력) 앱별 켜기**: 이번엔 쿠팡이츠만 내리고 배민, 요기요, 땡겨요는 계수만 해도 되는가. 실측 수를 PR에 싣고 앱마다 후속으로 켠다.
3. **(닫힘, 변경 이력) 뺀 오퍼의 `firstSeenAt`**: 내보내기에서 빠졌다 되살아나면 "신규"로 다시 뜨는 것을 막으려 내림도 `carry`에 이어 둘까. 안 이으면 허브 복귀 때 신규로 표시된다.
