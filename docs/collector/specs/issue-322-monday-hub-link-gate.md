# 이슈 322: 월요일 00시대 3단계를 새 허브 링크가 올 때까지 보류한다

영역: `collect`. 시험은 폰 없이 돈다(`tests/test_ce_link_gate.py`). 사용자 지시 2026-11-16 02:4x: 월요일엔 허브 단계를 후순위로 미루고 기다리다 안 오면 그대로 간다. 만료 판정과 수집 순서는 별개다. 이 건에 한해 설계 승인 단계를 건너뛰고 바로 구현한다.

## 1. 문제

월요일 00:01 회차의 3단계가 옛 공유 링크로 매주 죽는다(10-26, 11-02, 11-09, 11-16). 허브는 00시에 바뀌고 새 링크는 사람이 00:2x~00:5x에 주기 때문이다. 3단계가 죽으면 3s, 3b, 5a, 5b, 6, 7이 건너뛰어지고 3s가 새 링크를 읽는 길도 막힌다.

## 2. 폭발 반경

`mono/docs/CHANGE-PROPAGATION.md`에 3단계 순서나 `run_routine` 풀이 걸린 줄은 없다(없다고 말하고 시작). 코드에서 찾은 짝:

| 자리 | 넣나 | 이유 |
|---|---|---|
| `scripts/run_routine.py` `Task.gate`, `Pool.pick`, `Pool.run`, `main` | 고침 | 보류와 출력 한 줄 |
| `capture/coupangeats_share.py` `link_in` | 더함 | `share_link`와 mono 원격 사본이 같은 정규식을 쓰게 한다. 동작 변경 없음 |
| `find_hub_key`, `share_link_fresh` | 안 고침 | 만료 판정은 그대로(사용자 2026-10-21). 폴백 없음도 그대로 |
| `reflect_daily`, 8단계 선행 | 안 고침 | 8은 이미 선행 실패를 허용한다. 90분 뒤에도 안 열리면 3단계 실패 → 후속 건너뜀 → 8은 쿠팡이츠 없이 간다 |
| `check_routine`, `STEPS`, 단계 목록 | 안 고침 | 새 단계 번호를 만들지 않았다. 3단계 출력 맨 앞 한 줄만 는다 |
| ROUTINE-SPEC 단계 3, COLLECTION-INCIDENTS | 고침 | 동작과 확인법 |

## 3. 설계

- `scripts/ce_link_gate.py` `LinkGate`: `held()`가 참인 동안 `Pool.pick`이 그 단계를 집지 않는다(선행이 끝났어도). 다른 폰은 다른 단계를 계속 돈다. `Pool.pick`이 폰마다 1초 간격으로 부르니 조회는 60초에 한 번만 한다.
- **풀리는 조건**: (a) 상수 링크(`COUPANGEATS_LINK`)가 HTTP로 푸는 허브 키가 직전 수집이 연 키(`captures/coupangeats-hub-share-<전날 이전 가장 최근>.json`의 `key`)와 다르다. (b) 시작 뒤 90분. (b)는 지금 링크로 한 번 시도한다. 날짜나 요일로 이번 주 키를 짐작하지 않고(10-21 결정), "지난 수집과 같은가"만 본다. 키 모양(`V5_DEAL_`, `V5_WOW_LOUNGE_`)이 바뀌어도 다르면 풀린다.
- **걸리는 회차**: 월요일 00~03시 시작, 직전 키를 아는 때만. 시험(`PYTEST_CURRENT_TEST`)과 풀이 없는 옛 큐에는 안 건다.
- **사람 단계 하나 덜기**: 조회 때마다 `git -C mono fetch`로 `origin/main`의 링크를 보고 다르면 `merge --ff-only`로 수집 트리를 맞춘다(합쳐지지 않으면 둔다). 링크 교체 push만 사람이 하면 된다.
- **알림과 기록**: 보류 시작에 슬랙 한 번, 풀릴 때 한 번. 3단계 출력 맨 앞에 `[대기] 허브 링크를 N분 기다렸다 - 새 링크가 왔다(키)` 또는 `… 안 와 지금 링크로 시도한다`.

## 4. 하지 않은 것

- 홈 라벨 폴백(10-21 결정을 뒤집는다). 링크를 대신 만드는 일(앱이 사람 계정으로만 만든다).
- 3b, 3w, 6, 7 따로 보류: 모두 3을 선행으로 둬서 3 하나로 충분하다.
- 풀 없는 큐의 보류: 운영은 풀로 돈다. 풀 없이 돌리는 날이 생기면 본다(`ce_link_gate.py` 머리말 ponytail).

## 5. 시험

`tests/test_ce_link_gate.py`: 같은 키면 보류하고 키가 달라지면 푼다(조회 간격, 알림 두 번), 상한이 지나면 푼다, 링크를 못 풀면 계속 보류한다, `make_gate`가 월요일 새벽과 직전 키가 있을 때만 건다, `Pool.pick`이 보류 단계를 건너뛰고 풀리면 집는다.
