# 예약 실행 소요 줄이기 — 죽은 링크 장부 + 전수조사 하루 한 번 (2026-09-17)

브레인스토밍 결과(사용자 결정 A+B, 월요일 예외, 죽은 링크 보고 흐름). 구현은
같은 날 먼저 들어갔다(`e6d5903`) — 이 문서는 그 설계를 사후에 적고, §5의 실측으로
맞는지 확인한 기록이다.

## 1. 목표

시간·낭비·신선도 셋 다.
- 한 바퀴 70~90분 중 4단계 전수조사 48분(55%). 그중 배민 29분.
- 배민 44곳 중 매일 30곳 이상이 같은 링크 오류(`브랜드 페이지에 못 닿았다`,
  `deeplink_did_not_open`). 값이 안 읽히면 `last_checked`에 안 올라 **주 1회 의도가
  하루 3번 × 2회 시도**로 뒤집혔다. 29분 중 ~20분 낭비.
- 낮 실행(10:55·15:55)도 전수조사를 돌아 폰을 하루 4시간 잡는다. 브랜드관 값은
  하루 안에 안 바뀐다(주간 주기, ROUTINE-SPEC).

## 2. 결정

| | 내용 | 근거 |
|---|---|---|
| A | **죽은 링크 장부** `data/dead_links.json`. 링크 오류 3회 연속(하루 1회 셈)이면 `_is_due`가 `last_checked`와 같은 주간 규칙을 탄다. 재시도 패스는 링크 오류를 뺀다. 값이 읽히면 장부에서 지운다 | 원인이 스킵 규칙 한 줄. 기존 흐름 안 바꿈. 복구된 링크는 최대 1주 뒤 봄 — 주간 주기 원래 의도 |
| B | **전수조사는 00:01 실행만.** 낮 실행은 4단계 건너뜀. **월요일은 세 번 다** | 주간 주기가 새로 열리는 날 대상이 몰린다. cmd 인자 하나 |
| 보고 | 로그 `죽은 링크로 넘김 N곳` / `죽은 링크 장부 N곳`, `check_routine` 판정에 수, `audit-<날짜>.md` 끝 표, 사람이 `brands.yml` 링크 수정(ADR-025) → 다음 월요일 재확인 → 되살아나면 자동 삭제 | 사람 몫이 명확해야 장부가 안 쌓인다 |
| 안 함 | C 배민 검색 진입(딥링크 대체) | 이틀+, 죽은 링크 목록 나온 뒤 판단 |

## 3. 바뀐 파일

- `scripts/full_audit.py`: `DEAD_LINKS_PATH`·`DEAD_AFTER=3`·`LINK_ERRORS`, `_is_due(..., dead)`,
  `record_link_outcomes()`, 재시도 필터, `write_report(..., dead)` 표.
- `scripts/after_open_daily.cmd`: `RUN_AUDIT` = 시각<03시 또는 `DayOfWeek=1`. 괄호 블록 안이라
  `%ERRORLEVEL%` 대신 `if errorlevel 1`.
- `scripts/check_routine.py`: 단계 4 건너뜀 줄 PASS, 죽은 링크 수 표기.
- `tests/test_dead_links.py`(4), ROUTINE-SPEC 단계 4, ROUTINE-TIMING §4.
- `data/dead_links.json`: 09-15~17 audit로 채움(41곳 기록, 15곳 확정).

## 4. 예상

- 00:01 실행: 배민 29 → 7~10분, 한 바퀴 90 → ~65분.
- 낮 실행: 90 → ~40분(4단계 48분 절약).
- 결과 동일성: 값이 읽히던 브랜드는 그대로(장부는 링크 오류만 건드림). 죽은 링크
  15곳은 판독 실패 목록에서 빠지고 장부 표로 옮겨 간다.

## 5. 실측 — 02:57 `full_audit.py` 단독 재실행(새 규칙) vs 00:01 실행(옛 규칙)

| | 00:01 (옛) | 02:57 (새) |
|---|---|---|
| 4단계 전체 | 48분 | **25.5분** (02:57:30 → 03:22:57) |
| 배민 | 29분, 44곳, 재시도 44곳 | **18분**, 29곳(죽은 링크 15곳 스킵), 재시도 9곳(링크 오류 제외) |
| 배민 결과 | 판독 실패 35 · 만료 후보 9 · 캡처 19 | 판독 실패 5 · 만료 후보 4 · 캡처 23 |
| 땡겨요·요기요 | 19분 | 7.5분 (이번 주기 이미 확인 38·12건 제외) |
| 에러 | 없음 | 없음(Traceback 0) |
| 장부 | — | 43곳 기록, 16곳 확정(+돌배기집) |

**동일성** — 양쪽 다 본 배민 29곳 중 결과가 같은 것 17곳. 나머지 12곳은 같은
브랜드가 `no_store` ↔ `error` ↔ `empty`로 **실행마다 바뀐다**(또봉이통닭·나우카페·
다운타우너·열정국밥…). 즉 배민 딥링크 실패는 브랜드 고정이 아니라 **흔들린다.**
값(tiers)이 읽힌 브랜드는 00:01 0곳, 02:57 1곳 — 배민 브랜드관 순회는 지금
거의 아무것도 못 읽고 있다. 이 사실이 이 문서보다 크다: 장부는 낭비를 줄이지만
**배민 전수조사 자체의 산출이 0에 가깝다**(→ §6).

**부작용 없음** — 원장·export는 안 건드린다(audit는 보고서만). 스케줄러 첫 적용은
10:55 실행(건너뜀 판정)과 09-18 00:01 실행.

## 6. 남는 문제 (다음 결정)

- 배민 딥링크 순회(`collect_via_links`)는 사흘째 값 0~1곳. 링크가 죽었거나(장부 16곳),
  살아도 페이지 판독이 비어 있다(empty 4~9곳). 접근 C(검색 진입) 또는 배민 전수조사를
  **끄고** 배짱·쿠폰함으로만 배민을 보는 선택이 남는다. 사용자 결정 필요.
- 죽은 링크 장부는 흔들리는 실패도 3회 누적이면 죽음으로 친다 — 값이 읽히면 풀리므로
  산출이 0인 지금은 해가 없다.
