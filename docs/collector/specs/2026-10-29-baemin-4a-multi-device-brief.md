# 배민 브랜드관 전수조사(4a) 폰 분산, 상위 검토용 상황 정리 (2026-10-29)

작성: WSL 수집 감시 세션. 사용자 지시("5개 기기를 제대로 활용해 분배하고 병렬로 돌릴 수 있는 로직을 쓰고, 못 하겠으면 상황 정리만 해서 상위 모델이 검증하고 설계하게").

## 요청

4a는 폰 한 대(A8)가 배민 브랜드 158곳을 순서대로 읽고 약 93분이 걸려 90분 상한에 매번 끊긴다. 폰은 5대인데 4a에는 1대만 쓴다. 아래 사실을 검증하고 여러 대로 나누는 설계를 해 달라.

- 배민 앱에 로그인된 폰이 A8 한 대뿐이다(§5). 로그인은 사람이 해야 해서 로직부터 짜도 효과가 없다고 판단해 코드는 쓰지 않았다.
- 로그아웃 폰이 로그인 화면을 "쿠폰 없음"으로 기록하는 구멍이 있다(§6). 분산 전에 막아야 하는지 판단해 달라.

## 1. 문제와 증거

4a가 세 번 연속 90분 상한에 끊겼다. 끊기면 프로세스째 죽어서 읽은 값과 확인 기록(`last_checked`)이 하나도 안 남는다.

| 실행 | 곳 수 | 결과 |
| --- | --- | --- |
| 10-28 00:01 | 158 | 155번째에서 끊김 |
| 10-28 03:53 (재실행) | 158 | 1차 순회는 끝, 값 없는 7곳 재시도 중 7/7에서 끊김 |
| 10-29 00:01 | 158 | 151번째(이타마에스시)에서 끊김. 00:16:37~01:46:38, 곳당 약 36초 |

출처: `logs/steps/2026-10-29/4a.log`, `logs/state.json`. 10-25에 브랜드 35곳이 늘었고(핸드오프), 10-26 4a는 81분이었다.

이름순으로 돌아서 뒤쪽 약 7곳은 계속 못 본다. 10-29 로그에서 직접 센 값: 151곳 중 값이 읽힌 곳 66곳, 나머지는 "가게 없음"이나 "쿠폰 없음".

## 2. 이미 넣은 안전망 (작업 트리, 커밋 전)

분산과 별개로 데이터를 버리지 않게 하는 장치다. 단위 테스트 1736개 통과. 실제 폰 검증과 커밋은 00:01 수집이 끝난 뒤에 한다.

- 배민 첫 순회에 시간 예산 75분(`BAEMIN_BUDGET_S`, 환경변수로 덮어쓰기). 넘기면 새 브랜드를 시작하지 않고 거기까지를 저장한다. 재시도에 15분을 남긴다.
- 대상 정렬을 이름순에서 "안 본 곳 먼저, 그다음 오래된 곳"으로 바꿨다.
- 예산으로 멈춘 순회는 `full=False`. export가 "이번 수집에 안 보인 오퍼는 내린다"(`sweeps.jsonl`)라서 부분 순회를 전수로 적으면 오퍼가 잘못 내려간다.
- 수정 파일: `scripts/full_audit.py`, `capture/brand_links.py`, `tests/test_audit_budget.py`.

예산은 시간을 늘린 게 아니다. 하루에 보는 곳이 약 125곳으로 줄고 나머지는 다음 실행이 이어서 본다. 158곳을 매일 다 보려면 분산이 필요하다.

## 5. 분산을 막는 사실

- 배민에 로그인된 폰이 A8 하나다. 로그인에는 자격증명이 필요하고 사람이 해야 한다. 노트20은 점유가 풀린 뒤 확인해야 한다. X6는 로그인돼 있지만 느리고 4a 값이 안 나온 이력이 있다.
- 계정과 주소가 같아야 같은 값이 나온다. 원장 행에는 `target_address`(A8은 경기도 성남시 수정구 금토동)와 멤버십(배민클럽 여부)이 들어가고 쿠폰 구간이 멤버십에 따라 갈린다. 다른 폰이 같은 계정, 같은 주소, 같은 멤버십인지 확인할 방법이 필요하다.

## 6. 정확성 구멍: 로그인 화면이 "쿠폰 없음"이 된다

V50(로그아웃)에서 시험 모드(`--only`, 장부와 보고서에 안 적음)로 9곳을 읽었더니 9곳 모두 "브랜드관은 열렸고 쿠폰 없음"으로 판정됐다. 같은 9곳을 A8이 오늘 4a에서 읽은 값과 비교한다. 증거 캡처는 배달의민족 로그인 화면이다.

| 브랜드 | A8 (10-29 4a) | V50 (시험) |
| --- | --- | --- |
| BBQ, bhc | 18,000↑ 3,500원 / 18,000↑ 3,000원 | 쿠폰 없음 |
| 네네치킨 | 15,000↑ 3,500원 | 쿠폰 없음 |
| 멕시카나 | 18,000↑ 5,000원 / 18,000↑ 4,000원 | 쿠폰 없음 |
| 오븐마루치킨 | 18,000↑ 3,000 / 25,000↑ 4,000 / 31,000↑ 5,000원 | 쿠폰 없음 |
| 자담치킨, 두찜, 기영이숯불두마리치킨, 아라치치킨 | 값 있음 | 쿠폰 없음 |

- "쿠폰 없음"은 재시도에서 빠지고 확인 기록에 적히는 관측이다(`_settled`). 장부 모드였다면 "확인함"으로 남았을 것이다.
- AGENTS.md의 첫 규칙은 "부재를 주장하기 전에 제대로 봤다를 양성 신호로 증명한다"이다. 로그인 벽 감지가 4a 경로에 없는 것으로 보이지만 `brand_page_is_open`이 왜 통과시켰는지는 안 봤다(추정).
- 캡처 파일이 덮어써진다. `captures/_audit_2026-10-29/baemin/baemin_2026-10-29_<브랜드>.png`는 브랜드별 고정 이름이라 V50 시험이 A8이 찍은 9장을 로그인 화면으로 바꿨다. 오늘 4a는 끊겨서 원장이 가리키는 행은 없다.

## 7. 설계할 때 검토할 것

쓰기 경합
- `full_audit.py`는 끝에 한 번 `last_checked.json`, `dead_links.json`, `audit-<날짜>.json`을 쓴다. 후자는 `_merge_save`가 "내 플랫폼 키만 갈아끼운다".
- 프로세스를 샤드로 나누면 같은 플랫폼 키(`baemin`)를 서로 덮어쓴다. 병합 단계가 필요하다. 한 프로세스 안에서 폰별 스레드로 돌리고 결과를 메모리에서 합치면 파일 경합이 없다.
- `data/resolved_links.json`을 순회 중 쓰는지는 안 봤다.

스케줄
- `run_routine.py`는 폰마다 큐 하나다. 4a는 `app=baemin`이라 A8 큐에 들어간다. 다른 폰이 쓰는 중이면 겹친다. `_dev_locks`는 넘겨받기(takeover) 전용이다.
- 쉬는 폰을 그 순간에만 빌리려면 "큐가 비었고 배민 로그인 사전 점검을 통과한 폰"만 고르는 로직이 필요하다.
- 각 폰 앞에 `prepare`가 필요하다(비행기+Wi-Fi, 앱 정리). LG 폰은 깨우기에 scrcpy 창이 뜬다.

완전성
- 샤드 하나가 중단되면 그 몫은 안 본 것이다. `full=False`로 두고 다음 실행이 먼저 보게 하면 오퍼는 잘못 안 내려간다(§2의 장치).
- 폰 N대면 약 93/N분 + 준비다. 2대면 약 47분으로 예산 안에 든다. 첫 순회에 배분이 고르다는 가정이다.

## 8. 사용자가 정할 것

- V50(와우 계정 폰)에 배민을 A8과 같은 계정, 같은 주소로 로그인할지. 사람이 해야 하는 일이다.
- 노트20의 배민 로그인 상태와, 쿠팡이츠·요기요 단계 사이에 배민 4a 몫을 맡길 수 있는지.
- V30를 수집에 되돌릴지(사용자에게 묻고 켜기로 한 폰), X6 제외를 풀지.
- 158곳을 매일 다 봐야 하는지, 오래된 곳 먼저 이틀 순환으로 충분한지(`RECHECK_DAYS=2`).
