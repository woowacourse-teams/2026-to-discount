# 방문 이벤트 DB 계획 (2026-11-10, 계획만, 구현 전)

결론: 이벤트 횟수와 비율을 쓰는 분석에는 PostHog와 별개로 고정된 정본이 필요하다. 서버 이벤트 로그(`events.jsonl`)를 로컬 SQLite에 증분 적재하는 안을 권한다. 사용자가 승인하기 전에는 아무것도 만들지 않는다.

## 배경

- 방문자 이벤트는 두 길로 쌓인다. 서버가 `POST /api/events`로 받아 `events.jsonl`에 한 줄씩 기록하고(2026-07-29 17:16부터), PostHog에도 들어간다. PostHog에는 브라우저가 직접 보내는 길과 서버 중계(`DISCOUNT_POSTHOG_ENABLED`, 2026-08-21 13:18부터)가 있다.
- 두 길이 같은 이벤트를 하나로 합치도록 `eventId`를 `$insert_id`로 쓰게 설계했다(`delivery-discount-api/docs/traffic-analytics.md`). `eventId`가 없는 옛 요청은 합쳐지지 않는다고 그 문서에 적혀 있다.
- 배너 평가 문서(`docs/research/2026-11-09-banner-effect.md`)가 PostHog 값으로 클릭률과 사용자 지표를 냈다.

## 문제

2026-11-10에 같은 기준으로 서버 로그와 PostHog를 견주니 사용자 수는 맞고 이벤트 횟수는 맞지 않았다.

| 비교 | 서버 로그 | PostHog |
| --- | --- | --- |
| 방문 사용자, 07-29~11-09 5개 기간 | 1,569 / 849 / 5,574 / 3,232 / 3,942 | 1,569 / 852 / 5,729 / 3,255 / 3,979 |
| 07-31 `offer_link_click` | 514 | 1,028 |
| 07-29~08-11 오퍼 링크 클릭 | 1,932 | 3,192 (같은 시각 중복을 지우면 1,913) |
| 08-21~09-28 오퍼 링크 클릭 | 3,951 | 4,763 (같은 시각 중복을 지우면 4,199) |
| 08-21~09-28 화면을 연 횟수 | 12,481 | 15,339 |
| 08-12~08-20 탐색 조작 | 1,659 | 1,720 (같은 시각 중복을 지우면 931) |

- 07-31 PostHog의 클릭은 전부 같은 사용자가 같은 밀리초에 두 줄씩 남긴 중복이다. 이런 날이 07-29~10-30 중 14일에서 5%를 넘는다.
- 중복 제거 키가 하나로 안 맞는다. `(사용자, 시각, 이벤트)`는 08-12~08-20에 정상 이벤트를 지우고, 속성까지 넣은 키는 08-21~09-28의 중복을 못 지운다.
- 서버 로그는 `eventId` 중복이 3건, 같은 초 중복이 281건뿐이다. 개발 트래픽(`dev`)과 봇(`bot`) 표시가 줄마다 붙어 있다.

## 필요성 확인

- 사용자 수만 쓰면 PostHog로 충분하다. 차이가 최대 2.7%다.
- 횟수나 비율(클릭률, 방문 100번당 조작, 링크 클릭 중 배너 몫)을 쓰면 PostHog는 구간에 따라 +23%에서 -2%까지 어긋난다. 배너 평가 문서의 1, 2, 4장이 여기에 든다.
- 따라서 정본이 필요하다. 다만 지금 규모(57만 줄, 332MB)에는 서버가 아니라 로컬 DB로 충분하다.

## 대안

| 안 | 내용 | 판단 |
| --- | --- | --- |
| A | PostHog를 유지하고 질의에서 중복을 지운다 | 위 근거대로 한 키로 구간 전체를 맞추지 못한다. 탈락 |
| B | 서버 로그를 로컬 SQLite에 증분 적재한다 | 서버를 건드리지 않는다. 같은 질의가 항상 같은 값을 낸다. 권고 |
| C | 운영 서버에 DB를 둔다 | 서버 변경과 승인이 필요하고 지금 규모에 과하다 |
| D | 매번 서버 로그를 받아 스크립트로 센다 | 지금 방식이다. 332MB를 매번 옮기고 기준이 사람마다 달라진다 |

## 선택 (제안)

B안. 적재 규칙은 다음과 같다.

- 서버 로그에서 마지막으로 읽은 위치 뒤만 받아 붙인다.
- 중복 키는 `eventId`, 없으면 (`visitorId`, `event`, `ts`, `props` 해시)로 둔다.
- `dev`, `bot`, 점검용 방문자 id(`mono/scripts/experiments.py`의 `SYNTHETIC`)는 지우지 않고 열로 남겨 질의에서 거른다.
- 날짜는 KST로 저장한다.

## 다음 단계

1. 사용자 승인. DB 위치(로컬 SQLite 권고)와 적재 주기를 정한다.
2. 이슈를 올리고 적재 스크립트와 시험을 만든다. 시험은 서버 로그 줄 수와 이벤트별 건수를 대조한다.
3. 배너 평가 문서 1, 2, 4장의 횟수와 비율을 DB로 다시 센다.
4. PostHog 중복 적재의 원인을 조사한다. 07-29~08-06은 원인을 모르고, 08-21~08-31은 직접 전송과 서버 중계의 겹침으로 짐작하지만 확인하지 않았다.

## 모르는 것

- PostHog 중복이 `offer_link_click` 말고 어떤 이벤트에 더 있는지 전수 확인하지 않았다.
- 08-21~09-28 PostHog의 화면 열림이 서버 로그보다 23% 많은 까닭을 찾지 못했다.
