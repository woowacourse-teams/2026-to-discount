# 화면 덤프 방식(dump_way) 기록 모음과 분업 (2026-11-11)

상위 이슈 [#248](https://github.com/nn98/delivery-discount-tracker/issues/248). **문서 지도:** 결과는 [경과 보고](2026-11-11-dump-way-progress.md), 가설과 실험은 [가설과 실험 대장](2026-11-11-dump-way-hypotheses.md), 지금 상태와 정리 목록은 이 문서 9절. 이 문서 6절은 01~06시 WSL 측정의 시간순 원본이고 최신 통합은 경과 보고다. 이 문서는 덤프 방식을 기존 `uiautomator dump`, 패치 u2, 자체 서버 fdump 중에서 고르는 일의 **목차**다. 여러 세션이 갈라 맡을 수 있게 기록, 분업 규칙, 작업 시작 방법을 한 곳에 모았다. 결과가 나올 때마다 5절과 6절을 고친다.

사실에는 출처를 붙이고, 확인하지 못한 것은 "추정"이나 "미확인"으로 적었다.

## 1. 한눈에 (01시 작성, 지금 상태는 9절에서 14:40 기준으로 갱신)

- **발단:** 4c(요기요 전수)가 V30(Android 9)에서 90분 상한에 반복해 끊김. V30의 `uiautomator dump`가 빈 트리를 자주 줘 한 동작에 평균 40초.
- **1차 조치:** 덤프를 uiautomator2(u2)로 바꿈(PR #244, 병합 `69576ce`). 덤프 한 번 7~29초가 0.3~0.7초로 줄었지만, 웹뷰 쿠폰함(배민 5단계, 요기요 5y)에서 u2가 노드를 덜 줘 실패했고 같은 날 19:30에 `adb`로 되돌림([#245](https://github.com/nn98/delivery-discount-tracker/issues/245)).
- **원인(실기와 바이트코드로 확정):** u2 서버가 접근성 플래그 65618(`FLAG_RETRIEVE_INTERACTIVE_WINDOWS` 포함)로 연결하면 웹뷰의 화면 밖 노드가 "안 보임"(`isVisibleToUser` 거짓)이 되고, u2 덤퍼가 안 보이는 자식을 하위 트리째 건너뛴다. 기존 덤프는 건너뛰지 않는다. 플래그를 끄거나(fdump, 65554) 건너뛰기 4바이트를 지우면(패치 u2) 같은 화면에서 기존 덤프와 같은 노드가 온다. 근거는 `docs/research/2026-11-10-u2-dump-parity.md` 4.6절과 인계 `4691ed`.
- **후보 셋:** 기존, 패치 u2(PR #246, `capture/fleet/u2_jar.py`), fdump(브랜치 `feat/fdump`). 비교 측정 18건(11-11 00:08~00:24)은 6절.
- **지금 상태:** 운영 변경 없음(폰 5대 `dump_way` 전부 `adb`). 예약 수집 `discount-after-open`은 11-11 00:06 사용자 지시로 **비활성화**(되돌리기 `Enable-ScheduledTask -TaskName discount-after-open`). 00:01 회차는 1단계에서 중지돼 결과 없음(`logs/state.json`이 `2026-11-11T0001`, 1단계 `run`, `done: False`로 남음). GitHub Actions(CI)는 **무료 사용량 초과로 동작하지 않는다**(사용자 확인 11-11, [#255](https://github.com/nn98/delivery-discount-tracker/issues/255)). `Tests`는 전부 3초 실패하므로 PR 점검은 로컬 전체 시험이 유일한 관문이고(PR #246 브랜치 2,316건 통과), 병합 뒤 Actions 자동화(`followup-issues` 등)도 안 돌 수 있어 후속 이슈는 손으로 만든다.

## 3. 분업 규칙

1. **폰:** 한 폰에 한 세션. 잡기 전에 자기 인계 파일에 `- 잡음: <폰> <시각>`을 적고, 놓을 때 `- 놓음: <폰> <시각>`과 함께 서버 0개, `dump_way` adb 복구를 확인한다. 수집 예약이 다시 켜지면 수집이 우선이고 예약 앞뒤 15분은 시험하지 않는다(`docs/workflow/HANDOFF.md`).
2. **파일 소유:** 2절 표의 소유 파일은 그 묶음만 고친다. 같은 파일을 고쳐야 하면 인계 파일에 요청을 남기고 소유자가 반영한다(`dumpers.py`는 묶음 2가 단독 소유).
3. **작업 폴더:** 저장소 밖 `<사용자 폴더>\_dev\wt-dumpway-<이름>`에 **Windows git**으로 만든다. 작업 폴더 연결 정보는 Windows 경로로 적히므로 WSL git에서는 어긋나 보인다(WSL git으로 보면 `prunable`, `git status` 실패, 11-10 `wt-fdump`에서 확인. Windows git에서는 정상). 그래서 만들 때도, git 명령을 쓸 때도 Windows git(PowerShell)을 쓴다. 예약 수집이 세는 폴더(tracker 안)에는 두지 않는다(`rules/git.md`).
4. **PR:** 기능 하나에 PR 하나. 병합은 사용자. CI가 불통이라 PR 본문에 로컬 전체 시험 결과를 적는다. 문서만 바꾸는 변경은 PR 없이 main(사용자 지시 11-04).
5. **비밀값, 개인정보:** 실험 XML(쿠폰함, 허브)은 저장소에 올리지 않는다. 스크립트와 결과 줄만 올린다.
6. **인계:** 읽은 줄은 `- 받음: <식별값>`으로 남긴다. 넘길 말에는 읽은 범위와 못 읽은 범위, 출처를 적는다.

### 환경 (측정, 시험을 돌리는 세션이 먼저 볼 것)

- **셸은 PowerShell(Windows git, Windows Python 3.14)**: 수집 PC 파이썬에 `uiautomator2==3.7.1`과 pytest가 있다. 측정은 WSL이 아니라 PowerShell에서 `python ...`으로 돈다. 폰 지정은 환경변수 `ADB_SERIAL` 또는 `--serial`.
- **폰을 잡는 시험은 `scripts\collect_trial.ps1 -Command "..."` 안에서 돌린다.** 예약 작업을 끄고 시험한 뒤 되돌리며, PC 공용 잠금(`%LOCALAPPDATA%\delivery-discount-tracker\collect_trial.lock`)으로 시험끼리 겹치지 않게 한다. **주의:** 예약이 이미 `Disabled`이면 `wasEnabled`가 거짓이라 끝에 다시 켜지 않는다. 그러나 앞 시험이 죽어 남은 **오래된 잠금 파일이 있으면** `$staleTrial`이 참이 되어 끝에 예약을 **다시 켠다**(사용자 홀드가 풀림). 시작 전에 잠금 파일이 없는지 확인한다(11-11 02시 기준 없음, 예약 `Disabled`).
- **작업 폴더:** 측정 묶음(#249)용 `<사용자 폴더>\_dev\wt-dumpway-measure`(브랜치 `feat/dumpway-measure` = `origin/feat/fdump` + `origin/fix/u2-webview-fallback`, 원격에 올림). 다른 묶음이 두 후보 코드가 필요하면 이 브랜치에서 갈라낸다.
- **fdump 소스와 jar:** 브랜치 `feat/fdump`의 `capture/fleet/fdump_src/`(`FDump.java`, `fdump.jar`, 빌드 `README.md`). 폰에는 `fdump.py`가 jar가 다르면 올린다.
- **시험:** 이 브랜치에서 `tests/test_fleet_dumpers.py`, `tests/test_fleet_fdump.py` 13건 통과(11-11 02시). 전체 시험 `pytest tests -m 'not ci_only and not non_gate'`(약 10분, CI 불통이라 이것이 관문).
- **가짜 날짜:** 단계 스크립트를 시험으로 돌릴 때는 `2099-…` 날짜로 저장하고 끝나면 지운다. 같은 폰, 같은 날짜를 여러 스레드가 쓰지 않는다(11-11 측정의 경합 원인 추정).
- **11-11 00시 이전에는 시험을 `collect_trial` 밖에서 돌렸다**(WSL 세션 실험 대부분). 이후 측정은 안에서 돌린다.

### 작업 시작 (예)

```powershell
cd <사용자 폴더>\_dev\delivery-discount-tracker
git fetch origin
# 묶음 1(측정): 두 후보 코드가 다 필요하다
git worktree add <사용자 폴더>\_dev\wt-dumpway-measure -b feat/dumpway-measure origin/feat/fdump
cd <사용자 폴더>\_dev\wt-dumpway-measure
git merge origin/fix/u2-webview-fallback
# 그 밖의 묶음(기준 origin/main)
git worktree add <사용자 폴더>\_dev\wt-dumpway-tidy -b chore/dumpway-tidy origin/main
```

푸시는 `git push`로 시작하는 단독 명령으로 한다(허용 규칙이 맞아야 함). 커밋은 파일 이름으로 담고(`git commit -F <메시지> -- <파일들>`) 작성자는 사용자다(`rules/git.md`).

## 5. 확정, 추정, 모르는 것

**확정(실기):**
- u2 서버는 `visible-to-user=true` 노드만 준다. 배민 쿠폰함에서 원본 u2 91노드, 기존 260노드, 빠진 노드의 대부분이 화면 밖 또는 크기 0이고 쿠폰 글자가 거기 있다.
- 건너뛰기 분기(`dumpNodeRec` 바이트코드 오프셋 372의 `if-eqz`)를 지우면 u2가 기존과 노드 402 = 402, 글자 142 = 142.
- fdump(플래그 65554, 가시성 필터는 유지)도 같은 화면에서 기존과 같다(main 실측). 즉 "플래그가 가시성을 바꾸고 u2 필터가 잘라낸다"가 두 실측을 설명한다.

- 딥링크에서 패치 u2는 덤프 중앙값이 3~4초이고 물러섬이 실행마다 1회다: 덤프가 2~3번뿐이고 그중 웹뷰가 막 뜬 첫 덤프가 기존으로 물러서서 중앙값이 기존 속도가 된다. 단계 시간은 fdump 9~12초, 기존 14초, 패치 u2 16~18초 순.
