# 덤프 방식 선택 경과 보고 (2026-11-11 12시 기준)

상위 이슈 [#248](https://github.com/nn98/delivery-discount-tracker/issues/248). **문서 지도:** 결과는 이 문서, 가설과 실험 상태는 [가설과 실험 대장](2026-11-11-dump-way-hypotheses.md), 목차와 분업은 [색인](2026-11-11-dump-way-index.md). 목차와 분업 규칙은 [`2026-11-11-dump-way-index.md`](2026-11-11-dump-way-index.md), 원인 분석은 [`2026-11-10-u2-dump-parity.md`](2026-11-10-u2-dump-parity.md). 이 문서는 **지금까지 무엇을 알아냈고, 후보가 어떻게 견줘졌고, 무엇이 안 풀렸고, 무엇을 결정해야 하는지**를 한 번에 읽도록 모은 것이다. WSL, sub, main 세션의 결과를 합쳤다. 사실에는 출처를 붙이고, 확인하지 못한 것은 "추정"으로 적었다.

## 1. 한 줄 결론

- **원인은 풀렸다.** u2가 웹뷰 쿠폰 카드를 못 읽은 것은 u2 서버의 접근성 플래그와 "안 보이는 자식 건너뛰기" 때문이고, 기존 `uiautomator dump`가 V30, V50의 움직이는 요기요 홈에서 안 끝나는 것은 idle을 기다리기 때문이다.
- **후보 둘(패치 u2, fdump)은 노트20과 V50의 쿠폰함, 브랜드관, 허브에서 기존과 같은 결과를 낸다.** 단계 시간은 fdump가 기존의 0.4~0.74배, 패치 u2가 0.53~0.95배(4a에서 가장 작은 이득)이고 fdump는 물러섬이 없다.
- **딥링크로 쿠폰함에 바로 들어가면 홈을 건너뛰어 실패 자리가 사라진다**(검증 통과). 세 앱 모두 쿠폰함 딥링크가 있다.
- **fdump는 V30에서 4c(요기요 전수)가 무너졌다**(전수수집 시험). V30의 4a, 4c는 아직 후보를 못 정했다.
- **운영은 그대로다.** 폰 5대 `dump_way`는 모두 `adb`, 예약 수집 `discount-after-open`은 사용자 지시(11-11 00:06)로 비활성화, PR #246 미병합, GitHub Actions(CI)는 무료 사용량 초과로 불통([#255](https://github.com/nn98/delivery-discount-tracker/issues/255)).

## 3. 확정한 사실

1. **u2 웹뷰 누락의 원인.** u2 서버가 접근성 플래그 65618(`FLAG_RETRIEVE_INTERACTIVE_WINDOWS` 포함)로 연결하면 웹뷰의 화면 밖 노드가 "안 보임"이 되고, u2 덤퍼가 안 보이는 자식을 하위 트리째 건너뛴다. 플래그를 끄거나(fdump 65554) 건너뛰기 4바이트를 지우면(패치 u2) 같은 화면에서 노드, 글자가 기존 덤프와 같다. 근거: 바이트코드와 같은 화면 대조, 상세는 `2026-11-10-u2-dump-parity.md` 4.6절.
2. **u2 덤퍼는 이모지를 `..`로 바꾼다**(서로게이트 치환). 패치 2번이 지운다. fdump는 해당 없음.
3. **V50, V30의 기존 덤프 실패는 "움직이는 요기요 홈"에서만 난다.** V50 5y 기존이 홈 경로 8회 중 4번 454~473초 뒤 빈 트리로 실패(00:2x, 01:57, 02:08, 05:3x). 같은 V50에서 딥링크로 쿠폰함에 들어가면 기존 덤프가 2.8초에 정상이고 3/3 성공이며 세 후보 모두 9/9다. 증거 화면은 켜져 있고 홈이 정상 표시(`yogiyo_home-20261111-020825.png`).
4. **딥링크 진입은 결과가 같고 훨씬 빠르다.** 요기요 5y 결과 JSON 해시가 홈 경로와 딥링크에서 같다(쿠폰 52장). 아래 4.4절.
5. **쿠폰함 딥링크는 세 앱 모두 있다**(sub 실기, #256): 요기요 `yogiyolink://move.page/my_yogiyo/coupon`, 배민 `baemin://./couponbox`, 쿠팡이츠 `coupangeats://PromotionCode`(`CouponManagementActivity`). 과거 기록("쿠폰함은 딥링크가 없다", 2026-09-12)은 틀린 문장이 되어 정정했다(`768ae2f`).
6. **GitHub Actions가 죽어 있다**(무료 사용량 초과). PR 점검은 로컬 전체 시험이 유일한 관문이다.

## 6. 풀리지 않은 것

- **V30 fdump 4c, 4a.** 4c는 빈 트리 43%로 5곳만 읽음, 4a는 후보와 상관없이 딥링크 도달 실패가 누적. 앱보다 먼저 서버를 띄우는 순서(#250)가 해결하는지는 아직 안 쟀다.
- **4a가 몇 시간 연속 뒤 무너지는 이유.** 덤프 방식과 무관해 보이나 순서를 뒤집은 재측정, 재부팅 뒤 재측정이 없다(#249).
- **A8 fdump의 단계가 기존보다 길다.** 덤프가 빨라 폴링이 늘어난 것으로 보인다(#253).
- **패치 u2 물러섬의 줄이기.** `check_complete`가 "웹뷰가 막 뜬 순간"을 실패로 보는 조건을 재시도로 흡수할지(#250, #245).
- **V50 홈 경로의 간헐 실패 원인**(시각, 앞 단계). 딥링크가 우회하지만 홈을 거치는 단계(2, 3w 등)는 남는다.
- **딥링크 착지 화면 팝업.** 확인하려면 팝업이 뜨는 날의 측정이 필요하다.
- 전수수집 시험 3단계 판정기 FAIL과 배민 4a 확인 불가 증가는 4.7절에서 풀렸다(fdump 종료 예외 오판, 가게 없음 23곳).
- **요기요 4c가 V30 밖(V50, adb)에서도 적게 읽힌 이유**(4.7절). 오늘 할인 탭 브랜드 수와 목록 판독 중 어느 쪽인지.
- **쿠팡이츠 쿠폰함 5a 결과 동일**은 계정 상태가 변해 못 쟀다.

## 7. 잠정 의견 (결정은 #252, 사람)

1. **쿠폰함 단계(5, 5a, 5y): 딥링크 진입 + fdump**가 가장 빠르고(요기요 5y 9~12초) 실패 자리를 없앤다. 기존 덤프도 딥링크에서는 노트20, V50에서 성공한다.
2. **4a, 허브: fdump**가 단계 시간 0.67~0.74배로 가장 좋고 결과가 같다. 패치 u2는 물러섬 때문에 이득이 작다.
3. **V30: 5y, 5는 fdump로 풀린다. 4a, 4c는 fdump를 쓰지 않는다**(병합본으로도 4c 실패 확인). 4c는 패치 u2(11-10 40곳 읽힘)나 다른 폰이 후보.
4. **A8: 기존 유지**(u2는 사실상 기존, fdump는 단계가 더 김). **G6: fdump 소폭 이득.**
5. 패치 u2는 후보로 코드에 남기되 fdump가 정해지면 쓰이지 않는 코드가 된다. PR #246은 운영 동작을 바꾸지 않아 병합 위험이 낮지만 CI가 없어 로컬 시험 결과가 근거다.
