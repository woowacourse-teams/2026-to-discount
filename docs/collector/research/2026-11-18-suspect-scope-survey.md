# 원장 반영을 막는 SUSPECT의 범위 조사 (이슈 #117)

5b 말고도 SUSPECT 하나로 출처 전체를 원장 반영에서 빼는 단계가 있는지, 그 사유를 브랜드 단위로 좁혀도 되는지 본다. 5b는 #103(PR #109)이 이미 브랜드 단위 부분 반영(`partial_ok`)을 넣었다.

읽은 파일(2026-11-18, origin/main 3891527d): `scripts/reflect_daily.py`(`sources`, `partial_check`, `main`), `scripts/check_routine.py`(단계 2, 3, 4, 5, 5b, 5y), `scripts/build_couponbox_records.py`, `scripts/baemin_couponbox_daily.py`, `capture/coupangeats_hub.py`(`[suspect] 3` 줄), `docs/setup/CROSS-CHECK-VERDICTS.md`, `docs/setup/ROUTINE-SPEC.md` §2. 실측은 `logs/steps/2026-10-*/8.log`, `logs/steps/2026-11-*/8.log`의 판정 줄을 셌다.

읽지 않은 것: 6, 7단계(배너)는 원장 반영을 막지 않아 뺐다. 4a~4g 하위 단계의 개별 판정기는 4단계 묶음으로만 봤다.

## 1. 어느 판정이 반영을 막나

`reflect_daily.sources`가 출처마다 근거 단계 판정을 본다. 막는 조건은 단계마다 다르다.

| 출처 | 근거 단계 | SUSPECT일 때 | 근거 |
|---|---|---|---|
| 배민 배짱할인 | 2 | 출처 전체 건너뜀 | `verdicts.get("2") == "PASS"`일 때만 읽음 |
| 배민 쿠폰함 | 5 | 출처 전체 건너뜀 | `verdicts.get("5") == "PASS"`일 때만 빌드 |
| 쿠팡이츠 허브 고정 쿠폰, 쿠팡이츠 행사 | 3 | 두 출처 모두 건너뜀 | `verdicts.get("3") == "PASS"`일 때만 허브 파일을 읽고 `split_ce_events`로 가름 |
| 쿠팡이츠 쿠폰함 | 5b | 사유가 허용 목록과 상한 안이면 부분 반영 | `partial_ok`(이슈 #103) |
| 요기요 쿠폰함 | 5y | 막지 않음 | PASS와 SUSPECT를 같이 받음 |
| 전수조사(배민 브랜드관, 땡겨요, 요기요) | 4 | 막지 않음 | 판정과 상관없이 `audit_records(day)` |

그러니 조사 대상은 단계 2, 3, 5다.

## 2. 단계별 사유와 판정

"좁혀도 됨"은 사유가 특정 브랜드 행을 가리키고, 그 행을 빼면 나머지 행이 검증된 관측이라는 뜻이다. 판단 근거는 로그 문구가 아니라 빌더가 이미 행을 뺐는지, 사유가 어느 행에 걸리는지다.

| 단계 | 사유(판정기 분기) | 범위 | 판정 | 이유 |
|---|---|---|---|---|
| 2 | 브랜드 0곳 | 전체 | 안 됨 | 화면을 못 읽은 것과 구분이 안 된다 |
| 2 | 지난 수집보다 브랜드 급감(`drop_message`) | 전체 | 안 됨 | 어느 브랜드가 빠졌는지가 아니라 목록을 다 읽었는지가 의심이다. 남은 행만 넣으면 빠진 브랜드가 "안 보였다"가 된다 |
| 3 | 고정 쿠폰 0곳 | 전체 | 안 됨 | 같음 |
| 3 | 고정과 선착순 합이 10장 미만 | 전체 | 안 됨 | 목록을 덜 읽었다는 의심이다 |
| 3 | `[suspect] 3 행사 머리줄 … 같은 브랜드로 못 읽었다`(`coupangeats_hub.py`) | 행사 카드 한 장 | **좁혀도 됨(행사 출처로)** | 행사 머리줄 판독 문제라 고정 쿠폰 행과 무관하다. 지금은 고정 쿠폰 수십 행까지 같이 빠진다 |
| 3 | `[suspect] 3 릴레이 … 여는 시각을 못 읽었다`, `… 같은 시각을 받았다` | 선착순 카드 | **좁혀도 됨(선착순 행으로)** | 여는 시각은 선착순 행의 배지에만 쓰인다. 고정 쿠폰 행과 무관하다 |
| 3 | 시간 지연(`[suspect] 3 시간 지연`, #159 이전 형식) | 전체 | 해당 없음 | #159 뒤로는 근거 칸에만 붙고 판정을 안 바꾼다(`_SLOW_RE`) |
| 5 | 보유쿠폰 0장 | 전체 | 안 됨 | 판독이 깨진 쪽이다 |
| 5 | `[suspect] 5 쿠폰함 뒷면을 못 읽은 쿠폰 N장`(`baemin_couponbox_daily.py`) | 쿠폰 몇 장 | **좁혀도 됨** | 빌더(`build_couponbox_records.build`)가 뒷면을 못 읽은 쿠폰을 이미 뺀다(`[suspect] 5 뒷면을 못 읽은 쿠폰이라 뺐다`). 남은 행은 뒷면까지 읽은 관측인데, 지금은 이 사유 하나로 배민 쿠폰함 전체가 그날 반영되지 않는다 |

## 3. 실측 빈도

8단계 판정 줄(`logs/steps/<날짜>/8.log`, 단계별 로그가 남기 시작한 날부터 11-18까지):

| 단계 | SUSPECT 횟수 | 사유 |
|---|---|---|
| 2 | 8 | 브랜드 0곳 3, 급감 5 — 전부 "안 됨" 사유 |
| 3 | 2 | 고정 쿠폰 0곳(10-19), 시간 지연(11-04, #159 이전) |
| 5 | 0 | `[suspect] 5`는 11-15에 생겨 아직 판정 줄로 나온 적 없음 |
| 5b | 7 | 이미 부분 반영 대상(#103) |

통합 로그(`logs/after-open-<날짜>.log`)에서 `[suspect] 3 릴레이`가 판정을 SUSPECT로 만든 날은 10-01, 10-02 두 번이다. 두 날 모두 `쿠팡이츠 허브 고정 쿠폰: 건너뜀(단계 3 = SUSPECT)`으로 고정 쿠폰 출처가 통째로 빠졌다. 사유는 릴레이 선착순 카드의 여는 시각(BHC, 배스킨라빈스, 스타벅스)이라 고정 쿠폰 행과 무관했다. 그 뒤로는 같은 사유가 판정을 바꾼 기록이 없다.

## 4. 후속 설계 제안

1. **배민 쿠폰함 `[suspect] 5`를 부분 반영으로**(#407): 빌더가 뺀 쿠폰 말고는 반영. 뺀 쿠폰은 보고서 "보류한 브랜드" 절에 이름으로 남긴다. 상한은 5b와 같은 방식(장 수와 몫)으로 둔다. 가장 작은 변경이고, 11-15 훌랄라 14,100원 같은 날 배민 쿠폰함 전체가 하루 빠지는 것을 막는다.
2. **단계 3의 행사, 선착순 사유를 행사 출처로만 좁히기**: `[suspect] 3`의 종류를 빌더가 구조 값(사유 코드)으로 남기게 하고, `reflect_daily`가 그 코드가 행사나 선착순일 때 허브 고정 쿠폰 출처는 연다. 10-01, 10-02에 실제로 고정 쿠폰이 통째로 빠졌다. 그 뒤로는 재발이 없어 1번보다 뒤다.

단계 2와 단계 3의 0곳, 급감, 10장 미만 사유는 목록을 다 읽었는지에 대한 의심이라 좁히지 않는다.
