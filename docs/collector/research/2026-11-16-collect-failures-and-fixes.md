## 2. 빠른 덤프(fdump)를 적극 쓴다

같은 일을 기존 덤프(adb uiautomator)와 fdump로 맞대 본 결과, 결과가 같으면 fdump가 2배 넘게 빠르다. 단계별 덤프 방식은 측정 저장소(`%LOCALAPPDATA%\delivery-discount-tracker\fleet\device_traits.json`의 `dump_way_steps`)가 정하고, 실제 쓴 방식과 물러섬은 단계 로그 `[덤프]` 줄과 `logs/dumps`의 `way` 칸에 남는다(#332).

| 비교 | adb | fdump | 결과 |
|---|---|---|---|
| 노트20 3b 24곳(11-16 19:5x) | 2,036초 | 946초 | 상태 23/24 같음, 다른 1곳은 떡참이 찾아짐, 쿠폰 같음 |
| 노트20 3b 롯데슈퍼 1곳 | 82초 | 54초 | 쿠폰 2장 같음(fdump 첫 시도 0장 → 빈 시트 다시 읽기 추가) |

새 단계를 만들거나 단계를 다른 폰에 넘길 때는 그 단계의 fdump 칸부터 잰다. 3b는 11-13에 생겨 측정표(11-12)에 빠져 있었고 그래서 adb로 돌았다.

## 3. 원인별 과정

### 3-1. 4c 시간 초과
- 끊긴 회차를 폰별로 세니 모두 V30이었다(logs/dumps 4c: V30 중앙 7초, 노트20 2.7초, V50·A8·G6 3초 안팎).
- A8, G6 실측: 45곳 기준 A8 38분, G6 47분. 수정 뒤 15:55 손 회차는 V50이 43곳 30분, 판독 실패 0.
- 상한은 90분으로 되돌리고, 끊겨도 읽은 곳을 남겨 이어 읽는 장치는 예비로 남겼다(#328).

### 3-2. 4c 덜 읽음
- 처음엔 "같은 계정을 두 폰이 동시에 써서"로 짐작했다. 틀렸다.
- 덤프 기록에서 같은 화면이 15번(탭 안 먹음), 4번(밀기 안 먹음) 이어진 것을 보고, 증거 트리에서 내비바 "홈"이 `[0,0][0,0]`인 것을 찾았다.
- 수정 뒤 A8 실기: 창원 4 → 9, 솔데스크 0 → 16, 집 0 → 4(08:30 V30 9, 12, 5).

### 3-3. 8단계 업로드 거부
- 배포 가드가 "서버 상세가 사라진다"로 막았다. 앱 화면(16:14 캡처)에 기본 1,000원 할인이 실제로 없어진 것을 보고, 구간을 잃는 코드 갈래(`build_yogiyo`의 쿠폰만 갈래)를 고친 뒤 두 곳만 손실 허용으로 올렸다.

### 3-4. 3w G6
- 처음엔 "메모리 부족"으로 짐작했다. 틀렸다. 허브에서 직접 덤프하니 여유 메모리 1.5GB인데 2초 만에 137.
- fdump로 허브를 따로 뜨면 229노드, 허브 표지, 카드 글자가 다 나온다. 그런데 3w 흐름 안에서는 fdump가 빈 트리만 준다(빈 트리면 서버를 다시 띄워도 같음). 원인 미확정.
- 한 번은 G6 화면이 꺼진 채로 덤프해 "빈 트리"를 원인으로 오인할 뻔했다. 폰 시험 전에 화면부터 깨운다(`scripts/wake_phones.py`).

### 3-5. 3b 이름 비교
- 노트20 허브를 내리며 화면마다 찍어 보니 노드 글자는 `떡참 떡볶이&치킨`, 카드 판독은 `떡참 떡볶이&amp;치킨`(옛 정규식 키와 맞추려고 일부러 원문 꼴로 되돌림).
- 이름 정규화 함수(`coupangeats_hub._same_brand`)가 이미 있었는데 매장 혜택만 `==`를 썼다. 같은 실패가 세 번 되풀이됐다.
- `same_brand` 규칙: 접기(이스케이프, 전각, 띄어쓰기, 대소문자) → brands.yml 별칭 → 끝 범용어(치킨, 피자)를 뗀 이름이 화면에 하나뿐. 앞부분만 같은 건 다른 가게. 이마트와 이마트에브리데이는 별칭표로 같은 가게(이마트 카드를 누르면 이마트에브리데이 매장이 뜬다).

### 3-6. 3b 건너뛰기
- 옛 규칙(어제·오늘 상태 파일 둘 다 매장 없음)은 그날 첫 3b(15:55)에 오늘 파일이 없어 늘 0곳이었다. 최근 두 기록으로 바꾸면 11-16에 9곳을 건너뛰고, 9곳 다 그날도 매장 없음이었다.
- 상태 파일은 폰을 가리지 않는다. 폰마다 배달 주소가 달라(나눠 읽으려고 일부러 다르게 둔 것) 보이는 매장이 다르다. 그래서 건너뛰기 기록을 폰별 파일(`captures/skip_ce_store_<시리얼>.json`)로 떼고, 규칙은 `capture/skip_policy.py`에 모았다.
- 월요일(새 주 허브), 매월 1일(월간쿠폰), 00:01(전부 읽기)은 건너뛰지 않는다.

## 4. 이 날의 판단 실수

- 원인을 확인하기 전에 추정으로 말했다(메모리 부족, 동시 계정 사용). 덤프 기록과 증거 트리를 먼저 봤으면 바로 나왔다.
- V50과 노트20의 3b 결과 차이를 "주소를 맞춰야 한다"로 읽었다. 두 폰 주소가 다른 것은 나눠 읽기 위한 설정이고, 그 차이가 곧 V50이 따로 읽어야 할 매장이다.
- 기존 정규화 함수를 찾지 않고 새로 고치려 했다. 고치기 전에 같은 일을 하는 코드를 먼저 찾는다(`claude-harness/tools/find_prior.py`).
