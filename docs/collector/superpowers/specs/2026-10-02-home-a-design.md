# 메인 화면 A안 — 가장 큰 할인·새 할인·행사를 먼저 보이는 모바일 홈 (설계)

- 날짜: 2026-10-02
- 상태: 16차로 확정(2026-10-03). 구현 계획 1단계: `docs/superpowers/plans/2026-10-03-home-a-coupon-card.md`
- 시안: https://claude.ai/artifact/MXz9WKkejx7qHek7bM2vGn (레퍼런스 6장, 지금 화면 대비 A안 첫 방문·재방문, 같은 틀의 B·C안)
- 관련: `mono/web/src/variant.js`(9월 A/B 실험 흔적), `docs/HANDOFF-20260914.md` §4(9월 실험 결론), 배너 분석 보고서 https://claude.ai/artifact/CTwm3UjH4TcYymxQ1YZnW7

## 1. 무엇을 왜

사용자가 배거스에 오는 이유는 하나다 — **지금 가장 크고, 새로 생긴 할인을 빨리 찾아 배달앱으로 가는 것.**
지금 홈은 그 일을 잘 못 한다(2026-10-02 390px 실측):

- 브랜드 카드가 앱별 할인·조건을 처음부터 다 펼친다. 피자헛 한 곳이 약 900px — 첫 화면에 브랜드가 한 곳도 다 안 들어온다.
- "새로 생긴 할인"을 알려 주는 자리가 없다. 다시 온 사람이 무엇이 바뀌었는지 모른다.
- 행사 배너가 캐러셀 한 칸(약 100px)을 늘 차지한다. 배너 분석에서 묶음 배너 클릭률 1.09%(단독 2.13%), 자사 행사 0.62%.
- 390px에서 금액 열과 분류 탭이 화면 밖으로 넘친다(헤드리스 캡처, 실기 확인 필요).

## 2. 사용자 결정(이 대화, 2026-10-02)

| 질문 | 결정 |
|---|---|
| 승패 지표 | 핵심: 오퍼 클릭률·배너 클릭률·리텐션. 보조: 체류·탐색·첫 클릭까지 걸린 시간·탐색 깊이. 리텐션은 이미 쌓인 추이를 기준선으로 쓴다 |
| "새 할인" | 첫 방문은 오늘 새로 생긴 할인, 재방문은 마지막 방문 뒤 새로 생긴 할인 |
| 정렬 | 기본 할인금액 높은순. 사용자가 바꿀 수 있다. 정렬 기준은 갈아 끼우는 자리 하나로(인기순·실시간 순위 대비) |
| 방향 | A안(요약 + 목록). B·C는 재활용 목록으로 남긴다 |
| 원칙 | 지금 UI·부품을 최대한 유지, 덜어내고 접는다, 모바일 기준, 점진·순차 리팩터링 |

## 3. 레퍼런스에서 가져온 것

| 화면 | 가져온 점 |
|---|---|
| 요기요 홈 | 숫자 하나를 크게(최대 9,000원), 나머지는 작게. 하단 타이머 띠로 "지금만" |
| 쿠팡이츠 홈 | 맨 위에 혜택 한 장만 크게 — 그 아래는 탐색. 혜택과 탐색을 위아래로 가른다 |
| 쿠팡이츠 페스티벌 | 시각 머리표 → 큰 카드 1장 → 작은 카드. 선착순은 시각이 금액보다 먼저 |
| 땡겨요 브랜드쿠폰 | 카드 한 장 = 금액 한 줄 + 최소주문 한 줄 + 채널 띠. 펼침 없이 다 읽힌다 |
| 요기요 브랜드 | 최대 금액 → 추가할인 → 쿠폰. 겹치는 할인은 합계를 먼저, 구성은 아래 |

공통 원칙: **숫자 하나를 크게 → 그다음 탐색 → 카드는 펼치지 않고도 금액·최소주문·채널이 읽힌다.**

## 4. 화면 구성 — 2차: 시선 집중안(2026-10-02 개정, 이 절이 아래 1차 표를 대신한다)

사용자 피드백: "활용하라는 건 구조가 아니라 에셋과 요소다. 앱 아이콘 → 상단 메뉴 → 분류 바 → 배너 → 정렬을 지나야 브랜드 카드가 나오고, 카드 안에도 요소가 많다. 1차 A안도 여전히 분산된다."
그래서 1차의 '가장 큰 할인 1장'·'새 할인 띠'는 뺐다(그 자체가 새 요소다). 첫 금액 앞 요소를 **18개 → 6개**로 줄인다.

| 지금 요소 | 집중안 | 근거 |
|---|---|---|
| 상단 앱 아이콘 4 + 체크 | 거르기 시트로. 각 줄에 그 할인의 앱 아이콘 하나만 | 아이콘이 '거르기'와 '출처'를 겸해 첫 줄에서 눈을 끈다 |
| 메뉴 아이콘 3(알림·홈·필터) | 검색 + "거르기" 버튼 하나. 알림은 푸터로 | 첫 화면에서 쓰는 건 검색과 거르기뿐 |
| 분류 바 8칸 | 거르기 시트로. 켜지면 버튼에 글자로("피자 · 앱 3") | 9월 실험 "감추면 못 본다". 390px 넘침도 사라진다 |
| 배너 캐러셀 | 목록 4번째 자리에 행사 한 줄(브랜드 줄과 같은 꼴, 노란 바탕) | 묶음 1.09%, 자사 0.62% |
| 정렬 알약 2 | 제목 옆 "금액순 ▾" 글자 하나 | 인기순·실시간은 이 목록에 더한다 |
| 브랜드 카드(최고 테두리·나머지 칩·앱별 상세·접기) | 한 줄: 로고·이름·최고 앱과 조건·금액, 다른 앱은 작은 한 줄. 누르면 그 자리 펼침 + "최고 앱에서 열기" | 한 브랜드 약 900px → 약 64px, 첫 화면 브랜드 1 → 8 |
| 와우·랜덤·N%할인 배지 | 조건 글자 안 | 색 표식은 새로·선착순·행사 셋만 |

- **바로가기(3차, 사용자 지적: 신속성이 핵심인데 펼침으로 깊이가 한 칸 늘었다):** 각 줄 오른쪽에 금액 버튼(최고 앱 아이콘 + 금액 + ›)을 둔다. 누르면 지금처럼 한 번에 그 앱으로 간다. 줄 몸통을 누르면 펼침(2등 앱이 필요할 때만). 펼친 칸의 앱별 줄도 각각 바로 그 앱으로 간다. 줄은 키운다(로고 48px, 줄 약 80px, 첫 화면 브랜드 약 6곳) — 밀집감을 줄인다. 이벤트: 금액 버튼은 기존 `offer_link_click`에 `from: 'row'`, 펼침 안은 `from: 'expanded'`.
- **줄 모양(4차, 이 항목이 위 3차의 줄 배치를 대신한다):** 위는 로고(56px)와 이름·표식, 아래는 최고 오퍼 버튼(앱 아이콘 28px + 금액 26px + "땡겨요 열기 ›", 옅은 바탕 + 1px 테두리, 줄 폭 가득). 차선 오퍼(앱 아이콘 + 금액)는 로고 밑에 작게 세로로. 조건(채널·최소주문·선착순 시각 외 문구)은 기본으로 숨긴다. 로고·이름을 누르면 펼침: 최고 오퍼 조건 한 줄 + **지금 운영 카드의 앱별 할인/조건 구간**(금액·포장/배달·최소주문)과 앱마다 "열기" 버튼. 펼친 줄은 왼쪽 굵은 선, 최고 버튼은 진하게 반전.
- **줄 모양(5차, 4차 배치를 대신한다):** 왼쪽에 큰 로고(76px, 두 줄 높이). 로고 오른쪽 위에 브랜드 이름(18px 굵게). 그 아래 한 줄에 — 로고 높이에 맞춘 차선 오퍼 목록(앱 아이콘 15px + 금액, 세로) → 남은 폭 전부를 최고 오퍼 버튼(앱 아이콘 + 금액 24px + ›)이 채운다. 차선이 없으면 버튼이 그 폭까지 넓어진다. 한 브랜드 약 90px, 첫 화면 브랜드 약 5곳 + 행사 한 줄. 펼침은 4차와 같다.
- **줄 모양(6차, 5차를 대신한다):** 왼쪽 세로 열 = 큰 로고(76px) + 그 밑에 차선 오퍼 세로 목록(앱 아이콘 + 금액, 많을수록 줄이 아래로 길어진다). 오른쪽 = 맨 위 브랜드 이름(18px 굵게), 그 아래 남은 공간 전부를 최고 오퍼 버튼이 채운다(최소 56px, 차선이 많으면 같이 길어진다).
- **오퍼 크기·내용(7차):** 최고 오퍼 버튼을 줄인다(금액 19px, 앱 아이콘 20px, 높이 약 52px, 남는 세로 공간을 억지로 채우지 않는다). 버튼에 최소주문 한 줄("24,000원 이상", 없으면 "최소주문 없음")을 넣는다. 오퍼는 모두 가운데 정렬 — 최고 버튼 안의 금액·최소주문, 로고 밑 차선 목록 모두.
- **운영 요소 되살림(8차):** 지금 운영 카드처럼 최고 오퍼 버튼 오른쪽에 앱 로고(34px)를 둔다(› 대신, 누를 곳임을 겸한다). 선착순 시각("11시 오픈", 노랑)·멤버십("쿠팡와우" 검정, "배민클럽" 민트)은 버튼 위 모서리에 살짝 기운 포스트잇 배지로 붙인다 — 지금 운영의 배지 에셋과 색을 그대로 쓴다. 이름 옆에는 "새로"만 남긴다.
- **읽을 글 줄이기(9차, 2026-10-03, 8차의 버튼 안 구성을 대신한다):** 시안 https://claude.ai/artifact/Lec9gdjZAZoUJW4y73C9Ag
  - 표식 "새로"는 `New`로 쓴다.
  - 최고 오퍼 칸에는 값만 둔다: 앱 아이콘, 금액, 최소주문(위쪽 화살표 아이콘 + 금액, 예: ↑18,900). 0이면 "최소주문 없음", 모르면 "최소주문 ?".
  - 선착순 시각(시계 아이콘 + "11시")과 멤버십(쿠팡와우, 배민클럽) 같은 문구는 버튼에서 빼서 브랜드 이름 아래 한 줄로 옮긴다. 배지 색은 운영 그대로다.
  - 누를 곳은 따로 둔다: 최고 오퍼 칸 오른쪽에 알맞은 크기의 버튼. 문구는 "주문하러 가기"와 "앱에서 보기"를 견준다(시안 A·B).
  - 펼친 화면에는 "열기" 글자를 쓰지 않는다. 앱별 칸 전체에 눌리는 버튼 질감(아래 테두리 두께, 눌렀을 때 살짝 들어감)을 주고 그 칸 전체가 그 앱으로 간다.
  - 원칙: 글보다 아이콘과 그림. 시선을 흩뜨리는 요소를 더하지 않는다. 시안은 `redesign-existing-projects`, `minimalist-ui` 스킬 규칙(1px 테두리, 모서리 12px 이하, 짙은 그림자 없음, 이모지 없음)으로 만들었다.
- **쿠폰 티켓(10차, 2026-10-03, 9차의 최고 오퍼 칸과 별도 버튼을 대신한다):** 같은 시안 2판.
  - 최고 오퍼는 버튼처럼 꾸미지 않고 쿠폰 티켓 모양으로 정보와 누를 곳을 하나로 묶는다. 왼쪽에 앱 아이콘, 금액, 최소주문(↑), 절취선 오른쪽 꼭지에 이동 아이콘(↗). 내려받기 아이콘은 쓰지 않는다. 티켓 전체가 그 앱으로 가는 링크다.
  - New, 선착순 시각, 멤버십 배지는 브랜드 이름 **옆**에 붙인다.
  - 로고 두 안을 견준다: A 정사각 로고(왼쪽 열, 밑에 다른 앱 금액), B 배너형 로고(카드 위 가로 띠, 다른 앱 금액은 이름 아래 한 줄).
  - 펼친 화면의 앱별 칸 오른쪽 표시도 같은 이동 아이콘(↗)으로 맞춘다.
- **확정 쪽 정리(11차, 2026-10-03):** 같은 시안 3판.
  - 로고는 정사각(A안). 배너형은 버린다.
  - 배지는 이름 옆에 붙이고, 길면 다음 줄로 넘어간다.
  - 티켓은 이미지 없이 CSS 마스크로 절취 홈을 판다. 점선 절취선, 짙은 꼭지가 이동 버튼(↗). 카드당 요소를 늘리지 않는다(지연 로딩 뒤 총 차단 시간 1.5초를 지킨다).
  - **같은 금액 오퍼:** 지금 운영 카드의 규칙(동점이면 하나를 골라 올리지 않는다, 거짓 우열 금지)을 그대로 따른다. 티켓 왼쪽에 금액을 한 번 쓰고 "같은 금액"을 적는다. 오른쪽 꼭지는 앱마다 한 줄(앱 아이콘, 최소주문, ↗)로 나눠 각자 그 앱으로 간다. 줄 순서는 최소주문이 낮은 쪽부터, 모르는 값은 뒤로. 2026-10-03 데이터에서 8곳이 해당한다(도미노피자, 보스피자, 꾸브라꼬숯불치킨 셋 등).
- **배지와 로고 바탕(12차, 2026-10-03):** 같은 시안 4판.
  - 로고 칸 바탕은 늘 흰색이다. 투명 배경 로고가 다크 모드에서 안 보이던 것을 막는다.
  - 같은 금액 티켓에 "같은 금액" 글자를 쓰지 않는다. 금액은 한 번, 앱마다 한 줄이다.
  - 같은 금액 앱들의 배지(선착순 시각, 멤버십, 최적)가 모두 같으면 절취부 오른쪽 위에 지금 운영 화면처럼 살짝 기운 포스트잇으로 붙인다. 서로 다르면 그 앱 줄 안에 작게 붙인다(예: 꾸브라꼬숯불치킨은 요기요만 최적).
  - 한 앱만 최고면 배지는 이름 옆이다.
- **쿠폰에 집중(13차, 2026-10-03):** 같은 시안 5판.
  - 쿠폰을 키운다(높이 약 76px, 금액 25px, 앱 아이콘 34px). 카드마다 쿠폰 하나에 눈이 가게 한다.
  - New는 카드 오른쪽 위 모서리 배지로 붙인다.
  - 같은 금액 쿠폰의 포스트잇 배지는 오른쪽으로 기울인다.
  - 쿠폰 아래에 "눌러서 자세히 보기"와 아래 화살표를 둔다. 누르면 펼치고 "접기"로 바뀐다.
  - 추가 기안(B): 서브 오퍼를 로고 밑 글자 대신 작은 쿠폰(앱 아이콘, 금액, 이동 꼭지)으로 쿠폰 아래에 둔다. A(로고 밑 글자)와 견준다.
- **한 줄 이름, 펼치면 쿠폰(14차, 2026-10-03):** 같은 시안 6판.
  - 브랜드 이름은 한 줄로 쓴다. 글자 수로 글자 크기를 정한다(8자까지 17px, 한 자마다 0.7px씩 줄여 12px까지, 그래도 넘치면 말줄임). 그린 뒤 폭을 재서 줄이는 방식은 카드마다 배치를 강제로 다시 계산하게 하므로 쓰지 않는다.

## 5. 데이터

### 5-1. "새로" 판정
- 필요한 값: 오퍼(앱·브랜드·채널·금액 구간) 하나하나의 **처음 본 시각 `firstSeenAt`**. 지금은 어디에도 없다(API·내보내기 모두).
- 만드는 곳: tracker 내보내기(`export_data.py`). 원장(append-only)에서 같은 (앱, 브랜드)의 같은 금액·조건이 처음 관측된 시각. 금액이 오르면 새 오퍼로 본다(사용자에게 "새로" = 더 좋아짐).
- 전달: export.json 항목에 `firstSeenAt` 추가 → API `OfferRecord` 통과 → 웹. API는 값을 해석하지 않고 넘긴다(웹이 방문자 기준으로 판정).
- 웹 판정: 기기 저장소(`localStorage`)에 마지막 방문 시각. 없으면 첫 방문 = 오늘 0시 이후 `firstSeenAt`. 있으면 그 시각 이후. 저장소를 못 쓰면 첫 방문으로 본다.
- 파급(`mono/docs/CHANGE-PROPAGATION.md` 오퍼 칸 묶음): 내보내기 → API 레코드·계약 테스트 → 웹. 세 곳을 한 작업으로.

### 5-2. 정렬
- 정렬 기준을 이름 → 비교 함수 표 하나로 둔다(`sortKeys`). 지금: 할인금액·할인율(할인 ÷ 최소주문)·최소주문. 나중에: 인기(클릭 수, 서버 집계 필요)·실시간 순위.
- 같은 금액이면 지금 순서를 유지(안정 정렬). 화면 순서 변동이 잦아질 미래를 위해 목록은 키(브랜드)로 그린다.

## 6. A/B 실험

- 배정: 9월에 쓴 방식 재사용 — 방문자 id 해시(FNV-1a)로 반반. `variant.js`의 고정값 `'a'`를 배정 함수로 되돌린다. 값 이름은 새로: `home: 'now' | 'a'`(9월 `variant`와 섞이지 않게 별도 속성).
- 기록: 모든 이벤트에 `home` 속성. PostHog 개인 속성(person property)에도 처음 배정을 남겨 리텐션을 갈라 본다.

| 지표 | 정의 | 이벤트 |
|---|---|---|
| 오퍼 클릭률 | 오퍼 링크를 누른 방문자 ÷ 방문자 | `offer_link_click` / `page_view` |
| 배너 클릭률 | 배너 클릭 ÷ 배너 노출 | `banner_click` / `banner_impression` |

1. 데이터: `firstSeenAt` 내보내기 → API → 웹 통과(화면 변화 없음).
