# 메인 화면 A안 표시 모델: 오퍼, 배지, 쿠폰, 라벨 (명세)

- 날짜: 2026-10-03
- 상태: 사용자 확정
- 설계: [2026-10-02-home-a-design.md](2026-10-02-home-a-design.md) 16차
- 구현 계획: [../plans/2026-10-03-home-a-coupon-card.md](../plans/2026-10-03-home-a-coupon-card.md)

새 카드가 무엇을 어떤 꼴로 보여 줄지 먼저 정한다. 원칙은 셋이다.
- API 응답(오퍼 스키마)은 바꾸지 않는다.
- 새 카드는 웹에서 이미 받는 값만 다시 묶는다.
- 운영 카드(`BrandCard`, `OfferChip`)와 같은 입력이면 같은 배지, 같은 링크, 같은 계측이 나와야 한다. 다른 것은 아래 "기존과 다른 점"에 적은 것뿐이다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 오퍼 | API `/api/brands`의 `offers[]` 한 줄. 앱 하나의 할인 하나다 |
| 배지 | 오퍼의 속성을 짧은 글자로 올린 표식. 한정(선착순 시각, 기간), 멤버십, 값의 성격(최적, 불확정, 랜덤, 특정메뉴, n%할인) |
| 쿠폰 | 오퍼 하나(동점이면 여럿)를 티켓 모양으로 그린 것. 구조는 늘 같다: 앱 아이콘, 금액, 최소주문, 이동 꼭지 |
| 라벨 | 작고 납작한 표식. 하위 오퍼 금액 줄과 배지를 라벨 꼴로 쓴다 |
| 포스트잇 | 운영 화면의 기운 탭 배지 꼴. 복수 최고 쿠폰의 배지에만 쓴다 |

## 2. 카드 구조

| 자리 | 접힌 카드 | 펼친 카드 |
|---|---|---|
| 최고 오퍼(동점이면 전부) | 쿠폰 하나 | 앱마다 쿠폰 하나 |
| 하위 오퍼 | 로고 밑 라벨(앱 아이콘 + 금액) | 앱마다 쿠폰 하나 |

## 2-1. 복수 최고(동점) 쿠폰은 캐러셀 (2026-10-03 사용자 변경)

- 동점 최고 오퍼 각각을 단독 쿠폰과 똑같은 구조의 쿠폰으로 만들어 가로로 나란히 둔다. 한 쿠폰을 앱 줄로 쪼개지 않는다.
- 쿠폰 폭은 카드 폭의 약 86%다. 옆 쿠폰이 조금 보여 넘길 수 있음을 알린다. 넘기면 쿠폰 단위로 멈춘다(CSS 스크롤 스냅).
- 캐러셀 아래 점 표시로 쿠폰 수와 지금 위치를 보인다. 위치는 화면 관찰(IntersectionObserver)로만 바꾼다. 서버 렌더링 첫 화면은 첫 점이 켜진 상태다.
- 순서는 최소주문이 낮은 쪽부터다.

## 3. 배지 자리 규칙

| 경우 | 배지 자리 | 꼴 |
|---|---|---|
| 단독 최고 쿠폰 | 브랜드 이름 옆. 줄이 넘치면 이름 아래 줄 | 라벨 |
| 복수 최고 쿠폰(동점) | 동점 쿠폰마다 그 쿠폰 오른쪽 위 | 포스트잇(오른쪽으로 기움). 쿠폰마다 자기 배지라 앱 아이콘 접두는 없다 |
| 펼친 쿠폰(최고, 하위 모두) | 금액 오른쪽, 이동 꼭지 왼쪽의 남는 칸 | 라벨 |
| 접힌 하위 라벨 | 배지를 붙이지 않는다 | |

요기요 "최적"의 계산식("25,000원 × 5% + 4,000원")은 배지가 아니다. 쿠폰 안에 넣지 않고 "최적" 배지 바로 아래 한 줄로 둔다. 단독 최고면 이름 줄 아래, 펼친 쿠폰이면 그 쿠폰의 배지 칸 아래다. 복수 최고 쿠폰의 포스트잇 아래에는 두지 않는다. 그때는 펼친 쿠폰에서 본다.

## 4. 배지 목록과 값의 출처

`badgesOf(offer)`는 아래 순서로 배지를 낸다. 순서가 뜻이다: 값의 성격 → 누구만 쓰는지 → 언제까지인지(운영 `OfferChip`의 `chip-tags` 순서와 같다).

| 순서 | 배지 | 글자 | 조건(오퍼 필드) | 운영 카드에서 |
|---|---|---|---|---|
| 1 | 값의 성격 | 불확정 / 랜덤 / 특정메뉴 | `qualifier`가 `최대` / `랜덤` / `특정메뉴` (최대는 "불확정"으로 쓴다) | 같다(`QUALIFIER_TONE`) |
| 1 | 최적 | 최적 | `qualifier === '최적'` | **다르다.** 운영은 2026-09-12부터 그리지 않았다. 사용자가 2026-10-03 다시 보이기로 했다 |
| 1 | 비율 할인 | `n%할인` | 위 셋이 아니고 `badge`가 `^\d+%할인$` | 같다 |
| 2 | 멤버십 | 배민클럽 / 쿠팡와우 / 요기패스 | `membership`이 있고 `none`이 아니거나, `badge`가 `전용쿠폰`으로 끝난다. 글자는 `MEMBERSHIP_LABEL[offer.platform]`, 없으면 `badge` 원문 | 같다 |
| 3 | 한정(시각, 기간) | `badge` 원문 축약: "오전 11시 오픈"은 "11시"로 | `badge`가 있고, 비율 할인이 아니고, `전용`, `클럽`, `패스`가 들어 있지 않다 | 글자만 다르다. 운영은 원문 그대로 쓴다. 새 카드는 시각 꼴(`오전/오후 N시 오픈`)만 "N시"로 줄이고 나머지는 원문이다 |
| | 최고 | (쓰지 않는다) | | **다르다.** 운영의 "최고" 탭은 쿠폰 자체가 최고라는 뜻이라 새 카드에서 뺀다 |

배지 색은 운영 CSS 색을 그대로 쓴다: 선착순과 기간 노랑, 쿠팡와우 검정, 배민클럽 민트, 최적 초록, 불확정과 특정메뉴 회색, 랜덤 검정.

## 5. 쿠폰 안의 값

| 칸 | 값 | 출처와 규칙 |
|---|---|---|
| 앱 아이콘 | `PlatformBadge(offer.platform)` | 운영과 같다 |
| 금액 | `amountText(offer)`: `amount`가 있으면 "11,000원", 없으면 `rawText` 원문 | 운영 `offerAmountText`와 같다 |
| 품절 | 금액에 취소선, 금액 옆에 "품절" 라벨 | 운영과 같다 |
| 최소주문 | `↑18,900`, 0이면 "최소주문 없음", 없으면 "최소주문 ?" | 새 표기. 운영은 상세에서만 "18,900원 이상"으로 썼다 |
| 이동 꼭지 | `offerLink(offer, brand.links, brand.name)` | 운영 링크 사다리와 같은 함수(구현 계획 작업 2에서 꺼낸다) |
| 흐린 쿠폰 | 최고가 없을 때(전부 품절이거나 견줄 수 없음) 대표 쿠폰의 금액을 회색으로 | 운영 `offer--capped`와 같은 뜻 |

## 6. 최고와 동점, 정렬

- 최고: `displayBestAmount(offers, include)`와 같은 금액이고, `comparable(offer, include)`이며 품절이 아닌 오퍼 전부. 운영 `BrandCard`의 `isBest`와 같다.
- 동점 안의 순서: 최소주문이 낮은 쪽부터, 모르면 뒤로. **새 규칙이다.** 운영은 금액 순 정렬에 맡겼고 동점 안 순서는 정하지 않았다.
- 하위: 나머지를 금액 큰 순. 운영은 `최대`를 맨 뒤로 민다. 새 카드도 같게 한다(`qualifier === '최대'`면 뒤로).

## 7. 계측

| 이벤트 | 새 카드 | 운영과 |
|---|---|---|
| `offer_link_click` | 쿠폰과 펼친 쿠폰을 누를 때. 속성은 `offerClickProps` | 같은 키. `best`는 최고 쿠폰이면 true |
| `brand_expand` | "눌러서 자세히 보기"나 이름을 눌러 펼칠 때 | 같다 |
| `brand_impression` | 카드 머리(로고 칸)가 보일 때 | 같다 |
| 숨기기 | 오른쪽 위 숨기기 버튼 | 같다 |

## 8. 기존과 다른 점 요약 (마이그레이션 판단)

| 항목 | 운영 | 새 카드 | 스키마 변화 |
|---|---|---|---|
| 최적 배지 | 그리지 않음 | 그린다 | 없음(`qualifier` 그대로) |
| 최고 탭 | 그린다 | 쿠폰이 대신한다 | 없음 |
| 한정 배지 글자 | 원문 | 시각 꼴만 "N시"로 축약 | 없음 |
| 최소주문 | 상세에만 | 쿠폰마다 `↑` 표기 | 없음(`minOrderAmount` 그대로) |
| 동점 순서 | 정하지 않음 | 최소주문 낮은 순 | 없음 |
| 기본 펼침 | 펼침 | 접힘 | 없음 |
| 배지 계산 위치 | `OfferChip.jsx` 안 JSX 조건문 | `couponModel.badgesOf`(순수 함수). 운영 칩도 같은 함수를 쓰도록 바꾼다 | 없음 |

API와 원장은 바꾸지 않는다. 리팩터링은 둘이다.
- 링크 사다리와 클릭 계측 속성을 `offerLink.js`로 꺼낸다.
- 배지 계산을 `badgesOf`로 꺼내, 운영 칩과 새 카드가 같은 함수를 쓰게 한다. 운영 칩은 `최적`을 거르는 인자(`{ showBestFit: false }`)로 지금 화면을 그대로 유지한다.
