## 서브 폰에서 수집이 0건이던 원인

1. **절전 모드.** 배터리가 100%인데도 `settings get global low_power`가 1이었다.
   이 상태에서 `uiautomator dump` 성공률이 1/6이었고, 끄니 7/10으로 올랐다.
   서브 수집이 실패하면 이 값부터 본다.
2. **Android 9의 알려진 결함.** `ERROR: null root node returned by UiTestAutomationBridge.`가
   간헐적으로 난다. 화면이 계속 움직이면 더 잦다. 땡겨요 홈에는 롤링 배너, 카운터, 말풍선이 있다.
   0.5초 간격 재시도로는 20초 내내 실패했다.
   `capture/common.py`의 `dump_ui`에 3초 간격 재시도 8번을 더했다. 메인은 첫 시도에 읽혀서
   여기까지 오지 않는다.
   - 참고: android/testing-samples#283, android-testing-support-library 그룹의 "null root returned by UiTestAutomationBridge"
   - 재시도로도 안 되면 다음 단계는 연결을 계속 유지하는 uiautomator2 서버다. 폰에 앱을 하나 더 설치해야 한다.

재시도를 넣은 뒤 서브에서 땡겨요를 세 번 돌렸고, 세 번 모두 37곳이 나왔다.
메인과 같은 브랜드 목록이다.

## 가드 일원화

팝업, 광고, 시트, 재난문자, ANR, 권한 창을 닫는 코드는 모두 `capture/guards.py`에 있다.

- 앱 안 가드는 `GUARDS` 표, 시스템 창 가드는 `WINDOW_GUARDS` 표다.
- 부르는 함수 `dismiss`, `dismiss_any`, `find_or_dismiss`, `back`은 serial만 받는다.
  기기별 분기는 없고, 좌표는 `ref_xy`로 기기 크기에 맞춘다.
- `popups.py`와 `overlay_guard.py`는 지웠다.
- 한 번 점검하려면 `python -m capture.guards --serial <s> --once`를 돌린다.
