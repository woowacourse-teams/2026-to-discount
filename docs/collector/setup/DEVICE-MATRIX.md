# 폰별 단계 대조표 (2026-10-07)

세 폰에서 수집 단계를 하나씩 미리보기 모드로 돌려, 어느 폰이 어느 단계를 같은 결과로 끝내는지 확인한 기록이다.
배정(`data/devices.json`)은 이 표에서 통과한 조합만 쓴다.

- 폰: 메인 `<폰 일련번호>`(Android 8, 1080x2220), 노트20 `<폰 일련번호>`(Android 13, 1080x2400), sub2 `<폰 일련번호>`(LG X6, Android 10, 720x1520, 느림).
- 계정: 셋 다 같은 주계정이다. sub2의 쿠팡이츠만 일부러 와우가 아닌 일반 계정이다.
- 방식: 원장, 업로드, `--write`/`--apply` 없이 돌렸다. 날짜가 붙는 산출물은 `--date 2026-10-07-mx<폰>`로 갈랐고, 미리보기도 덮어쓰는 파일(`data/coupangeats_hub_share.json`, 오늘 캡처)은 백업했다가 되돌렸다.
- 예약 작업 `discount-after-open`은 사용자 지시로 꺼 둔 채 시험했고, **지금도 꺼져 있다.** 켤지는 사용자가 정한다.

## 배정 (2026-10-07)

`python scripts/run_routine.py --dry-run --force-audit`:

```
<폰 일련번호>: 2 -> 4a -> 4g -> 4c -> 4f
<폰 일련번호>: 3 -> 3s -> 4b -> 5 -> 5a -> 6 -> 7
<폰 일련번호>: 3w -> 4d -> 5y
```

4d는 메인 부하를 덜려고 sub2로 옮겼다(sub2 통과). 4b, 4c, 4g는 화면 스윕이라 범위를 좁힐 수 없어 이번에 폰별로 안 돌렸다. 지금 배정 폰은 그동안 예약 실행에서 쓰던 그대로다.

## 4a, 4d 원인 (2026-10-07 저녁)

같은 화면을 메인과 노트20에서 프로젝트 드라이버로 덤프해 비교했다(`_open_and_read`에 덤프 저장만 끼운 임시 스크립트, 폰 설정은 안 바꿈).

- 기기: 메인 SM-G885S Android 8, 웹뷰(크롬) 69.0.3497; 노트20 SM-N981N Android 13, 웹뷰 153.0.8010; sub2 LM-X625N Android 10, 웹뷰 154.0.8037.
- **4a**: BBQ 브랜드 페이지의 쿠폰 버튼 노드
  - 메인: `text="쿠폰 받기" content-desc="" clickable="true" bounds="[931,1204][1008,1281]"`
  - 노트20: `text="" content-desc="쿠폰 받기" clickable="true" bounds="[919,1245][1004,1330]"`
  - 새 웹뷰는 버튼 이름을 설명 칸에 싣는다. `_coupon_button`이 글자 칸만 봐서 노트20, sub2에선 시트를 안 열었다. 해상도, 글꼴 크기, 노드 쪼개짐은 원인이 아니었다(칩 "3,000원 할인"은 두 폰 다 한 노드).
  - 조치: 버튼 찾기와 쿠폰 흔적 판정을 `Node.label`(글자 칸 또는 설명 칸)로 본다. 테스트 `test_finds_the_button_when_new_webview_puts_its_label_in_content_desc`.
- **4d**: 노트20에서 `공유하기`를 누른 뒤 화면은 삼성 시스템 공유 창이고 복사 버튼 이름이 "URL 복사"다. 찾는 이름("클립보드에 복사", "복사", "링크 복사")에 없어 `copy_event_link`가 뒤로 나왔다. scrcpy 로그(`-V debug`)에는 클립보드 오류가 없었다 — 다리까지 가지도 않았다.
  - 조치: `COPY_LABELS`에 "URL 복사"를 더했다. 고친 뒤 노트20 `--only 두찜`이 `gateway4.html` 링크를 받아 확인했다.
