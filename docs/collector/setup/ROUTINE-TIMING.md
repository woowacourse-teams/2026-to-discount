# 예약 실행 소요 시간. 기록 되짚기 (2026-09-17)

`discount-after-open`(`scripts/after_open_daily.cmd`) 한 바퀴가 얼마나 걸리는지.
로그(`logs/after-open-<날짜>.log`)에는 **시작 시각만** 찍히고 단계별 시각이 없어
산출물 파일의 mtime과 `data: 자동 반영` 커밋 시각으로 역산했다. 같은 날 여러 번
돌면 파일이 덮이므로 **그 날 마지막 실행**만 단계별로 나온다. 09-17부터는 로그의
`-- n)` 줄에 시각을 찍어 이 문서를 로그로 바로 갱신한다(§3).

> 2026-11-13(이슈 #171): 쿠팡이츠 매장 혜택 읽기는 3단계에서 떼어 3b 단계로 옮겼다. 3b는 15:55 회차에만 돌고 상한은 90분이다. 이 표의 3) 소요는 허브 읽기만이다(11-05 00:01에는 매장 혜택 30곳이 섞여 90분 상한에 끊겼다). 3b 소요는 `logs/runs-index.json`의 단계 `3b`로 본다. 상한을 줄이는 것은 3b 실측을 사흘 본 뒤로 미뤘다.

## 3. 앞으로

- `after_open_daily.cmd`의 `echo -- n)` 줄에 `%TIME%`을 붙여 로그만으로 단계별
  소요를 읽는다(09-17 00:01 실행이 끝난 뒤 반영. 도는 배치 파일을 고치면 cmd가
  바이트 위치로 읽다 깨진다).
- 세 실행(00:01, 10:55, 15:55)이 각 80분이면 폰 점유는 하루 4시간. 10:55 실행이
  12:15에 끝나고 15:55 실행과 겹치지 않는다. 00:01 실행은 01:20 종료.
- 줄일 수 있는 곳: 4단계 배민 순회(29분)는 브랜드 수에 비례. `brands.yml`
  순회 대상(ADR-025)을 줄이거나 화면 대기 시간을 재면 된다. 3단계 "구성 변경 클릭"은
  변경이 없는 날은 안 돈다.

## 4. 2026-09-17 조치 (A+B, 사용자 승인)
