# 메인 화면 비교 실험 중간 보고 (2026-10-14)

메인 화면 비교 실험(A/B 테스트, 방문자를 둘로 나눠 서로 다른 화면을 보이고 결과를 견주는 실험)은 아직 판정할 수 없다. 표본이 목표의 3분의 2다. 방향은 쿠폰 카드 안이 앞선다. 다만 그 차이는 대부분 컴퓨터 방문자에서 나온다.

## 배경

- 2026-10-05 00:00부터 방문자를 반반으로 나눈다.
  - 쿠폰 카드 안(`coupon`): 브랜드마다 대표 쿠폰 한 장을 접힌 카드로 보인다.
  - 기존 안(`old`): 브랜드 카드가 앱별 할인 칩을 펼쳐 보인다.
- 배정은 방문자 ID의 해시(같은 입력에 늘 같은 값을 내는 계산)로 한다(`web/src/homeExperiment.js`). 같은 방문자는 늘 같은 안을 본다.
- 판정에 쓰는 핵심 지표는 실험 설계에서 미리 정했다. 전환, 링크 클릭, 재방문이다. 설계는 tracker 저장소의 `docs/superpowers/specs/2026-10-02-home-a-design.md` 6절에 있다.
- 목표 표본은 안마다 1,000명이다.
- 두 안에 들어간 변경의 시각은 [HOME-AB-LOG.md](HOME-AB-LOG.md)에 적는다.

## 결론

1. **2026-10-14 15:44 기준으로 판정할 수 없다.** 쿠폰 카드 안 661명, 기존 안 623명이다. 하루 신규 방문자가 50~80명이라 2026-10-23쯤 1,000명이 찬다.
2. **두 안이 가장 덜 바뀐 기간에는 쿠폰 카드 안이 링크 클릭에서 앞선다.** 이 문서에서 구간 2라고 부르는 2026-10-07 18:00 ~ 2026-10-12 23:23이다.
3. **폰에서는 두 안의 전환이 같다.** 컴퓨터에서는 쿠폰 카드 안이 전환을 두 배로 낸다. 방문자의 80%가 폰이다.
4. **쿠폰 카드 안은 실험 중에 크게 바뀌었다.** 그래서 전 기간 숫자보다 구간별 숫자를 본다.
5. **첫 방문 안내가 두 안의 전환을 함께 깎았다.** 2026-10-14 15:44에 뺐다.

숫자는 아래 각 절의 표에 있다.

## 집계 기준

모든 숫자는 원장(`events.jsonl`, 서버가 받은 행동 이벤트를 한 줄씩 쌓는 파일)에서 냈다. 행동 분석 서비스 PostHog의 숫자는 쓰지 않았다. 두 곳의 숫자가 다르면 원장이 맞다는 것이 이 저장소의 규칙이다(`docs/ANALYTICS.md`).

집계에서 뺀 방문자는 다음과 같다.
- 개발자 접속(`dev` 표시)과 검색 로봇 같은 자동 방문(`bot` 표시)
- 배포 점검용 방문자(`v_deploycheck`)
- 주소에 `?home=a`나 `?home=old`를 붙여 안을 강제로 고른 방문자(`home_forced`, 43명)
- 어느 안인지 기록이 한 번도 없는 방문자(36명)
- 동작 없이 화면만 하루 수십 번 연 자동 방문자 1명(`v_fa46ff74d778e5ba`). 근거는 아래 "추가 분석" 1절에 있다

방문자의 안은 그 사람의 이벤트에 마지막으로 실린 `props.home` 값으로 정했다. 구간별 표는 그 구간 안에서 일어난 이벤트만 센다. 한 사람이 두 구간에 걸쳐 왔으면 두 구간에 모두 들어간다.

지표는 모두 방문자 수의 비율이다.

| 지표 | 그 방문자에게 있어야 하는 것 |
|---|---|
| 전환 | 할인 링크 클릭(`offer_link_click`)이나 배너 클릭(`banner_click`)이 한 번 이상 |
| 무동작 | 모든 세션(한 번 들어와서 나갈 때까지)에서 아무 동작도 없음. 화면 노출, 들어옴, 나감, 설문 노출, 알림 안내, 첫 방문 안내는 동작으로 치지 않는다 |
| 검색 | 검색어 확정(`brand_search_submitted`) |
| 필터, 분류 | 분류 바꾸기, 앱 거르기, 빠른 필터, 필터 시트 열기나 적용, 멤버십, 초기화 중 하나 |
| 재방문 | 서로 다른 날짜에 이틀 이상 방문 |

표의 마지막 세 열은 이렇게 읽는다.
- 차이: 쿠폰 카드 안 비율에서 기존 안 비율을 뺀 값이다. 단위는 퍼센트포인트(%p)다.
- 상대 차이: 쿠폰 카드 안 비율을 기존 안 비율로 나눈 뒤 1을 뺀 값이다.
- 검정 통계량(z): 두 비율의 차이가 우연인지 가늠하는 값이다. 절댓값이 1.96 이상이면 우연일 확률이 5% 아래다.

[HOME-AB-LOG.md](HOME-AB-LOG.md)의 2026-10-08 현황은 무동작과 재방문의 정의를 적지 않았다. 그래서 그 숫자와 이 문서의 숫자를 이어 비교하지 않는다.

## 첫 방문 안내

첫 방문 안내가 신규 방문자의 첫 세션 전환을 절반으로 줄였다. 그래서 2026-10-14 15:44에 뺐다(커밋 `a06d655`).

안내는 2026-10-12 23:23에 두 안 모두에 들어갔다. 단계는 4~5개였고, 안내가 떠 있는 동안 화면 스크롤을 잠갔다.

전후 비교는 신규 방문자의 첫 세션으로 했다. 외부 링크로 몰려온 날은 원래 전환이 낮다. 예를 들어 2026-10-06에는 외부 유입 241명의 전환이 14%였다. 그래서 들어온 경로를 나눠 비교했다.
- 직접 유입: 주소를 치거나 앱 안 브라우저로 들어옴
- 외부 유입: 다른 사이트의 링크를 타고 들어옴

| 유입 | 안내 전 (2026-10-07 ~ 2026-10-12) | 안내 후 (2026-10-12 23:23 ~) | 전환 차이 |

| 직접 | 400명, 전환 29%, 무동작 36% | 72명, 전환 14%, 무동작 56% | -15%p (상대 -52%, z=2.7) |

- 원인은 스크롤 잠금으로 본다. 다음이나 건너뛰기를 누르기 전에는 화면을 쓸 수 없었다. 실제 폰에서 재현하지는 않았다.
- 안내를 뺄 때 화면 코드, 띄우는 조건, 스타일, 이벤트 `first_guide`를 함께 지웠다.

## 추가 분석

### 1. 기존 안의 방문자당 세션이 많았던 이유

자동 방문자 1명이 기존 안의 세션을 부풀렸다. 그래서 이 방문자를 집계에서 뺐다.

세션은 브라우저 탭마다 따로 매긴다(`sessionStorage`, 탭을 닫으면 지워지는 브라우저 저장소). 앞 세션이 끝나고 1분 안에 새 세션이 시작된 경우를 셌다. 이런 경우는 새로고침이나 새 탭으로 다시 연 것이다. 시각은 서버가 받은 시각 대신 브라우저 시각(`clientTs`)으로 쟀다. 서버 시각은 이벤트를 묶어 보낸 시각이라 세션 길이가 0초로 찍힌다.

| | 쿠폰 카드 안 | 기존 안 |
|---|---|---|
| 1분 안에 다시 시작한 세션 | 93건(69명) | 190건(60명) |
| 그중 한 사람이 낸 것 | 최다 5건 | 112건(`v_fa46ff74d778e5ba`) |

`v_fa46ff74d778e5ba`는 사람으로 보기 어렵다.
- 2026-10-11 ~ 2026-10-12 이틀 동안 세션이 145개다.
- 이벤트는 진입, 이탈, 노출뿐이다. 누르거나 고른 기록이 하나도 없다.
- 네트워크 주소의 해시(`ipHash`)가 7개로 바뀌었다. 유입은 모두 직접이다.
- 봇이라고 스스로 밝히지 않아 서버의 크롤러 판정을 빠져나갔다.

이 방문자를 빼면 기존 안의 방문자당 세션은 2.41에서 2.18로, 동작 없는 세션은 59.8%에서 55.5%로 내려간다. 방문자 단위 지표는 한 명이 빠지는 것이라 거의 바뀌지 않는다.

같은 꼴의 방문자를 집계 도구가 앞으로 잡게 했다(`scripts/experiments.py`의 `mark_idle_reloaders`).
- 조건: 동작이 하나도 없고, 세션 40개 이상이며, 하루 평균 세션 20개 이상
- 처리: 크롤러처럼 `bot` 표시(`idle-reload`)만 하고 지우지 않는다. `--include-bots`로 다시 볼 수 있다
- 기준을 높게 둔 이유: 새 할인을 보기만 하고 가는 사람은 실제로 있다. 14일 동안 25번 와서 아무것도 누르지 않은 방문자가 있었다
- 지금 원장에서 이 조건에 걸리는 방문자는 두 명이다. 다른 한 명은 이미 개발자로 판정돼 빠져 있었다

남은 차이도 하나 보였다. 앞 세션에서 링크를 누른 뒤 다시 들어온 세션이 쿠폰 카드 안 32%, 기존 안 15%다. 배달앱에 갔다가 돌아와 다시 보는 사람이 쿠폰 카드 안에 더 많다.

### 2. 쿠폰 전체를 링크로 만든 변경의 효과

커밋 `76f22d4`(2026-10-07 08:53)가 쿠폰 카드 안의 링크 클릭을 올린 것으로 보인다. 다만 같은 날 다른 변경도 들어가서 이 커밋 하나의 효과로 확정하지는 않는다.

변경 전후의 링크 클릭 방문자 비율이다. 변경 전 구간은 서버가 쿠폰 카드를 처음부터 그리기 시작한 2026-10-05 15:51부터 잡았다.

| 기간 | 쿠폰 카드 안 | 기존 안 | 차이 | z |
|---|---|---|---|---|
| 전 (2026-10-05 15:51 ~ 2026-10-07 08:53) | 47/266 = 17.7% | 45/258 = 17.4% | +0.2%p | +0.07 |
| 후 (2026-10-07 08:53 ~ 2026-10-12 23:23) | 118/312 = 37.8% | 91/301 = 30.2% | +7.6%p | +1.98 |

- 변경 전에는 두 안이 같았다. 차이는 변경 뒤에 생겼다.
- 두 안 모두 변경 뒤에 올랐다(쿠폰 카드 안 +20.2%p, 기존 안 +12.8%p). 날짜에 따른 공통 변화다.
- 공통 변화를 빼는 이중차분(두 안의 변화량끼리 다시 빼는 방법)으로 +7.4%p가 남는다.
- 변경 뒤 쿠폰 카드 안의 링크 클릭 399건은 쿠폰 면 326건, 하단 시트 48건, 캐러셀 25건이다. 클릭 위치는 클릭 이벤트의 `where` 속성으로 셌다.

- 무동작 정의가 2026-10-08 현황과 같은지 확인하지 못했다.
