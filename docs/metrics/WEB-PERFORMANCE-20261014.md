# 웹 성능, 접근성, 요청 수 점검 (2026-10-14)

홈 쿠폰 카드 쪽(`?home=a`)의 첫 화면 차단 시간(TBT, 첫 화면 뒤 입력이 막히는 시간의 합)을 저사양 폰 조건에서 중앙값 416ms에서 167ms로 줄였다. 원인은 카드마다 하이드레이션(서버가 그린 HTML에 브라우저가 동작을 붙이는 단계)이 실패해 카드 12장을 다시 그린 것이었다. 같은 날 접근성 점수를 93에서 100으로 올렸고, 요청 수를 줄이려 홈 CDN 캐시를 늘렸다.

## 배경

- Vercel Hobby(무료 플랜) 요청 한도가 걱정돼 요청 수를 줄일 곳과 검색 노출(SEO)과 부딪히는 곳을 다시 봤다.
- 홈 A/B(2026-10-05 시작, 첫 방문 배정은 2026-10-06 13:21부터 미들웨어)의 두 쪽 가운데 쿠폰 카드 쪽 Lighthouse(구글의 웹 성능 점검 도구) 성능이 운영 카드 쪽보다 10점쯤 낮았다.

## 1차: 요청 수, SEO, 접근성 (main `9861614`)

| 변경 | 이유 | 결과 |
|---|---|---|
| `robots.txt`에서 `Disallow: /assets/` 삭제 | 구글은 JS, CSS를 받아 화면을 그려 색인한다. 막으면 브랜드 페이지가 스타일 없이 보인다 | 운영 반영 확인 |
| 같은 줄을 `scripts/prerender.mjs`에서도 삭제 | 빌드가 `public/robots.txt`를 덮어써 첫 수정이 반영되지 않았다(프리뷰에서 발견) | 운영 반영 확인 |
| 홈 CDN 캐시 60초에서 300초, 만료 뒤 옛 화면 제공도 300초 | 금액은 하루 세 번만 바뀐다. 반영이 최대 약 10분 늦는다 | `s-maxage=300` 확인 |
| 강조 주황 `#dd4b02`에서 `#c44200`, 선착순 빨강 `#e5322d`에서 `#d32a25`, 정렬 칩 글자 흰색 | 흰 배경 대비 4.13, 4.35로 기준 4.5 미달 | 대비 5.09 |
| 바닥글 링크 위아래 여백 | 누르는 영역 21.8px로 기준 24px 미달 | 기준 충족 |

운영 Lighthouse(모바일): 접근성 93에서 100, SEO 100 유지, 권장 사항 100.

## 2차: 쿠폰 카드 TBT (main 반영, 브랜치 `preview/perf-hydrate`)

### 찾은 원인

CPU 4배 감속 프로파일에서 쿠폰 카드 쪽 앱 스크립트 실행이 4,260ms로 운영 카드 쪽(1,005ms)의 4배였다. 콘솔에 React 오류 #421(하이드레이션이 끝나기 전 Suspense 경계에 갱신이 닿음)이 카드 수만큼 12번 났다.

1. `App.jsx`가 `CouponCard`를 `lazy`로 받고 카드마다 `Suspense`로 감쌌다. 코드 조각(15KB)을 받는 동안 `setMounted(true)` 같은 급한 갱신이 오면 React는 서버 화면을 버리고 대체 카드(`BrandCard`)와 진짜 카드를 차례로 다시 그렸다. 조각이 늦게 올 때만 나서 5회 중 1회꼴로 잡혔다. 느린 망의 실사용에서는 더 잦았을 것이다.
2. 2026-10-12 수정(`1af3801`)은 알림 토글 갱신 하나만 전환으로 바꿔 다른 급한 갱신은 막지 못했다.
3. iOS 글자 겹침을 고치는 재배치 스크립트(`api/ssr.js`의 `RELAYOUT`, `main.jsx`의 `relayout`)가 모든 기기에서 페이지 전체를 다시 배치했다. 4배 감속에서 456ms였다.

### 바꾼 것과 지킨 목적

| 변경 | 지킨 목적 |
|---|---|
| `CouponCard`를 정적 import. 경계 자체가 없어져 같은 갱신이 와도 #421이 날 수 없다 | 쿠폰 카드 화면, 서버 렌더는 그대로 |
| `coupon-card.css`만 따로 받기(`App.jsx` 효과, 서버 렌더는 `<head>` 링크) | 이 CSS에 `:root` 배경 같은 전역 규칙이 있어 운영 카드 쪽에 섞이지 않게 했다 |
| 재배치는 iOS WebKit(아이폰, 아이패드, 카카오톡 인앱)에서만 | 겹침은 iOS에서만 났다. iOS에서는 전과 같이 돈다 |
| GA4를 load 직후가 아니라 한가할 때(최대 4초 안) 띄움 | 방문 집계는 남는다. PostHog와 같은 방식 |
| 로고 캐시 30일에서 1년 | 로고 주소에 `?v=<내용 해시>`가 붙어 바꾸면 주소가 바뀐다 |

### 상호작용 부하 (`web/scripts/dev/load-interact.mjs`)

같은 조건에서 카드 펼치기, 필터 열고 닫기, 검색 입력, 목록 끝까지 스크롤을 차례로 했다.

- **목록 끝까지 스크롤(쿠폰 카드 쪽):** 운영은 5회 중 2회 13초짜리 긴 작업이 나 차단 시간 합이 25~30초였다. 개선 버전은 6회 모두 긴 작업 최대 321ms였다. 스크롤로 새 카드 묶음이 붙을 때도 `lazy` 경계에서 같은 하이드레이션 실패가 겹친 것으로 본다. 운영 카드 쪽은 운영에서도 최대 213ms였다.
- 카드 펼치기, 필터, 검색: 긴 작업 0건, 입력 지연 최대 32~48ms(입력 반응 기준 200ms).
- 메모리: 목록 끝까지 내려도 JS 힙 4.5~6.1MB로 늘지 않았다.
- 브랜드 페이지 `/brand/맘스터치`: TBT 333~374ms, 레이아웃 이동 0.024 이하.
- 서버(순차 8회만): 홈 서버 렌더 0.32~0.50초, CDN 적중 15/16. `/api/brands` 0.10~0.22초, 응답 155KB(압축 전), 캐시 헤더 없음.

## 해 보고 버린 것

- **첫 방문 안내 구멍을 `transform`으로 옮기기:** 화면이 빨라져 안내가 일찍 뜨며 카드를 따라 움직인 것이 레이아웃 이동으로 잡혀 고쳤다. 같은 날 안내 자체가 빠져(`a06d655`, 신규 첫 세션 전환을 절반으로 깎음) 이 수정은 넣지 않았다. 위 측정의 개선 쪽은 안내가 있던 버전이다.

- **Lighthouse로 전후 비교:** 같은 운영 주소의 TBT가 0.6~3.5초, 성능 점수가 40~62로 흔들려 판단에 못 썼다. 실제 브라우저에서 긴 작업을 세는 `load-tbt.mjs`로 바꿨다.
- **`content-visibility: auto` 추가:** 화면 밖 카드에 이미 걸려 있었다(`brand-card.css`, `coupon-card.css`).
- **Edge 헤드리스 `--screenshot`으로 360px 캡처:** 창이 360px로 줄지 않고, 보호 우회 값이 첫 요청에만 붙어 로고와 CSS가 깨졌다. CDP로 모든 요청에 헤더를 붙이고 화면 크기를 지정해 찍었다.

## 남은 것

- 요청 수 감소는 Vercel 대시보드 사용량에서 며칠 뒤 확인한다(기록 `vercel-usage.jsonl`은 2026-09-13이 마지막).
- iOS 재배치는 `ios-shot` 워크플로(실제 iOS 사파리 시뮬레이터)로 운영 반영 뒤 찍어 확인한다. 프리뷰를 찍으려면 저장소 시크릿 `VERCEL_BYPASS`가 필요하다.
- 운영 카드 쪽 TBT 300ms대의 나머지는 GA4, PostHog 같은 제3자 스크립트와 스타일 계산이다.
- `/api/brands`는 압축 전송 여부와 캐시 헤더를 확인할 거리다. 배너 자동 넘김, 할인 그래프 드래그는 아직 재지 않았다.
