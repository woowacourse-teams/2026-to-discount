# ADR-001. 3레포를 한 저장소로 합치고, 트래커는 일부만 싣는다

- 날짜: 2026-08-06
- 상태: 확정
- 대체: `tracker/docs/decisions/ADR-012-three-repo-split-and-deployment.md`

## 맥락

파이프라인은 저장소 셋으로 나뉘어 있었다. 나눈 근거는 ADR-012에 있다 —
배포 단위가 다르다는 것(Vercel 정적 빌드 vs OCI 상시 프로세스). 그 판단
자체는 지금도 틀리지 않았다.

문제는 배포가 아니라 **읽기**였다. 세 저장소가 서로를 전제로만 동작해서,
한쪽만 봐서는 무엇이 계약인지 알 수 없다.

- `export.json`의 필드 하나를 늘리면 세 저장소를 다 고쳐야 한다. 실제로
  API가 모르는 필드를 만나 `/api/reload`가 500으로 죽는 사고가 세 번
  반복됐다(2026-08-03).
- 계약을 적어둔 문서(`docs/ORCHESTRATION-CONTRACT.md`)가 저장소마다 하나씩
  있는데, 셋 다 08-01 기준에서 멈춰 실제와 어긋나 있었다. 필드 수를 13개로
  적어둔 채 실제는 16개였고, "reload가 500난다"고 적힌 동작은 이미 고쳐진
  뒤였다.
- 세 저장소를 오가며 교차 확인하는 일 자체가 매번 비용이었고, 그 비용이
  문서를 낡게 만든 원인이었다.

## 판단

한 저장소 아래 `tracker/` · `api/` · `web/`로 합친다. 커밋 이력은 전부
살린다.

```
/
├─ docs/          루트: 오케스트레이션 계약·컨벤션·이 ADR
├─ tracker/       판독 규칙·데이터 모델·원장 (구현 일부 제외, 아래)
├─ api/           Spring Boot — 별칭 정규화·확정/보류·만료 판정
└─ web/           React — 교차 비교 화면
```

이력 보존은 `git filter-repo --to-subdirectory-filter` 후
`--allow-unrelated-histories` 병합으로 했다. 223개 커밋이 그대로 남고
`git log --follow`도 동작한다. ADR-012가 `git subtree split`으로 웹을 떼어낼
때 쓴 것과 같은 원칙이다 — 복사하면 이력이 사라지고, 이력이 사라지면 왜
그렇게 됐는지도 사라진다.

### 트래커는 일부만 싣는다

캡처 자동화 본체(`capture/` — ADB 조작, 앱별 진입 경로, 실측 좌표 상수)와
실행 진입점(`tracker.py`·`dashboard.py`), 캡처 대상 설정(`config/`)은
싣지 않는다. 실제로 돌릴 사람에게는 따로 전달한다.

남긴 것은 **"직접 판독한다"는 주장의 근거가 되는 것들**이다.

| 남김 | 이유 |
|---|---|
| `parse/CONTRACT.md` | 판독 규칙의 명세. 무엇을 레코드로 만들고 무엇을 버리는지 |
| `schema.py`·`store.py`·`export_data.py` | 데이터 모델·중복 정리·내보내기 규칙 |
| `ingest.py`·`backfill_export.py`·`check_deploy.py` | 원장 운용과 안전장치 |
| `data/log.jsonl`·`data/export.json` | 실제 판독 결과 226건 |
| `tests/` | 위 규칙이 검증된다는 증거 |
| `docs/` | ADR 17건 + 계약 + 스펙 |

`parse/CONTRACT.md` 머리말에 구현이 없다는 사실을 적어뒀다 — 계약만 있고
구현이 없는 상태를 모르고 읽으면 문서가 거짓말처럼 보인다.

### 캡처 원본은 이력에서 지운다

`ref/` 199MB(스크린샷 원본)를 이력째 제거했다. 트래커 저장소 206MB 중
대부분이 이것이었고, 합친 저장소는 37MB가 됐다.

되짚을 근거를 남긴다는 원칙(ADR-003)과 상충하지만, 남긴 쪽은 판독 **결과**
(`data/log.jsonl` 226건, `raw_text` 원문 포함)이고 지운 쪽은 그 결과를 만든
**화면 이미지**다. 원본이 필요하면 원래 저장소에 그대로 있다.

## 근거

- **계약이 한 곳에 있어야 안 어긋난다.** 세 문서를 각각 갱신하는 규율은
  세 번 다 실패했다. 저장소가 하나면 필드를 늘리는 커밋과 계약을 고치는
  커밋이 같은 diff에 들어온다.
- **이력을 살리는 비용이 낮다.** `filter-repo`는 별도 서버나 변환 없이
  경로 필터와 디렉터리 이동을 한 번에 한다.
- **트래커 전량 공개는 목적이 아니다.** 이 저장소의 목적은 파이프라인이
  어떤 규칙으로 도는지 보이는 것이지, 남의 앱 화면을 긁는 도구를 배포하는
  게 아니다(ADR-015의 공개 범위 원칙과 같은 방향).

## 대가 / 아직 안 한 것

- **배포 워크플로가 죽어 있다.** `tracker/.github/workflows/deploy.yml`과
  `api/.github/workflows/deploy.yml`은 하위 디렉터리로 들어가면서 GitHub이
  읽지 않는 위치가 됐다(루트 `.github/`만 인식). **운영 배포는 여전히 원래
  세 저장소에서 돈다.** 이 저장소를 운영 소스로 삼으려면 워크플로를 루트로
  올리고 `paths:` 필터로 앱별 트리거를 나눠야 한다 — 러너 경로와 시크릿이
  걸려 있어 이번 범위에서 제외했다.
- **ADR 번호가 앱마다 1부터다.** 합치면서 통합 번호로 바꾸지 않았다. 앱
  단위 결정은 앱 디렉터리 안에서 완결되고, 상호 링크 27건을 전부 고치는
  비용이 이득보다 크다. 루트 `docs/decisions/`는 **오케스트레이션 층의
  결정만** 담는다 — 앱 하나로 끝나지 않는 것.
- **원본 저장소를 아카이브하지 않았다.** 배포가 거기서 도는 동안은 살아
  있어야 한다.
