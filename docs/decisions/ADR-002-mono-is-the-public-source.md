# ADR-002. mono는 공개 정본이자 단일 진입점이다. 수집기는 싣지 않는다

- 날짜: 2026-09-29
- 상태: 확정
- 대체: ADR-001의 "트래커는 일부만 싣는다" 절

## 전제

ADR-001은 수집기의 일부(판독 계약, 데이터 모델, 원장, 문서)를 이 저장소에 두었다. 옮기는 일은
"같은 작업 안에서 손으로" 했다. 2026-09-28 실측으로 그 규율은 깨져 있었다. 문서 44개는 같았지만
10개가 갈라지고 36개가 빠져 있었고, mono tracker/의 export 사본은 09-18에 멈춰 있었다. 데이터는
09-01부터 수집기가 서버로 직접 올리고 있어서 이 저장소의 사본은 아무도 읽지 않았다.

## 결정

- 이 저장소는 코드(`api/`, `web/`)와 공개 문서의 정본이다. 팀 입구는 `docs/WORKFLOW.md` 하나다
- `tracker/`는 싣지 않는다. 수집기는 비공개 저장소에만 있다
- 문서는 비공개 저장소에서 쓰고 공개해도 되는 것만 이 저장소로 전파한다. 서버 경로, 계정 파일,
  토큰이 섞이지 않게 전파 전에 검사한다
- 쓰지 않는 배포 경로(`deploy-api.yml`, `deploy-data.yml`)와 이 저장소에 붙어 있던 운영 서버 러너는 걷어낸다

## 근거

- 손으로 맞추는 사본은 갈라져도 양쪽 다 멀쩡히 동작한다. 갈라짐을 아무도 못 본다
- 공개 저장소에 운영 서버 러너가 붙어 있으면, 수동 실행 하나로 멈춘 코드가 운영을 덮을 수 있다
- 문서를 공개 저장소에서 바로 쓰면 민감한 줄이 한 번의 커밋으로 공개된다

## 결과

과거 PR과 이력은 그대로 남는다. 이력을 다시 쓰지 않는다.
