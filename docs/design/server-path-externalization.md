# 공개 저장소 서버 경로 외부화 구현 계획

작성일: 2026-10-15

## 요구사항과 범위

공개 저장소에 환경별 서버 절대경로를 기록하지 않는다. 실행에 필요한 경로는 외부 설정으로 주입하고 실제 서버 경로를 기본값으로 제공하지 않는다. 저장소 내부 상대경로는 허용한다.

이번 작업은 CI에서 검출된 기존 11개 파일에 한정한다. 해당 파일에서는 최초 검출 문자열뿐 아니라 환경별 서버 절대경로를 함께 정리한다. 다른 파일에서 발견한 경로는 변경하지 않고 후속 작업으로 남긴다. 따라서 저장소 전체의 경로 외부화 완료를 이번 작업의 완료 조건으로 삼지 않는다.

계획 승인 후 기존 11개 파일의 로컬 구현과 검증을 완료했다. 서버 설정 변경과 배포는 수행하지 않았다. 로컬 검증 후 사용자 승인에 따라 push와 PR 생성을 진행한다. 커밋 이력은 유지한다.

## 설계

공개 코드는 경로를 사용하는 방법만 정의한다. 실제 값은 GitHub 환경 설정이나 관리자가 관리하는 비공개 배포 설정에 둔다. 생성된 systemd, nginx 설정과 실제 환경 파일은 공개 저장소에 커밋하지 않는다.

단순 문자열 삭제나 검사 예외 등록은 사용하지 않는다. tracker 검사는 유지하고 대상 파일을 정리해서 기존 실패 원인을 제거한다. 정책상 허용할 런타임 진입점 표기와 환경별 서버 배치 경로는 구분한다. 예를 들어 인터프리터 shebang을 서버 배치 정보로 취급하지 않는다.

### 경로 입력 계약

- 데이터 동기화: 제안된 `DEV_OFFERS_SOURCE_EXPORT_PATH`를 사용하되 기존 브랜치의 실제 변경과 일치하는지 확인한다.
- 프로비저닝: 서비스 작업 디렉터리, 환경 파일, Java 실행 파일, JAR 위치, 쓰기 허용 디렉터리, 설치 대상, sudoers 파일 위치를 명시적으로 전달한다. 변수명은 기존 호출부 계약을 확인한 뒤 대상 README에 확정한다.
- 부하 테스트: 각 스크립트가 실제로 사용하는 데이터, 설정, 로그 경로만 인자로 받는다. 기존 인자와 환경변수가 있으면 재사용한다.
- 경로가 없거나 비어 있으면 변수명 또는 인자명만 표시하고 변경 작업 전에 종료한다. 실제 경로값은 오류나 CI 로그에 출력하지 않는다.
- 실행 코드에서는 경로를 셸 명령 문자열에 직접 연결하지 않는다. SSH 원격 명령에 필요한 인용과 입력 검증을 별도로 적용한다.

### 권한과 호환성

sudo로 실행되는 배포 코드의 경로 설정은 root가 관리하는 신뢰 가능한 입력이어야 한다. runner가 임의 설치 위치나 실행 대상을 선택할 수 있도록 권한을 넓히지 않는다. 비공개 설치 설정의 소유권과 쓰기 권한을 검증한다.

systemd는 일반 셸처럼 모든 필드의 환경변수를 치환하지 않으므로 설치 전에 템플릿을 렌더링한다. 필수 값과 미치환 토큰을 검사한 후 설정을 검증하고 설치한다. sudoers, nginx, systemd의 문법과 파일 권한을 유지한다.

설치된 외부 배포 코드와 기존 경로 계약은 유지한다. 대상 밖 `deploy.py`, `development.env`, nginx 설정 등에 고정 경로가 남아 있다는 사실을 기록한다. 이 파일들을 함께 고쳐야만 동작하는 설계는 이번 범위에 도입하지 않는다.

## 검증 명령과 기대 결과

구현 후 파일 이름과 기존 테스트 구조를 확인해 명령을 확정한다. 아래 명령의 실제 실행 결과는 문서 끝의 구현 기록에 정리한다.

```bash
git diff --check
bash -n api/deploy/dev/provision.sh
python -m pytest tests/test_mono_no_sensitive_strings.py -q
python -m pytest -q -rs
```

앞의 두 명령은 mono에서, pytest는 tracker에서 mono 체크아웃을 준비한 뒤 실행한다. 모두 성공해야 한다. 민감정보 검사는 최신 mono 전체를 검사하므로 이번 11개 밖의 실패를 별도로 구분한다.

추가 검증은 대상 파일의 서버 절대경로 잔존 검사, 워크플로 YAML 파싱, 변경한 Python 스크립트의 기존 테스트, 템플릿 렌더링 테스트다. `systemd-analyze verify`, `nginx -t`, `visudo -cf`는 임시 또는 격리된 설정을 대상으로 실행한다. 로그에 실제 설정값을 노출하지 않는다.

## 적용과 복구

외부 설정 준비, 로컬 검증, 개발 환경 적용, CI 확인 순서로 진행한다. 운영 서버의 디렉터리 구조는 바꾸지 않는다. 변경 전 비공개 설정과 설치 파일을 백업하고 문제가 생기면 기존 설치 파일로 복구한다. 공개 저장소에 실제 경로를 다시 커밋하는 방식으로 복구하지 않는다.

PR 생성 시 병합 전과 병합 후 인수테스트를 대화에서 안내한다. 환경, 실행 방법, 기대 결과, 관리자 직접 확인 항목을 구분한다.

## 구현 및 검증 기록

### 기준과 구현

- mono 기준: `34a65f92cdda6c924787c3ccdf3ca72c35a96d0a`의 별도 작업트리, 브랜치 `codex/server-path-externalization`.
- tracker 기준: 실패 실행과 같은 `e638994da7ee4cb26540923b441a8a72bf583fa4`.
- `6052c8cc`는 기존 경로 외부화 브랜치에서 확인했다. 이번 구현은 동일 원본 경로 Secret을 사용하면서 대상 11개 파일의 나머지 서버 경로도 정리한다.
- 코드 및 기존 문서 수정은 표의 11개 파일이다. 이 계획 문서는 진행 기록이다. 대상 밖 파일은 수정하지 않았다.
- 데이터 동기화에 기존 두 Secret 외에 원본 경로, SSH 대상, 동기화 명령, 임시 디렉터리의 네 Secret이 필요하다. 실제 값은 등록하지 않았다.
- 프로비저닝은 관리자 소유 JSON을 필수로 받으며 실제 환경 파일은 비공개 원본을 사용한다. 기존 환경 및 데이터 파일을 보존한다. 변경 범위 밖 배포 도구의 경로 계약과 다르면 설치 전에 거부한다.
- 부하 테스트 호출부는 변경하지 않았다. 프로세스 환경변수 또는 systemd의 관리자 `Environment=` 설정을 사용한다. 실제 경로 기본값은 없다.
- 서버 스냅샷은 경로 대신 논리 식별자와 해시를 출력한다. 기존 기준 스냅샷은 다시 만들어야 한다.

| tracker의 `python -m pytest tests/test_mono_no_sensitive_strings.py -q` | 1개 통과. 변경된 mono 작업트리의 추적 파일 전체 검사 |
| tracker의 `python -m pytest -q -rs` | Python 3.12에서 1,465개 통과, 건너뜀 없음. mono와 beggars-ops 검증 사본 사용 |
| `bash -n api/deploy/dev/provision.sh` | 통과 |
| 변경 Python 및 provision 내장 Python AST 검사 | 통과 |
| 워크플로 YAML 파싱 및 실제 bash의 가짜 SSH 실행 | 통과 |
| 렌더링한 격리 sudoers의 `visudo -cf` | 실제 문법 검사 통과 |
| 대상 11개 파일 경로 잔존 검사 | 환경별 서버 절대경로 없음. 인터프리터 shebang은 허용 |
| `git diff --check`, `git diff` | 공백 검사 통과 및 범위 확인 |

tracker 전체 검증은 처음 Python 3.11 문법 차이로 수집에 실패했다. Python 3.12로
전환한 뒤에는 자식 프로세스의 `python` 실행 파일 누락으로 1개 실패했다.
검증용 가상환경을 PATH에 연결하고 beggars-ops 사본을 준비한 최종 실행에서는
1,465개 모두 통과했다. 이 과정에서 tracker 소스와 검사 규칙은 변경하지 않았다.

추가 격리 테스트는 11개 파일 범위를 유지하기 위해 저장소 밖의 임시 검증 스크립트로
실행했다. 새 동작의 회귀 테스트를 저장소에 추가하려면 별도 테스트 파일 범위를 합의한다.

### 실제 적용 전 남은 작업

- 관리자가 development Secrets와 비공개 프로비저닝 JSON 및 환경 파일을 준비한다.
- 관리자 소유 별도 systemd drop-in에 `LOAD_TEST_*` 경로 설정을 등록한다.
- 로컬 macOS에는 `systemd-analyze`와 `nginx`가 없어 실제 systemd 및 Nginx 검증은 미수행이다. 개발 Linux 서버에서 렌더링된 unit 검증과 `nginx -t`가 성공해야 설치 및 reload를 진행한다.
- 실제 서버의 데이터 동기화, API 응답, 요청 ID 연결과 기존 파일 보존은 미검증이다. 부하 발생과 운영 서비스 재시작은 실행하지 않았다.
- 위 pytest 결과는 변경 작업트리를 연결한 로컬 결과다. 원격 CI의 최종 결과는 PR 체크에서 별도로 확인한다.


### PR 준비

- 사용자 승인 범위: 작업 브랜치 push 및 PR 생성. 병합과 서버 배포는 포함하지 않는다.
- PR 대상: `main`. 최신 `dev`에는 대상 부하 테스트 파일이 없어 `dev` 대상으로 제출하면 다른 기능의 변경이 함께 포함된다. 승인된 11개 파일과 계획 기록만 포함하도록 `main` 기준 Draft PR을 사용한다.
- 추가 사전 검증: `python -m pytest scripts/test_generate_project_structure.py -q` 5개 통과. `python3 scripts/generate_project_structure.py --check` 통과.
- 구조 검사 pytest의 캐시 쓰기는 로컬 sandbox에서 제한됐으나 테스트 5개는 정상 통과했다. 제품 코드나 검증 결과에는 영향이 없다.
