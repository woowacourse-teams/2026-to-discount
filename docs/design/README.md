# 설계 문서 목록과 상태

문서 종류는 셋이고 역할이 다르다.

| 종류 | 자리 | 무엇 | 언제 쓰나 |
|---|---|---|---|
| **설계(design)** | `docs/design/N-*.md` | 문제·대안·선택·근거. "무엇을 왜" | 결정 전. 브레인스토밍 산출물 |
| **계획(plan)** | `docs/superpowers/plans/YYYY-MM-DD-*.md` | 순서 있는 작업 목록(체크박스), 파일·테스트·검증 | 설계가 승인된 뒤. 이걸 보고 구현한다 |
| **결정(ADR)** | 트래커 `docs/decisions/ADR-NNN-*.md` | 이미 정한 것과 그 이유 | 구현이 끝나 규칙이 된 뒤 |

설계는 "할지 말지·어떻게 할지"를 고르는 문서라 투두가 아니다. 승인되면 계획으로
옮기고(`writing-plans`), 계획은 체크박스로 진행을 적는다. 설계 문서 자체는 승인 뒤
고치지 않는다 — 결과는 ADR과 계획에 남긴다.

문서 번호 3부터 20은 GitHub 이슈 번호와 같다. 21부터 27은 이슈 없이 순번만 이었고 그 사이 PR 번호가 앞서 나가 이슈 번호와 맞출 수 없게 되었다. 대신 문서마다 추적 이슈를 열었다(2026-09-17). 상태 변화와 논의는 이슈에, 결정과 근거는 문서에 적는다.
