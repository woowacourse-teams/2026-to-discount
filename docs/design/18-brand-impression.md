# Design: 브랜드 탐색 노출 측정

> 관련 이슈: #18

## 1. 문제

### 배경

브랜드 상세 정보가 기본으로 펼쳐져 있어 `brand_expand`는 사용자가 한
세션에서 몇 개의 브랜드를 살펴봤는지 나타내지 못한다. 검색, 필터,
배달앱 링크 클릭처럼 명시적인 행동은 기록하지만 링크를 누르지 않고 할인
정보를 비교한 탐색 과정은 현재 데이터에 남지 않는다.

### 해결하려는 문제

빠르게 스크롤해 지나간 브랜드를 제외하면서, 사용자가 인식할 기회가 있었던
브랜드를 세션 단위로 집계할 수 있어야 한다.

## 2. 목표

- 브랜드 헤더 전체를 1초 이상 연속으로 본 브랜드를
  `brand_impression`으로 기록한다.
- 동일 세션에서 같은 브랜드를 여러 번 보더라도 한 번만 기록한다.
- 기존 자체 분석 원장과 PostHog에 같은 이벤트와 공통 문맥을 전달한다.
- 모바일과 PC에서 같은 의미의 노출 기준을 적용한다.

## 3. Non-goals

이번 작업에서 하지 않는 것:

- 브랜드 카드의 기본 펼침 상태나 UI 변경
- `brand_expand` 이벤트의 제거 또는 의미 변경
- 개별 할인 칩의 노출을 나타내는 `offer_impression` 추가
- PostHog 인사이트 또는 대시보드 생성
- 모바일과 PC에 서로 다른 노출 임계값 적용

플랫폼별 노출 대비 클릭률이 필요해지면 `offer_impression`을 별도 이슈로
추가할 수 있다.

## 4. 요구사항

### 필수

- 각 브랜드 카드의 로고와 브랜드 이름이 있는 `.brand-card__head`를
  `IntersectionObserver`로 관찰한다.
- 브랜드 헤더 전체가 보이는 상태가 1초 동안 연속되면
  `brand_impression`을 발생시킨다.
- 1초 전에 헤더 일부가 화면 밖으로 나가거나 문서가 숨겨지면 진행 중인
  타이머를 취소한다. 다시 보일 때는 1초를 처음부터 센다.
- 중복 방지 단위는 `(source_session_id, brand)`이다.
- 세션 중 새로고침해도 중복 이벤트가 발생하지 않아야 한다.
- 이벤트는 기존 `track()` 경로를 사용한다.
- 이벤트 고유 prop은 `brand`, `position`, `platforms`, `category` 네 개로
  제한한다.
  - `brand`: 노출된 브랜드 이름.
  - `position`: 필터와 정렬을 적용한 현재 목록에서 1부터 시작하는 순번.
  - `platforms`: 현재 카드에 표시된 플랫폼 키를 정렬해 `+`로 연결한 문자열.
  - `category`: 노출된 브랜드 자체의 카테고리 키. 미분류는 `none`.
- 필터 문맥, `variant`, `device`, `viewport` 등 기존 공통 속성을 그대로
  유지한다.
- 노출 측정 실패가 카드 렌더링이나 사용자 동작을 막지 않아야 한다.

### 선택

- 없음.

## 5. 제약사항

- 기술적 제약: 카드 전체는 상세 내용과 할인 칩 수에 따라 높이가 달라져
  관찰 대상으로 사용할 수 없다.
- 기술적 제약: 프리렌더 과정에서 브라우저 API가 없으므로 모듈 로드 시
  `window`, `document`, `IntersectionObserver`에 접근하면 안 된다.
- 기존 시스템 제약: 자체 API는 허용 목록에 없는 이벤트를 버리므로
  프론트와 API 이벤트 계약을 함께 갱신해야 한다.
- 기존 시스템 제약: 자체 API의 이벤트 prop은 `Map<String, String>`이고 최대
  8개이므로 `platforms`는 배열이 아닌 정렬된 문자열로 보낸다. 고유 prop
  4개를 먼저 두고 나머지는 기존 필터 문맥을 사용한다.
- 기존 시스템 제약: 현재 웹 테스트에는 DOM 테스트 라이브러리가 없다.
- 개인정보 제약: 브랜드 노출에는 기존 익명 세션 문맥만 사용하며 새로운
  사용자 식별 정보를 수집하지 않는다.

## 6. 성공 조건

- [ ] 사용자는 기존 화면과 상호작용의 변화를 느끼지 않는다.
- [ ] 브랜드 헤더 전체가 1초 연속 노출된 브랜드만 기록된다.
- [ ] 빠른 스크롤, 영역 이탈, 백그라운드 시간은 노출로 기록되지 않는다.
- [ ] 동일 세션·브랜드의 이벤트는 새로고침 이후에도 한 번만 기록된다.
- [ ] 모바일과 PC에서 동일한 판정 기준을 사용한다.
- [ ] 자체 원장과 PostHog가 동일한 `brand_impression`을 받는다.
- [ ] `brand`, 1-based `position`, 정렬된 `platforms`, 브랜드 `category`가
  노출 시점의 화면 상태와 일치한다.
- [ ] 이벤트 계약 및 노출 판정 테스트가 자동으로 검증된다.

## 7. 고려한 접근 방식

### A. 브랜드 카드 전체 관찰

설명: 카드 컨테이너가 일정 비율 이상 보이는 시간을 측정한다.

장점:

- 카드 컴포넌트에 관찰 ref 하나만 추가하면 된다.

단점:

- 상세 내용과 할인 칩 수에 따라 카드 높이가 달라진다.
- 카드가 화면보다 길면 노출 비율 임계값을 충족하지 못한다.
- 브랜드마다 노출 판정 난도가 달라질 수 있다.

### B. 할인 칩 관찰

설명: 대표 할인 칩 또는 개별 할인 칩이 보이는 시간을 측정한다.

장점:

- 특정 할인 정보를 볼 기회가 있었는지 측정할 수 있다.
- 향후 `offer_link_click`의 정확한 노출 대비 클릭률을 구할 수 있다.

단점:

- 플랫폼 필터와 할인 칩 수에 따라 브랜드별 관찰 대상이 달라진다.
- 브랜드 노출과 개별 할인 노출이라는 서로 다른 분석 단위를 섞는다.
- 개별 할인 노출은 별도 `offer_impression`으로 정의하는 편이 명확하다.

### C. 브랜드 헤더 관찰

설명: 크기가 안정적인 로고·브랜드 이름 영역 전체가 1초 이상 보일 때
브랜드 노출을 기록한다.

장점:

- 사용자가 해당 브랜드를 인식할 기회가 있었다는 의미가 명확하다.
- 플랫폼 필터와 할인 칩 수의 영향을 받지 않는다.
- 모바일과 PC에서 같은 기준을 적용할 수 있다.

단점:

- 개별 할인 칩을 실제로 봤는지는 알 수 없다.
- 플랫폼별 노출 대비 클릭률에는 별도 `offer_impression`이 필요하다.

## 8. 선택

선택한 방법: C. 브랜드 헤더 관찰

선택 이유: `brand_impression`의 분석 단위를 브랜드로 유지하면서 카드 높이,
플랫폼 필터, 할인 칩 수에 따른 편향을 피할 수 있다. 개별 할인 노출은
브랜드 노출과 의미가 다르므로 이번 범위에 섞지 않고 향후 필요할 때
`offer_impression`으로 분리한다.

## 9. 설계

### Architecture

브랜드 카드가 `.brand-card__head` DOM 요소와 브랜드 이름을 노출 측정 모듈에
등록한다. 측정 모듈은 하나의 `IntersectionObserver`로 등록된 헤더를
관찰하고, 전체 노출된 요소마다 1초 타이머를 관리한다. 조건을 유지한
브랜드는 세션 중복 기록에 추가한 뒤 기존 `track()`으로 이벤트를 보낸다.

브라우저 API와 저장소 접근은 React 렌더링 이후에만 초기화한다. 따라서
프리렌더 환경에서는 측정 모듈이 아무 작업도 하지 않는다.

### Components

#### `BrandCard`

- 책임: `.brand-card__head`를 노출 측정 모듈에 등록하고 제거 시 해제한다.
- 의존성: 노출 측정 모듈의 등록·해제 인터페이스.
- 외부 인터페이스: 브랜드 이름, 현재 목록 순번, 표시된 플랫폼, 브랜드
  카테고리, 관찰할 DOM 요소.

#### 브랜드 노출 측정 모듈

- 책임: 요소 관찰, 1초 타이머, 문서 가시성 처리, 세션 중복 방지.
- 의존성: `IntersectionObserver`, `document.visibilityState`,
  `sessionStorage`, `track()`.
- 외부 인터페이스: 관찰 요소 등록 함수와 등록 해제 함수.

#### 기존 분석 전송 경로

- 책임: `brand_impression`을 자체 API와 PostHog로 전달하고 공통 문맥을
  붙인다.
- 의존성: 기존 `analytics.js`, PostHog fan-out, API 허용 목록.
- 외부 인터페이스:
  `track('brand_impression', { brand, position, platforms, category })`.

### Data Flow

1. 필터와 정렬이 끝난 목록이 각 `BrandCard`에 1부터 시작하는 `position`을
   전달한다.
2. `BrandCard`가 `.brand-card__head`와 브랜드 이름, 순번, 표시된 플랫폼,
   카테고리를 측정 모듈에 등록한다.
3. 헤더 전체가 보이면 측정 모듈이 1초 타이머를 시작한다.
4. 헤더 일부가 화면 밖으로 나가거나 탭이 숨겨지면 타이머를 취소한다.
5. 1초 동안 조건이 유지되면 세션 중복 여부를 확인한다.
6. 처음 본 브랜드이면 세션 저장소에 기록하고 플랫폼 키를 정렬한 뒤
   `track('brand_impression', { brand, position, platforms, category })`을
   호출한다.
7. 기존 전송 경로가 필터와 기기, A/B 문맥을 붙여 자체 API와 PostHog로
   전달한다.
8. 컴포넌트가 제거되면 관찰과 진행 중인 타이머를 정리한다.

### Error Handling

- `IntersectionObserver` 미지원 → 이벤트를 생략하고 화면은 정상 동작한다.
- `sessionStorage` 읽기·쓰기 실패 → 페이지 수명의 메모리 `Set`으로 중복을
  방지한다.
- 컴포넌트 제거 또는 관찰 해제 → 진행 중인 타이머를 취소한다.
- 이벤트 전송 실패 → 기존 분석 전송 경로의 비차단 처리에 맡긴다.
- 잘못된 브랜드명 또는 DOM 요소 → 등록하지 않고 화면은 정상 동작한다.

## 10. 테스트 전략

- Unit: 가짜 시계와 관찰 상태로 1초 충족, 조기 이탈, 재노출, 중복 방지,
  가시성 전환, 등록 해제를 검증한다.
- Unit: 세션 저장소 복원과 저장소 실패 시 메모리 fallback을 검증한다.
- Unit: 순번이 1부터 시작하고 플랫폼 키가 정렬된 문자열로 정규화되며
  미분류 카테고리가 `none`이 되는지 검증한다.
- Contract: 프론트에서 발행하는 `brand_impression`이 API 허용 목록과 분석
  이벤트 계약에 포함되는지 검증한다.
- Integration: 각 브랜드의 `.brand-card__head`만 관찰 모듈에 등록되는지
  검증한다.
- Acceptance: 모바일과 PC 크기에서 1초 노출·빠른 스크롤·백그라운드 전환을
  수동 확인한다.

### 2. 브랜드 헤더 연결

  상태와 일치하며, 렌더링 반복과 제거 뒤 타이머나 Observer가 남지 않는지
  검증한다.
- 완료 조건: 기존 카드 UI와 클릭 동작을 바꾸지 않고 모든 브랜드에 동일한
  노출 기준이 적용된다.
