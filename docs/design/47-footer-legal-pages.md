# 47. 바닥글 정리: 브랜드 목록 접기, 고지문을 별도 페이지로

상태: **제안** (2026-10-13). 결정 전이다.

## 1. 문제

모바일 첫 화면 맨 아래가 길다. 360px에서 바닥글 고지문만 약 650px이고, 그 아래에 홈의 브랜드 링크 목록(`prerender.mjs` `brandNav`, 검색 노출용)이 붙는다. 할인 목록을 다 본 사람이 만나는 것은 긴 글 두 덩어리다.

- 고지문 여섯 문단(비영리, 수집 방식, 금액 기준, 자체 통계와 PostHog, GA4, 상표)이 한 번에 펼쳐져 있다.
- 브랜드 목록은 검색 엔진에 브랜드 페이지를 알리려고 둔 것이라 사람에게는 쓸모가 적다.
- 개인정보 처리 내용(통계, 검색어 기록, 쿠키)이 바닥글 문단 속에 섞여 있어 찾기 어렵다.

## 2. 지켜야 할 것 (법, 관례)

| 근거 | 요구 | 이 설계에서 |
|---|---|---|
| 개인정보 보호법 제30조, 개인정보위 「개인정보 처리방침 작성지침」 | 처리방침을 **누구나 쉽게 확인할 수 있게** 공개한다. 관례는 모든 페이지 바닥글에 "개인정보처리방침" 링크를 두고 다른 링크보다 눈에 띄게(굵게) 한다 | 별도 페이지 `/privacy` + 바닥글 굵은 링크 |
| 정보통신망법, 쿠키 사용 고지 관례 | 쿠키를 쓰면 무엇을, 왜, 어떻게 거부하는지 알린다(GA4가 쿠키를 쓴다) | `/privacy`에 쿠키 절. 거부 방법(DNT/GPC, 브라우저 설정) 그대로 |
| 표시·광고 공정화법, 소비자 오인 방지 | 금액이 확인일 기준이고 달라질 수 있다는 안내는 **가격 가까이, 숨기지 않고** | 바닥글에 한 줄로 **남긴다**(접지 않는다) |
| 상표 사용 관례 | 지칭 목적 사용과 권리 귀속을 밝힌다 | `/about`으로 옮기고 바닥글엔 링크 |
| 검색 엔진(구글 모바일 우선 색인) | 접힌 내용(`<details>`, 탭)도 HTML에 있으면 색인된다. 사람에게 영영 안 보이는 숨긴 글은 스팸으로 본다 | 브랜드 목록은 지우지 않고 `<details>`로 **사람이 펼칠 수 있게** 접는다 |

참고한 바닥글 관례: 배달의민족, 쿠팡이츠, 요기요, 토스는 모두 "이용약관 · **개인정보처리방침** · 고객센터" 링크 한 줄과 짧은 사업자 정보만 두고, 긴 고지는 별도 페이지에 둔다. 우리는 사업자가 아니라 약관 대신 서비스 소개와 문의를 둔다.

## 3. 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 바닥글 전체를 접기 하나로 | 한 줄로 끝 | 금액 기준 안내까지 숨는다(위 표 3행 위반). 처리방침 링크도 안 보인다 |
| **B (추천)** | 바닥글은 금액 안내 한 줄과 링크 한 줄. 긴 고지는 `/about`, `/privacy`로. 브랜드 목록은 `<details>`로 접기 | 관례와 같다. 법 요구를 다 지킨다. 첫 화면 바닥이 약 650px에서 약 120px로 | 페이지 둘을 새로 만든다(프리렌더 목록, 배포 경로) |
| C | 지금 그대로, 글만 줄인다 | 일이 적다 | 처리방침이 여전히 문단 속이다 |

## 4. 추천안 B의 모양

```
[할인 목록 끝]
금액은 확인일 기준이며 달라질 수 있어요. 주문 전에 각 앱에서 다시 확인하세요.
서비스 소개 · **개인정보처리방침** · 문의
▸ 브랜드별 할인 페이지 (161)        ← <details>, 기본 접힘
```

- `/about`: 지금 바닥글의 비영리, 제휴 없음, 수집 방식, 상표 문단.
- `/privacy`: 자체 통계, PostHog, 검색어 기록, Vercel Analytics, GA4(쿠키), 거부 방법, 문의처, 시행일. 처리방침 작성지침의 필수 항목 순서를 따른다.
- 두 페이지는 브랜드 페이지처럼 빌드 때 HTML로 만든다(`prerender.mjs`). 자바스크립트 없이 읽힌다.
- 브랜드 목록 `<details>`는 서버 HTML에 그대로 있어 색인이 유지된다. 펼친 상태는 기억하지 않는다.

## 5. 단계 (하나씩, 각 단계 프리뷰 승인 뒤 다음)

1. **브랜드 목록 접기.** `prerender.mjs` `brandNav`를 `<details><summary>`로. 검사: 브랜드 링크 수가 그대로인지(`verify-brand-route.mjs`).
2. **`/privacy` 페이지.** 지금 바닥글의 통계 두 문단을 옮겨 처리방침 형식으로. 바닥글에 링크.
3. **`/about` 페이지와 바닥글 축약.** 남은 문단을 옮기고 바닥글을 위 모양으로.
4. **사이트맵과 robots.** 두 페이지를 `sitemap`에 넣는다.

## 6. 정해 주셔야 할 것

- 문구 전부(바닥글 한 줄, 링크 이름, 두 페이지 본문). 화면 문구는 세션이 정하지 않는다(`CHANGE-PROPAGATION.md` 6절).
- 문의 경로: 지금은 "저장소 이슈"다. 공개 저장소 이슈로 둘지, 메일 주소를 둘지.
- 처리방침에 적을 보관 기간(자체 통계, 검색어 기록). 지금 정해진 값이 없다.

## 7. 같이 본 다른 개선 후보 (이번 범위 밖, 순서 제안)

| 순서 | 무엇 | 왜 |
|---|---|---|
| 1 | 새벽 안내 상자가 360px에서 바닥 배너 위 넓은 자리를 덮는다 | 마지막 화면 스크린샷에서 바닥글 글자를 가렸다. 한 줄로 줄이거나 닫기 버튼 |
| 2 | 운영 카드 쪽 첫 카드가 펼친 채로 시작한다 | 첫 화면에서 카드 하나가 화면을 거의 다 차지한다. 의도인지 확인 필요 |
| 3 | 빠른 정렬 줄과 스위치 사이가 좁다(360px) | 첫 방문 안내 2단계 스크린샷에서 "최소주문 낮은순"과 "5천원 이상만"이 붙어 보였다 |
