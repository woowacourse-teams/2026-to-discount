# 신규 할인 자동 알림

이슈: https://github.com/woowacourse-teams/2026-to-discount/issues/46

## 목표

수동 배너 등록 대신 신규 탭의 최고 할인 오퍼 1개를 매일 11:00~11:30 KST 사이 무작위 시각에 발송한다.

## 동작

- 웹 신규 탭 기본 기준을 사용한다. 한국 날짜 기준 firstSeenAt이 오늘이며 브랜드 최고 확정 할인인 오퍼만 후보가 된다.
- BrandComparisonService의 유효 오퍼를 사용하여 만료 오퍼를 제외한다. 품절, 불확정, 자사 채널, 금액 없는 오퍼도 제외한다.
- 후보 중 금액이 가장 큰 1개를 선택한다. 동액은 브랜드명, 플랫폼명 순으로 결정한다.
- 예약 시각에 후보가 없거나 활성 구독이 없으면 그날은 발송하지 않는다.
- 11시 이후 시작한 서버는 11:30까지 남은 구간에서 예약한다. 11:30 이후에는 뒤늦게 보내지 않는다.
- 예약 시각과 선택한 오퍼를 push 상태 파일에 보존한다. 재시작이나 부분 실패 시 성공한 구독에는 다시 보내지 않는다.
- 실패한 구독은 60초 간격으로 11:30 이전까지만 재시도한다.
- 재시도 중 선택한 오퍼가 유효 후보에서 빠지면 발송을 중단한다. 다른 오퍼로 교체하여 구독별 내용이 달라지지 않게 한다.
- 기존 배너 즉시 발송과 11시 요약 예약은 중단한다.
- 제목은 브랜드와 할인 혜택이며 본문은 ‘할인 시간과 적용 조건을 확인해 보세요.’이다. 클릭 목적지는 기존 서비스 페이지를 유지한다.

## 검증

신규 판정, 최대 할인 선택, 무작위 시각 범위와 저장, 부분 실패 후 재시작 중복 방지, 시간 범위 밖 발송 차단, 빈 후보, 알림 문구를 단위 테스트로 검증한다.

푸시 제공자가 요청을 접수한 직후 서버가 종료되면 성공 기록을 저장하지 못할 수 있다. 외부 전송과 파일 저장은 원자적이지 않으므로 이 구간의 중복 가능성은 남는다.

## 알림 대상 관리 API

- GET `/api/push/admin/next`: 다음 예약 시각, 자동 선정 대상, 실제 선택 대상, 교체 후보와 수정 가능 여부를 반환한다.
- PUT `/api/push/admin/next`: `mode`가 `replace`이면 조회 응답의 `offerId`로 교체하고, `exclude`이면 해당 날짜 발송을 제외하고, `auto`이면 자동 선정으로 복원한다.
- `date=YYYY-MM-DD`로 오늘 또는 내일을 지정한다. 생략하면 오늘의 미완료 예약을 사용하며 오늘 발송이 완료되거나 시간이 종료되었으면 내일을 사용한다.
- 자동 선정은 신규 탭 기본 기준을 유지한다. 수동 교체 후보는 해당 날짜의 유효한 신규 확정 할인 오퍼로, 브랜드 내 최고 할인보다 작은 신규 오퍼도 선택할 수 있다.
- 선택은 기존 Push 상태 파일에 저장되고 재시작 후에도 실제 발송에 반영된다. 교체와 제외는 예약 시각을 바꾸지 않는다.
- 발송을 시작했거나 완료했거나 해당 날짜의 발송 시간이 종료되면 변경 요청은 409로 거절한다. 부적절한 후보와 날짜는 400으로 거절한다.
- 발송 시작 상태를 전송 전에 저장해 일부 구독에 발송한 뒤 다른 내용으로 교체하는 것을 막는다.
- 기존 /ops Basic Auth를 재사용한다. beggars-ops의 deploy/nginx-delivery-discount-api.conf에서 관리 경로를 인증한 뒤 X-Ops-Authenticated 헤더를 붙여 내부 API로 전달한다. 별도 토큰은 필요하지 않다.
- API는 실제 연결 주소가 루프백이고 인증 표시가 있는 요청만 허용한다. 일반 공개 경로에서는 Nginx가 외부에서 보낸 인증 표시를 제거한다.
- 운영 적용에는 API 배포와 Nginx 설정 반영이 모두 필요하다. 콘솔은 같은 출처의 관리 경로로 요청해 기존 인증을 사용한다.
- 관리 콘솔 화면은 이 변경에 포함하지 않는다. 조회 응답의 candidates와 offerId를 이용해 별도로 연결한다.
