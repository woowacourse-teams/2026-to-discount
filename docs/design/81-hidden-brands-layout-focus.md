# Design: 모바일 숨긴 목록 버튼과 닫기 포커스 개선

이슈: [#81](https://github.com/woowacourse-teams/2026-to-discount/issues/81)
상태: 2026-10-15 설계 승인 및 구현, 로컬 검증 완료. PR 제출 준비.

## 1. 문제

390px 화면에서 정렬 버튼, 금액 필터, 숨긴 목록 버튼의 합산 너비가 사용 가능한 너비를 초과한다. 실제 배포 화면에서 숨긴 목록 버튼 오른쪽 끝이 449px로 측정됐다. 조작 영역에 줄바꿈이 없어 버튼이 잘린다.

숨긴 목록은 닫힌 상태에도 DOM에 남는다. 닫기 버튼에 포커스가 있는 채 부모에 aria-hidden을 적용하므로 브라우저가 접근성 경고를 출력한다. aria-hidden만으로 내부 버튼의 키보드 접근도 막을 수 없다.

## 2. 목표

- 모바일에서 모든 상단 조작 버튼을 화면 안에서 사용할 수 있게 한다.
- 목록 닫기 후 포커스를 여는 버튼으로 복원하고 닫힌 목록의 포커스 진입을 차단한다.

## 3. Non-goals

- 상단 배너 추가 또는 기존 하단 배너 배치 변경.
- 브랜드 숨김 규칙, 저장 방식, 정렬 및 금액 필터의 의미 변경.
- 다른 대화상자나 페이지 전체의 접근성 개편.

## 4. 요구사항

- 600px 이하에서는 정렬 버튼을 첫 줄에, 금액 필터와 숨긴 목록을 둘째 줄에 표시한다. 모든 버튼을 읽고 누를 수 있다.
- 일반 닫기 시 숨긴 목록 버튼으로 포커스를 복원한다.
- 마지막 숨긴 브랜드를 복원해 여는 버튼도 사라지면 남아 있는 상단 정렬 버튼으로 포커스를 이동한다.
- 닫힌 목록 내부는 클릭과 키보드 포커스 대상에서 제외한다.
- 기존 펼침 애니메이션과 브랜드 숨기기 및 취소 동작을 유지한다.

## 5. 제약사항

- 기존 데스크톱 한 줄 배치와 버튼 문구를 유지한다.
- 포커스 이동으로 불필요한 스크롤이 발생하지 않도록 한다.
- 현재 미커밋 문서 변경과 기존 작업 디렉터리를 보존한다.

## 6. 성공 조건

- [x] 320, 360, 390, 430px 화면에서 상단 조작 버튼의 경계가 화면 안에 위치한다.
- [x] 데스크톱에서 기존 조작 영역을 정상 사용할 수 있다.
- [x] 닫기 후 여는 버튼에 포커스가 있고 관련 aria-hidden 경고가 없다.
- [x] 닫힌 목록의 버튼으로 Tab 포커스가 들어가지 않는다.
- [x] 마지막 브랜드 복원 후 포커스가 사라지는 요소에 남지 않는다.
- [x] 브랜드 숨김 및 취소, 정렬과 금액 필터가 정상 동작한다.

## 7. 고려한 접근 방식

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 조작 영역 줄바꿈 | 기존 문구와 클릭 영역을 유지하며 좁은 화면에 대응 | 좁은 화면에서 조작 영역 높이 증가 |
| 버튼과 문구 축소 | 한 줄 유지 가능 | 가독성과 클릭 영역 축소, 향후 문구 길이에 취약 |
| 조작 영역 가로 스크롤 | 기존 너비 유지 | 사용자가 숨긴 목록 버튼을 발견하기 어려움 |

## 8. 선택

조작 영역 줄바꿈을 선택한다. 기능을 화면 안에 노출하면서 문구와 클릭 영역을 보존한다. 목록 닫기 전 포커스를 복원하고 닫힌 영역에는 inert를 적용한다.

## 9. 설계

- `web/src/styles/filter-sheet.css`: 조작 영역의 줄바꿈과 간격을 조정한다. 필요하면 숨긴 목록 버튼의 정렬 규칙을 함께 조정한다.
- `web/src/App.jsx`: 여는 버튼과 대체 포커스 대상의 ref를 보관한다. 일반 닫기와 마지막 브랜드 복원을 각각 처리하고 상태 updater 안에서 포커스 같은 부수 효과를 실행하지 않는다.
- `web/src/HiddenBrandsSheet.jsx`: 닫힌 영역의 inert 처리 및 기존 aria-hidden과의 일관성을 유지한다. 현재 화면 흐름 안에 표시되는 목록의 dialog 및 aria-modal 선언이 실제 포커스 동작과 맞는지도 이 컴포넌트 범위에서 점검한다.
- 흐름: 닫기 또는 마지막 항목 복원 → 남을 요소로 포커스 이동 → 목록 상태 갱신 → 닫힌 영역 접근 차단.
- 별도 네트워크 요청과 데이터 형식 변경은 없다.

## 10. 테스트 전략

- 구현 전 docs/의 모든 Markdown과 관련 저장소 규칙을 읽고 적용한다.
- 로컬 브라우저에서 모바일 네 가지 너비와 데스크톱의 요소 경계 및 기능을 검증한다.
- 키보드로 목록 진입, 닫기, 닫힌 목록 건너뛰기 및 마지막 항목 복원 후 포커스를 확인한다.
- 브라우저 콘솔에서 해당 접근성 경고의 재발 여부를 확인한다.
- `web/package.json`에 정의된 관련 검사와 빌드를 실행한다.
- `git diff`와 `git diff --check`로 변경 범위를 점검한다.
- 실제 운영 반영은 이번 착수 단계에 포함하지 않는다.

## 검증 기록

- `npm test`: 종료 코드 0. 기존 단위 테스트와 이벤트, 검색 및 필터, 브랜드 경로, API 주소와 문구 검사 통과.
- `npm run build`: 클라이언트 및 SSR 빌드와 프리렌더 통과. 최초 실행은 worktree 생성 파일의 쓰기 권한 제한으로 중단됐으며 동일 명령을 승인된 권한으로 재실행해 성공했다.
- 로컬 `?dev=1&home=a` 화면에서 320, 360, 390, 430, 600, 601, 1280px 조작 버튼 경계를 측정해 모두 화면 안에 있음을 확인했다. 600px 이하 두 줄 및 601px 이상 한 줄 배치를 확인했다.
- 390px에서 숨긴 목록 버튼 오른쪽 끝은 374px다. 기존 배포 화면에서 측정한 449px 초과를 해소했다.
- 닫기 후 활성 요소는 숨긴 목록 버튼이며 닫힌 영역에 inert 속성이 있다. 이후 Tab 18회 이동 중 숨긴 영역에 진입하지 않았다.
- 마지막 항목 복원 후 숨긴 목록 및 여는 버튼이 사라지고 활성 요소는 할인금액 높은순 버튼이다.
- `?dev=1&home=old`에서도 브랜드 두 개 숨김, 개별 취소, 닫기 및 정렬과 금액 필터 전환을 확인했다.
- 두 화면의 검사 중 브라우저 warn/error 기록은 없었다. 화면 내부 펼침 영역은 포커스를 가두지 않는 region으로 표시한다.
- 모바일 스크린샷: `/tmp/issue81-mobile-390.png`.
- 로컬 브라우저 검증이며 개발 배포 및 운영 배포 후 인수 검증은 미수행이다. 실제 모바일 Safari와 화면 읽기 프로그램 검증도 미수행이다.
