# 사용자 반응 집계(behavior.json) 매일 갱신 설계

작성일: 2026-11-18 · 상태: **승인 전** · 이슈 [#403](https://github.com/woowacourse-teams/2026-to-discount/issues/403) 후속 · 짝 문서: [INSIGHT-BEHAVIOR](../metrics/INSIGHT-BEHAVIOR.md)

## 결론

서버가 하루 한 번 자기 이벤트 원장(`events.jsonl`)에서 `scripts/insight_behavior.py`를 돌려 `behavior.json`을 다시 만든다. systemd 타이머(운영 서버가 정해진 시각에 작업을 시작하는 기능)로 돌리고, 코드는 운영 콘솔 저장소의 배포 목록(`push.sh`)이 서버에 올린다.

## 배경

- 운영 콘솔의 "사용자 반응" 탭은 API(`GET /api/admin/insight/behavior`)가 읽는 `behavior.json` 한 장으로 그린다. API는 파일의 수정 시각이 바뀌면 다시 읽는다.
- 2026-11-18 18:04에 손으로 한 번 올렸다. 갱신하는 작업이 없어 내일부터 낡는다.
- 원장은 약 378MB, 65만 줄이다(2026-11-18). 서버 메모리는 12GB, 파이썬 3.12가 깔려 있다.
- 집계 스크립트는 파이썬 표준 라이브러리만 쓴다(`experiments.py`, `snapshot.py`, `insight_behavior.py` 세 파일).

## 고른 길과 버린 길

| 길 | 판단 |
| --- | --- |
| **A. 서버 타이머 (고름)** | 원장이 서버에 있어 전송이 없다. 키와 네트워크가 필요 없다. 운영 콘솔 저장소에 이미 같은 모양의 타이머가 있다(백업, 빠른 점검). |
| B. 수집 PC 예약 작업 | 매일 378MB를 내려받고 다시 올려야 한다. 원장 캐시가 얼어 문서 4개가 같은 값이던 사건(2026-11-15)과 같은 구조다. PC가 꺼지면 멈춘다. |
| C. API 안에서 계산 | 방문자 거르기(`experiments.keep`)를 자바로 다시 짜야 하고 두 구현이 갈라진다. 요청 때가 아니라 매일 한 번이면 되는 계산에 상시 메모리를 쓴다. |

## 변경

- **타이머와 서비스 추가 (운영 콘솔 저장소):** `ops-insight-behavior.timer`(매일 05:30 KST)와 `.service`(oneshot). 백업(06:00)과 겹치지 않게 앞에 둔다. 실패하면 기존 실패 알림 서비스(`OnFailure`)로 알린다.
- **배포 목록 변경 (운영 콘솔 저장소):** `deploy/push.sh`가 mono의 세 스크립트를 서버의 전용 폴더에 올린다. 서버에서 저장소를 받지 않는다. 비공개 서버가 공개 저장소의 최신 코드를 스스로 받아 실행하는 길을 만들지 않으려는 것이다.
- **출력:** 원장과 같은 폴더의 `behavior.json`. 임시 파일에 쓴 뒤 바꿔 끼운다(스크립트가 이미 그렇게 한다). API가 반쪽 파일을 읽지 않는다.
- **탭에 갱신 시각 표시 (운영 콘솔 저장소):** 탭 머리에 `generatedAt`을 쓰고 36시간이 지났으면 낡았다고 알린다. 타이머가 조용히 멈춰도 사람이 알아본다.

## 열린 문제

- **원장이 쓰이는 중일 때 읽기:** 마지막 줄이 덜 쓰인 채 읽힐 수 있다. `experiments.load`가 깨진 마지막 줄을 건너뛰는지 구현 전에 확인한다. **미확인.**
- **서버에서의 시간과 메모리:** 수집 PC에서는 같은 원장으로 돌아갔다. 서버에서 걸리는 시간과 최대 메모리는 재지 않았다. **미확인.** API와 같은 서버라 `Nice`와 `MemoryMax`를 걸어 API를 밀어내지 않게 한다.
- **스크립트 사본의 낡음:** 서버에 올린 세 파일은 `push.sh`를 돌릴 때만 새로 고쳐진다. mono에서 이 스크립트를 고치면 같은 PR 설명에 "운영 콘솔 배포 필요"를 적는다.

## 이번 설계에 넣지 않는 것

- E 구역의 남은 칸(금액대별 클릭률, 배너 대 카드 비교)과 3단계(재방문 코호트, 선호). 별도 이슈로 나눈다.
- 갱신 주기를 하루보다 짧게 하는 것. 사용자 반응 지표는 일 단위로 읽는다.

## 리뷰 포인트

1. 갱신 시각을 05:30으로 두어도 되는가(백업 06:00 앞).
2. 스크립트를 `push.sh`로 올리는 방식으로 충분한가, 서버가 mono를 직접 받아야 하는가.
3. 낡음 경고 기준 36시간이 맞는가.
