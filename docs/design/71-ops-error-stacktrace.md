# Design: 운영 오류 목록의 전체 스택트레이스 조회

이슈: [#71](https://github.com/woowacourse-teams/2026-to-discount/issues/71)
상태: 운영 코드 PR #15 병합 및 자동 배포 완료. 운영 기동, 인증 차단 및 Loki 조회 확인. 실제 운영 ERROR 원문 대조는 대상 기록이 없어 미수행.

## 1. 필요 배경

- 현 상황: `/ops` 오류 목록에는 최대 240자의 첫 줄만 표시돼 전체 스택트레이스를 확인하려면 Grafana에서 별도로 검색해야 한다.
- 위험 존재: 오류가 발생한 코드 위치와 원인 예외를 즉시 확인하기 어려워 장애 원인 파악과 대응이 지연될 수 있다.

## 2. 목표

목록에서 오류를 선택하면 `/ops` 안에서 발생 시각, 요청 ID와 전체 예외 원문을 조회한다.

## 3. Non-goals

- 수집 주기, ERROR/WARN 집계 및 Slack 알림 정책 변경.
- Loki 보관 기간 변경과 오래된 압축 원본의 자동 검색.
- 성능 지표, WARN 전체 원문의 Loki 조회 및 범용 로그 검색 도구.

## 4. 요구사항

- 최근 ERROR 목록과 저장된 ERROR 이력에서 상세 조회 제공.
- 전체 메시지와 Caused by, Suppressed 및 프레임을 텍스트로 표시.
- 요청 ID가 없는 기존 기록도 발생 시각과 첫 줄로 정확히 식별 가능한 경우 조회.
- 기록 없음, 보관 기간 경과 가능성, 인증 및 통신 실패를 구분.
- 기존 Basic Auth, 집계, 알림과 관리 기능 유지.

## 5. 제약사항

- 로그 저장 및 전송은 #72에서 구축한 Grafana Cloud Loki를 사용한다. 상세 파일을 다시 자체 저장하는 이전 안은 채택하지 않는다.
- 무료 보관 기간은 14일이다. 그보다 오래된 이력의 조회 성공을 보장하지 않는다.
- Alloy가 묶은 로그 블록을 그대로 조회한다. 4096줄 초과 블록 분할 및 미전송 기록까지 원문을 복원하지는 못한다.
- Nginx 502, 504에는 API 예외 기록이 없을 수 있다. 기존 API ERROR 목록을 대상으로 한다.
- Loki 조회용 logs:read 토큰을 별도로 준비한다. 기존 전송 토큰과 분리하고 브라우저 및 응답에 포함하지 않는다.
- 현재 ops-apply는 단일 HTTPServer로 배너 변경도 처리한다. 외부 조회 지연이 관리 기능을 막지 않도록 구성한다.

## 6. 성공 조건

- [ ] 선택한 오류와 동일한 시각 및 요청 ID의 원문이 표시된다.
- [ ] 스택의 원인 예외와 마지막 프레임까지 수집된 내용을 보존한다.
- [ ] 유사한 오류가 여러 개면 임의로 다른 요청의 상세를 보여주지 않는다.
- [ ] 상세 조회 실패에도 기존 목록과 배너 관리가 동작한다.
- [ ] 미인증 상세 요청이 차단되고 토큰은 서버 밖으로 노출되지 않는다.

## 7. 고려한 방식과 선택

| 방식 | 장점 | 한계 |
| --- | --- | --- |
| Grafana Explore 링크 | 구현이 작음 | /ops 안에서 상세를 보려는 목표를 충족하지 못함 |
| 기존 ops-apply에 조회 추가 | 새 프로세스 불필요 | 단일 요청 처리로 관리 작업이 지연될 수 있음 |
| 같은 서버의 조회 전용 서비스 | 조회 지연을 배너 관리에서 분리 | service 및 배포 설정 추가 필요 |

선택: 기존 운영 서버에 조회 전용 서비스를 추가하고 Loki에서 읽는다. 별도 서버는 만들지 않는다.

## 8. 설계

### 흐름

`/ops 오류 선택 → 인증된 Nginx 상세 경로 → 조회 전용 서비스 → Loki query_range → 원문 표시`

### 목록과 오류 식별

- 기존 240자 요약과 집계를 유지한다. 각 ERROR 요약의 해시를 조회 ID로 사용한다.
- backend는 api.json 및 errors.jsonl에서 이 ID에 해당하는 기록을 찾는다. 클라이언트가 임의 쿼리나 파일 경로를 지정하지 못하게 한다.
- 발생 시각은 로그 첫 줄에서 읽는다. errors.jsonl의 at은 수집 시각이므로 조회 시각으로 사용하지 않는다.
- 요청 ID가 있으면 운영 API 라벨, 좁은 발생 시각 범위와 요청 ID로 조회하고 ERROR 첫 줄까지 대조한다.
- 요청 ID가 없으면 발생 시각과 첫 줄을 대조한다. 여러 후보가 일치하면 구분 불가로 표시하고 다른 오류를 임의 선택하지 않는다.
- 줄이나 시각을 해석하지 못하는 레거시 기록은 상세 조회 불가로 표시한다.

### 조회 서비스

- localhost 전용 포트의 읽기 전용 HTTP 서비스. 조회 ID만 입력으로 받는다.
- Loki endpoint와 서비스 및 환경 조건은 서버 설정으로 고정한다.
- logs:read 토큰은 접근 제한된 서버 파일에서 읽는다.
- 시간 범위, 반환 건수, 응답 크기와 대기 시간을 제한한다. 초과하면 전체 조회 완료로 표시하지 않는다.
- 짧은 성공 결과 캐시와 동시 조회 제한으로 반복 클릭의 API 호출을 줄인다.
- 401/403, 429, timeout, 빈 결과 및 응답 형식 오류를 구분하고 인증 정보나 원시 오류 응답은 전달하지 않는다.

### 콘솔

- 최근 수집과 저장 이력을 하나의 오류 및 경고 목록으로 통합한다. 동일 줄의 중복을 제거한다.
- 수준, 로거, 경로와 메시지가 같은 기록은 하나로 묶고 발생 횟수와 마지막 시각을 표시한다. 메시지 내용이 다르면 합치지 않는다.
- 기본 기간은 최근 24시간이며 최근 7일과 전체를 선택할 수 있다. ERROR/WARN 필터와 메시지, 경로, 요청 ID 검색을 제공한다.
- 목록은 짧은 메시지, 경로, 수준, 횟수와 시각만 표시한다. 표시 건수와 페이지 나누기는 제한하지 않고 이전 마지막 80줄 제한도 제거한다.
- 오류 행 아래 접이식 상세 영역에 발생 시각, 요청 ID, 전체 텍스트 및 복사 버튼을 표시한다. 묶인 오류도 개별 발생 기록을 선택해 조회한다.
- 검색은 발생 기록에 먼저 적용하므로 요청 ID 검색 결과에서 해당 요청의 원문을 조회한다. WARN은 상세 영역에서 기존 요약만 표시한다.
- 로딩, 재시도, 결과 없음과 구분 불가 상태 표시. 보관 기간이 지난 경우 만료 가능성을 안내한다.
- 로그는 textContent로 출력해 HTML이 실행되지 않도록 한다.

### 인증 및 운영

- 새 `/ops` 상세 경로에도 기존 Basic Auth 적용. localhost backend를 외부에 직접 노출하지 않는다.
- 조회 서비스 실패 시 목록 및 기존 ops-apply는 계속 동작한다.
- 구현 저장소는 beggars-ops이며 작업 브랜치에서 main으로 반영하고 운영 검증한다.

## 9. 테스트 전략

- Backend: 오류 ID 검증, 시각 해석, 요청 ID 없는 기록, 유사 후보, 조회 제한 및 오류 응답 처리.
- UI: 통합, 중복 제거, 그룹화, 기간 및 수준 필터, 요청 ID 검색, 상세 패널, 개별 발생 기록 선택, 복사, 실패 및 HTML 문자열의 텍스트 표시.
- 호환: 기존 ERROR/WARN 집계와 이력, Slack 알림 및 배너 관리 회귀 검증.
- 인수: 격리된 예외 fixture로 실제 Loki 조회와 /ops 원문 표시 대조. 운영 API를 인위적으로 실패시키지 않는다.
- 접근: 미인증 401, 토큰 미포함 응답 및 조회 장애 중 기존 관리 기능 확인.

## 10. 미해결 사항

- 운영 배포 후 인증 및 실제 오류 원문 인수 검증. 현재 운영 ERROR 목록에는 대상 기록이 없다.
- 이슈 담당자, 스프린트 및 마감일 미지정.

## 구현 및 로컬 검증 기록

- 2026-10-14: 기존 localhost:4173 데모에 반영. 운영 스냅샷을 사용하며 목록은 자동 갱신하지 않는다. 상세는 SSH 단건 명령으로 운영 서버에서 조회한다.
- 읽기 토큰은 운영 서버의 `/home/ubuntu/.grafana_logs_read`에 0600으로 저장돼 있으며 Loki 조회 권한을 확인했다. 토큰 값은 로컬로 가져오지 않았다.
- Python 전체 테스트 290개 통과. 새 backend 테스트 18개와 SSH 및 스냅샷 테스트 5개 포함.
- 오류 상세, 묶기, 스키마, 알림 및 외부 가용성 JavaScript 검사 통과. Python 문법, JavaScript 문법, 배포 쉘 문법과 `git diff --check` 통과.
- 브라우저에서 API 화면, 운영 WARN 이력과 추세 표시 확인. 운영 ERROR 기록은 0건이므로 실제 운영 스택트레이스 표시까지 검증한 것은 아니다. 원인 예외와 프레임 보존은 mock Loki 응답으로 검증했다.
- 새 Nginx 경로의 실제 인증 검사와 service 인수 검증은 운영 배포 후 수행한다.
- 추가 승인: 표시 건수 제한을 제외한 목록 통합, 요약, 반복 기록 그룹화, 검색 및 필터, 별도 상세 패널 개선을 반영한다.
- 로컬 더미 ERROR 15건은 4개 유형이며 같은 오류 12회의 개별 기록을 선택할 수 있다. 더미 자료는 Loki로 전송하지 않는다.
- 브라우저에서 12회 그룹의 개별 요청 전환과 원문 복사, 요청 ID 검색 1건, 전체 기간 WARN 이력 416건의 19개 유형 표시를 확인했다.

- 후속 화면 수정: 수준 필터의 전체 선택 문구는 `모두`로 변경하고 상세는 사이드 패널 대신 오류 행 아래에서 접고 펼친다. 브라우저에서 펼침과 접기를 확인했다.

- 펼침 및 접기 시 스크롤 좌표를 보존하고 접은 뒤 문서 높이 감소로 브라우저가 위치를 보정하지 않도록 처리한다. 접기 버튼의 포커스 이동도 스크롤하지 않는다. 심볼은 오른쪽 삼각형과 아래쪽 삼각형으로 표시한다. 4173 브라우저에서 펼침과 접기 전후 scrollY 차이 0px 확인.
