# Design: 선택한 혜택 공유하기

상태: 2026-10-28 사용자 구현 승인. 구현 및 로컬 검증 완료. 모바일 실기 및 배포 환경 인수 검증은 남아 있다.
연결 이슈: https://github.com/woowacourse-teams/2026-to-discount/issues/191

## 1. 문제

### 배경

Notion의 유입 급증 시기 사용자 행동 분석과 사용자 행동 분석 기반 기능 선정에서 개별 혜택 공유를 다음 실험으로 선정했다. 빠르게 선택한 혜택의 전달이 새로운 사용자의 할인 선택으로 이어지는지 확인하려는 가설이다. 공유 수요가 입증된 것은 아니다.

### 해결하려는 문제

현재 브랜드 단위 진입 경로는 있지만 선택한 혜택을 지정해 전달하는 사용자 흐름이 없다.

## 2. 목표

- 개별 혜택에서 기기 기본 공유 또는 링크 복사 제공.
- 공유 링크를 연 사람이 해당 혜택의 금액과 조건을 바로 확인하고 기존 할인 링크 이용.
- 공유 시도부터 수신자의 할인 선택과 이후 관측 가능한 재방문까지 연결할 수 있는 이벤트 제공.

## 3. Non-goals

- 실험 기간 및 정량 성공 기준 설정.
- 특정 메신저 SDK, 계정 연결, 공유 이미지 생성.
- 개별 혜택용 링크 미리보기와 해당 혜택별 메타데이터 생성. 공유 메시지에 혜택을 담고 링크 진입 시 대상을 바로 표시한다.
- 실제 주문이나 만족 측정.

## 4. 요구사항

### 필수

- 기존 할인 링크와 분리된 공유 버튼 제공. 링크 안에 버튼을 중첩하지 않는다.
- 카드 오른쪽 위에서 가리기, 공유하기, 링크 복사 순서로 아이콘 버튼을 배치한다. 아이콘은 가리기 버튼과 같은 크기와 선 굵기를 사용한다. 카드에서는 현재 대표 혜택을 공유하고 상세 영역에서는 개별 혜택별 공유를 유지한다.
- `공유하기`는 개별 혜택의 공유 문구와 해당 혜택으로 이동하는 URL을 함께 전달한다.
- 공유 문구는 `브랜드명과 앱명, 할인 혜택 → 최소주문 조건 → 필수 조건` 순서로 구성한다. 항목별로 줄을 나누고 정보가 없는 항목은 생략한다. 최대 할인이나 멤버십 등 적용 조건을 유지한다.
- `링크 복사`는 해당 혜택으로 이동하는 URL만 복사하며 공유 문구는 포함하지 않는다. 기본 공유 미지원 환경에서도 링크 복사를 제공한다.
- 기본 공유 취소는 정상 종료로 처리. 복사 실패 시 성공 표시 금지.
- 수신 화면은 선택한 혜택을 식별하고 기존 검색 필터나 숨김 설정으로 가려지지 않게 한다.
- 공유한 혜택이 변경되거나 만료 또는 삭제되어 더 이상 일치하지 않으면 안내 후 기본 홈 화면을 표시한다. 다른 혜택이나 해당 브랜드 화면으로 자동 대체하지 않는다.
- 버튼에 키보드 접근과 접근 가능한 이름 제공.
- 아래 이벤트 계약에 따라 공유 클릭부터 수신자의 할인 선택까지 기록하고 기존 수집 거부 설정을 준수한다.

### 선택

- 링크 복사 버튼은 항상 제공한다. 공유하기 버튼은 기본 공유 API 지원 환경에서 제공한다. 카드의 공유 아이콘은 현재 대표 혜택을 대상으로 한다. 상세 영역에는 각 혜택의 공유 및 복사 아이콘을 제공한다.

## 5. 제약사항

- 기존 브랜드 경로와 SSR을 유지한다. 클라이언트 전용 API는 사용자 동작 시점에 호출한다.
- 혜택 데이터는 갱신되므로 배열 순서나 금액만으로 공유 대상을 식별하지 않는다. 실제 식별 필드와 API 계약을 구현 전 확인한다.
- 작업 브랜치: feat/191-offer-sharing. origin/dev 기준으로 생성했으며 기존 사용자 편집본은 그대로 보존한다.
- 화면 문구는 COPY-STYLE.md에 따라 승인받은 문구를 사용한다.

## 6. 성공 조건

- [x] 혜택별 공유 버튼으로 문구와 URL을 전달하고 링크 복사는 URL만 전달한다. 기본 공유 호출은 단위 테스트, 복사는 로컬 브라우저 검증 완료.
- [x] 새 탭에서 링크를 열어 해당 혜택과 조건을 바로 확인할 수 있다. 브라우저 검증 완료.
- [x] 기존 할인 링크 이동이 유지된다.
- [x] 기본 공유 취소, 복사 실패, 만료 또는 잘못된 링크를 구분한다.
- [x] 관련 단위 테스트와 웹 빌드가 통과한다.
- [x] 공유 시도, 유입, 할인 선택의 식별값 연결과 API 원장 기록 및 PostHog 매핑을 테스트로 확인했다. 개발 환경에서 실제 PostHog 수신은 배포 후 확인한다.
- [x] 같은 혜택 및 다른 혜택 선택, 자기 링크 확인, 새로고침, 직접 재방문을 구분할 수 있다.

## 7. 고려한 접근 방식

### A. 기존 브랜드 화면에 혜택 지정 링크 추가

기존 브랜드 경로에 혜택 식별 정보를 추가하고 해당 혜택을 펼쳐 강조한다. 기존 카드와 앱 이동을 재사용하지만 검색 및 숨김 설정과 충돌하지 않도록 처리해야 한다.

### B. 별도 혜택 상세 화면 추가

공유 대상 하나를 독립 화면으로 제공한다. 수신 대상을 명확하게 보여줄 수 있으나 라우팅과 별도 화면 및 SSR 처리 범위가 커진다.

## 8. 선택

선택: A. 기존 카드의 개별 혜택을 펼쳐 해당 항목으로 이동하고 강조한다. 쿠폰 카드는 기존 상세 시트에서 해당 혜택을 표시한다.

## 9. 설계

### Architecture

공유 링크 생성과 대상 식별은 순수 함수로 분리한다. 브라우저 공유 및 클립보드 호출은 UI 동작에서 수행한다. URL에는 데이터에서 확인 가능한 대상 식별 정보만 포함하고 사용자나 세션 식별값을 넣지 않는다.

### Components

- 공유 유틸리티: URL 생성, 안전한 파싱, 현재 데이터에서 대상 확인.
- 혜택 공유 버튼: 기본 공유, 복사, 결과 표시. 기존 카드 유형에 공통 적용.
- App과 카드: 공유 대상 브랜드 및 혜택 표시와 이동. 기존 앱 링크 재사용.

### Data Flow

1. 사용자가 혜택의 공유 버튼을 누른다.
2. 해당 혜택의 서비스 URL을 생성한다. 기본 공유에는 공유 문구와 URL을 함께 전달하고 링크 복사에는 URL만 넣는다.
3. 수신 시 현재 데이터에서 대상을 확인하고 해당 혜택을 펼쳐 표시한다.
4. 사용자가 기존 할인 링크로 이동한다.

### Error Handling

- 기본 공유 취소: 오류나 복사 동작 없이 종료. 기본 공유 미지원 환경에서는 URL만 복사하는 링크 복사 버튼을 제공한다.
- 공유 불가: 복사 경로 제공.
- 복사 실패: 실패를 알리고 링크를 직접 복사할 수 있는 수단 제공.
- 대상 변경, 없음 또는 만료: 해당 혜택을 확인할 수 없다고 안내한 후 기본 홈 화면을 표시한다. 다른 혜택이나 해당 브랜드 화면으로 자동 이동하지 않는다.

### 공유 링크의 개별 혜택 도착 검토

확인 기준: 현재 작업 사본과 로컬 origin/dev 참조. 실제 공유 링크 도착 동작은 아직 구현 및 브라우저 검증 전이다.

- 현재 App의 해시 처리는 브랜드만 지정한다. BrandCard와 CouponCard는 해당 브랜드를 펼치고 카드로 스크롤한다. 개별 혜택의 위치나 캐러셀 선택은 지정하지 않는다.
- Offer 응답에는 영속적인 개별 혜택 ID가 없다. filters.offerKey는 플랫폼과 랜덤 및 선착순 구분으로 표시 칸을 식별하는 React 키이며, 기간이 다른 행사를 구분하지 못한다.
- 링크에는 브랜드와 공유 대상 혜택의 식별값을 포함한다. 브랜드명과 offerKey만으로 대상을 확정하지 않는다. 금액, 최소 주문, 조건, 만료일, 구간 할인 등 사용자에게 보이는 혜택 내용의 정규화된 서명을 함께 검증하는 방식을 검토한다. 수집 시각이나 정렬 순서는 서명에 사용하지 않는다.
- 현재 데이터에 일치하는 대상이 있으면 해당 혜택이 있는 펼침 영역 또는 캐러셀을 열고, 실제 혜택 요소까지 스크롤해 강조한다. 공유 대상이 검색, 플랫폼 필터, 브랜드 숨김 또는 지연 렌더링 때문에 가려지지 않도록 한다.
- 같은 브랜드와 플랫폼이어도 금액이나 조건이 달라졌다면 동일 혜택으로 이동시키지 않는다. 대상 없음 또는 변경 사실을 안내한 후 기본 홈 화면을 표시한다. 과거 데이터가 없으면 사라진 이유를 만료로 단정하지 않는다.
- 접힌 혜택, 캐러셀의 두 번째 이후 혜택, 같은 플랫폼의 일반 및 랜덤 및 선착순 혜택, 필터 및 숨김 설정이 있는 브라우저, 데이터 변경 및 만료 상태를 인수 테스트한다.

### 이벤트 계약

기존 brand_impression과 공유 클릭 및 수신 후 할인 선택을 연결해 분석한다. 별도의 offer_share_impression 이벤트는 추가하지 않는다. 이벤트명과 속성은 구현 시 최신 dev의 계약과 대조하되 아래 의미를 유지한다.

| 이벤트 | 발생 조건 | 주요 속성 |
| --- | --- | --- |
| 기존 `brand_impression` 재사용 | 기존 브랜드 카드 노출 기준 유지 | 기존 브랜드, 위치 속성 |
| `offer_share_click` | 개별 혜택 공유 버튼 클릭 | `shareId`, 대상 혜택, 브랜드, 플랫폼, 공유 방법 |
| `offer_share_result` | 기본 공유 또는 복사 결과 확정 | `shareId`, `method`, `result` |
| `offer_share_landing` | 유효한 형식의 공유 링크로 실제 화면 진입 | `shareId`, `landingId`, 대상 혜택, `selfOpen`, `visitorStatus` |
| `offer_share_target_view` | 수신 화면에서 대상 조회 완료 및 결과 표시 | `shareId`, `landingId`, `targetStatus` |
| 기존 `offer_link_click` 확장 | 공유 유입 세션에서 임의 혜택의 할인 링크 클릭 | `shareId`, `landingId`, `sharedOfferKey`, `offerKey`, `selectionRelation` |
| 기존 `page_view` 확장 | 공유 유입 이후 같은 브라우저의 후속 방문 | `entrySource`, 공유 이력의 `shareId`, `attributionType` |

- `shareId`는 공유 동작마다 새로 만드는 난수다. 공유자 visitorId나 sessionId를 URL에 넣지 않는다. 기존 공유 링크를 받은 사람이 다시 공유하면 새 shareId를 발급한다.
- 대상 식별값은 혜택 표시와 클릭 이벤트에 동일한 규칙으로 적용한다. 할인 금액만 같다는 이유로 같은 혜택으로 처리하지 않는다. 구현은 사용자에게 보이는 플랫폼, 금액, 조건, 기간과 구간 내용을 정규화한 SHA-256 식별값을 사용한다. 수집 시각, 정렬 순서, 신규 및 품절 표시는 식별값에서 제외한다.
- 기본 공유 결과는 `resolved`, `cancelled`, `failed`로 구분한다. `resolved`는 브라우저 API 완료이며 실제 전달 완료를 뜻하지 않는다. 복사는 `copied`, `failed`로 구분한다. 오류 원문이나 공유 대상 연락처는 수집하지 않는다.
- 노출은 기존 brand_impression의 브랜드별 중복 제거 기준을 유지한다. 지표는 브랜드 카드 노출 대비 공유 클릭률로 해석하며 개별 버튼 노출률로 해석하지 않는다. 유입과 대상 결과는 화면 진입별 1회 기록하고 재렌더 중복을 막는다. 새로고침은 새 진입으로 기록하되 기존 sessionId와 visitorId로 세션 수 및 방문자 수를 별도 집계한다.
- `targetStatus`: `available`, `expired`, `not_found`. 잘못된 형식의 URL은 정상 공유 유입으로 세지 않는다. 데이터 조회 실패를 `not_found`로 기록하지 않는다.
- `selectionRelation`: `shared_offer`, `same_brand_other_offer`, `other_brand`. 기존 offer_link_click를 재사용해 할인 선택을 이중 집계하지 않는다.
- 공유 맥락은 같은 수신 세션에서 필터 변경과 다른 브랜드 탐색 후에도 유지한다. 새로운 공유 링크 진입은 새 유입으로 구분한다.
- 신규 여부는 최초 방문 여부를 기존 브라우저 식별 체계로 관측할 수 있을 때만 `new` 또는 `returning`으로 기록한다. 기존 저장소가 있어도 최초 관측 시점을 알 수 없다면 `unknown`으로 기록한다.
- 자기 링크 확인은 로컬에 저장한 공유 시도 이력과 대조한다. 다른 기기로 옮겨 연 동일인을 식별할 수는 없다.
- 이후 직접 재방문은 `entrySource=direct`와 `attributionType=prior_share`로 구분한다. 같은 세션의 공유 전환은 `attributionType=share_session`으로 기록한다. 직접 재방문을 새 공유 유입으로 세지 않는다. 재방문 관측 기간은 관련 가설 세팅에서 정한다. prior_share는 마지막 공유 수신 이력과 시각을 나타내는 관측 속성이며 전환 귀속을 확정하지 않는다. 분석에서 shareReceivedAt을 기준으로 가설의 관측 기간을 적용한다.
- 수집 거부 시 이벤트를 보내지 않는다. 모든 이벤트에 기존 eventId를 사용해 전송 재시도 중복 제거를 유지한다.
- 서버 EventController의 이벤트 허용 목록, 속성 수 제한(MAX_PROPS)과 문자열 길이 제한을 함께 확인한다. 새 속성이 잘려 공유 연결이 사라지지 않도록 계약 테스트를 추가한다.
- 기존 원장과 SDK fan-out 경로를 사용한다. PostHog SDK로 별도 직접 전송해 중복 이벤트를 만들지 않는다.

분석 가능한 항목: 브랜드 카드 노출 사용자 대비 공유 시도 사용자, 공유 링크 유입 사용자, 유입자 대비 할인 선택 사용자, 공유 혜택 및 다른 혜택 선택 비중, 관측 가능한 재방문. 건수와 고유 사용자 및 세션 수를 구분한다. 공유 링크 유입과 후속 행동의 연관을 관측하며 인과 효과나 실제 주문으로 단정하지 않는다.

## 10. 테스트 전략

- Unit: URL 인코딩과 파싱, 대상 식별, 잘못된 링크와 변경된 혜택, 공유 취소와 복사 실패.
- Analytics: 공유 흐름별 이벤트와 연결 속성, 취소 및 실패 구분, 재렌더 중복 방지, 새로고침과 자기 링크 확인, 다른 혜택 선택, 재방문 귀속 및 수집 거부.
- Integration: 기존 브랜드 경로와 SSR 호환성 및 카드 유형별 버튼 제공.
- Acceptance: 모바일 기본 공유, 데스크톱 복사, 새 브라우저 진입, 만료 대상, 기존 할인 링크 이동.
- 검증 명령: web에서 npm run test:unit, npm run test:brand-route, npm run test:copy, npm run build.
- 계측 검증: npm run test:event-contract, npm run test:analytics, npm run test:posthog 및 API의 EventController와 PostHogEventMapper 관련 테스트. 개발 환경에서 원장과 PostHog 기록을 함께 확인한다.

## 11. 확정 사항

- 미정 사항 없이 구현을 시작하도록 사용자 승인.
- 공유 문구는 브랜드와 앱, 할인 혜택, 최소주문 조건, 필수 조건 순서로 구성한다. 최대 할인, 랜덤, 선착순, 멤버십 및 구간 조건을 유지한다.
- 공유하기는 문구와 URL을 전달하고 링크 복사는 URL만 복사한다. 개별 혜택 미리보기는 제공하지 않는다.
- 혜택 변경, 만료 또는 삭제 시 안내 후 기본 홈 화면을 표시한다.
- 재방문 관측 기간은 관련 가설 세팅에서 다룬다. 기능에 특정 기간을 강제하지 않는다.
- 마지막 공유 수신 이력 1개와 수신 시각을 기존 방문자 저장소와 같은 브라우저 범위에서 보관한다. 자기 링크 확인용 ID는 최근 100개를 보관한다. 수집 거부 시 이 저장소를 읽거나 갱신하지 않는다.

- web에서 npm run build: 클라이언트 빌드, 실제 API 기반 브랜드 115개 사전 렌더링과 SSR 빌드 통과.
- api에서 ./gradlew test --tests '*EventControllerTest' --tests '*PostHogEventMapperTest': 테스트 24개 통과. 새 이벤트 허용, 28개를 초과하는 연결 속성 보존 및 PostHog 속성 매핑 검증.
- 구조 생성기의 테스트 5개와 구조 문서 --check 통과. 기본 명령은 기존 _workspace 및 홍보자료_261020 폴더 때문에 중단되므로, 해당 두 작업자료 경로만 임시 Git 제외 파일로 제외해 생성 및 검사했다. 영구 Git 설정과 사용자 자료는 변경하지 않았다.
- 시스템 Python 3.9는 생성기의 newline 인자를 지원하지 않고 pytest가 없어 실행에 실패했다. 번들 Python과 /private/tmp의 전용 가상환경에서 생성 및 테스트를 완료했다.
- git diff --check 통과. 기존 사용자 문서는 작업 전 보관본과 바이트 단위로 일치함을 확인.
- 로컬 픽스처 API와 브라우저: URL 복사 성공, 일반 7,000원 혜택, 선착순 8,000원 혜택, 숨긴 브랜드의 랜덤 10,000원 혜택의 정확한 항목 이동과 포커스 확인. 다른 혜택으로 대체하지 않는 기본 홈 전환과 상세 닫기 확인.
- 로컬 수신 기록에서 공유 클릭, 복사 결과, 유입, 대상 표시 및 기존 offer_link_click의 식별값 연결 확인. 화면 진입별 유입 및 대상 표시 중복 없음 확인.
- npm audit: 기존 dompurify, esbuild, nanoid, source-map-js, vite의 취약점 5건으로 종료 코드 1. 추가한 @noble/hashes는 영향 목록에 없다. 기존 의존성 보안 업데이트는 별도 후속 작업이다.

### 남은 인수 확인

- 모바일 실기: 개별 혜택의 공유하기를 눌러 기본 공유 시트를 열고 메신저로 전달한다. 확정한 혜택 문구와 URL이 함께 전달돼야 한다.
- 별도 브라우저 또는 기기: 받은 URL을 열면 공유한 혜택이 펼쳐지고 해당 항목으로 이동해야 한다. 혜택이 변경되거나 사라졌다면 안내와 기본 홈 화면이 표시돼야 한다.
- 개발 배포 후: 공유 유입과 할인 선택을 실행해 API 원장 및 PostHog에서 같은 shareId와 landingId를 확인한다. 신규 공유 이벤트와 확장 속성을 받도록 API를 웹보다 먼저 또는 함께 배포한다.
- 재방문 관측 기간과 성공 기준은 관련 가설 세팅에서 결정한다. 이번 기능은 이를 특정 기간으로 고정하지 않는다.
