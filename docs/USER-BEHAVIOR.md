# 사용자 행동 — 무엇이 성공이고 어디서 새는가

원장(`events.jsonl`) 기준. 개발 트래픽은 뺐다(2,963명 중 102명 —
`experiments.py`의 `looks_developer()` 하나로 판정한다). 각 수치 옆에
어떤 명령으로 뽑았는지 적었다.

**집계 구간**: 2026-07-29 ~ 2026-08-27. 원장 스냅샷이 08-28 00:39에
끊겨 08-28은 하루치가 아니다 — 추이에서 뺀다.

---

## 성공 신호를 무엇으로 잡았나

```
전환 = offer_link_click  OR  banner_click
```

배달앱으로 나가는 **모든** 길이다. 그 뒤는 우리가 볼 수 없으므로 여기가
끝이다.

둘을 합쳐야 하는 이유가 있다. 한동안 `offer_link_click` 하나로 셌는데,
2026-08-19에 배너를 도입하면서 나가는 길이 하나 더 생겼다. `banner_click`은
그 이전 구간에서 **구조적으로 0**이라, 옛 정의로 전후를 비교하면 개편
이후가 무조건 낮게 나온다. "재방문 반토막"으로 읽었던 것이 실은 이
착시였다([ANALYTICS-CAPABILITY.md](ANALYTICS-CAPABILITY.md) §5.2).

이번에 `experiments.py`의 `--goal` 기본값을 둘의 합집합으로 바꿨다 —
정의를 문서에만 적어 두면 다음에 또 틀린다.

## 1. 성공 신호의 규모

`experiments.py compare --by returning`

```
모수 2,861명 · 전환자 1,028명 — 35.9%
```

주 단위 추이. 홍보일(07-31, 08-05, 08-10, 08-18, 08-24, 08-25)은 유입이
인위적이라 **포함·제외를 나란히** 뒀다. 제외하면 방문자가 3분의 1로
줄어드는 주가 있다 — 그만큼 홍보 의존이 크다.

| 주(월) | 방문자 | 전환율 | 홍보일 뺀 방문자 | 전환율 |
|---|---|---|---|---|
| 07-27 | 928 | 37.6% | 282 | 39.4% |
| 08-03 | 517 | 48.0% | 328 | 48.2% |
| 08-10 | 476 | 34.0% | 318 | 36.5% |
| 08-17 | 694 | 25.5% | 292 | 30.1% |
| 08-24 | 804 | 35.4% | 215 | 27.4% |

**홍보일을 빼도 08-03 정점(48.2%) 이후 내리막이다.** 마지막 주만
포함/제외 방향이 갈리는데(35.4% vs 27.4%), 그 주는 홍보일이 이틀 연속
(08-24, 08-25) 들어 있어 제외 후 표본이 215명까지 줄어든다. 한 주로
판단할 값이 아니다.

## 2. 어디서 새는가

`experiments.py paths`

세션 5,724개의 첫 3동작. **퍼널을 그리지 않고 실제로 밟은 순서를 셌다** —
없는 흐름을 단계로 놓으면 "여기서 78% 이탈" 같은 허수가 만들어진다
(§5.1). `brand_expand`는 링크 앞보다 뒤에 오는 일이 더 많아 전 단계가
아니라 사후 확인 행동이다.

| 경로 | 세션 | 비중 | 그중 전환 |
|---|---|---|---|
| **(아무것도 안 함)** | **3,314** | **57.9%** | 0 |
| offer_link_click | 727 | 12.7% | 727 |
| category_change | 283 | 4.9% | **0** |
| category_change > offer_link_click | 117 | 2.0% | 117 |
| brand_expand | 116 | 2.0% | **0** |
| membership_open | 73 | 1.3% | **0** |
| platform_filter_toggle | 66 | 1.2% | **0** |
| banner_click | 66 | 1.2% | 66 |

### 읽는 법

**가장 큰 손실은 아무것도 안 하고 나가는 57.9%다.** 다른 모든 이탈을
합친 것보다 크다. 화면을 보고 그냥 나간다 — 필터도 검색도 안 건드린다.

**전환한 세션은 대부분 첫 동작이 곧바로 링크다**(727/5,724 = 12.7%).
탐색을 거쳐 전환하는 경로는 전부 2% 미만이다. 즉 이 제품은 "둘러보다
고르는" 도구가 아니라 **"보자마자 누르거나 안 누르거나"**에 가깝다.

**뭔가 하나 건드리고 나간 무리가 뚜렷하다.** 분류 변경(283) · 펼침(116) ·
멤버십(73) · 플랫폼 필터(66) — 합쳐 538세션(9.4%)이 **한 동작만 하고
전환 없이 끝났다.** 조작은 했는데 원하는 걸 못 찾았다는 뜻이다. 이쪽이
"아무것도 안 함" 다음으로 손댈 만한 층이다.

## 3. 재방문 — 사람 단위와 세션 단위가 반대로 나온다

### 3.1 사람 단위

`experiments.py compare --by returning`

| 집단 | 방문자 | 전환 | 전환율 | 95% 구간 | 중앙 | 최다 1명 |
|---|---|---|---|---|---|---|
| 신규 | 2,085 | 543 | 26.0% | 24.2~28.0% | 1 | 18 |
| 재방문 | 776 | 485 | **62.5%** | 59.0~65.8% | 2 | 124 |

`z=18.07, p<0.0001` — 유의.

접속일수를 늘려 보면 더 가팔라 보인다.

| 접속일수 | 인원 | 비중 | 전환율 |
|---|---|---|---|
| 1일+ | 2,861 | 100% | 35.9% |
| 2일+ | 471 | 16.5% | 68.2% |
| 5일+ | 112 | 3.9% | 85.7% |
| 10일+ | 41 | 1.4% | 90.2% |

### 3.2 세션 단위 — 뒤집힌다

여기서 멈추면 "재방문하게 만들면 전환한다"로 읽는다. **틀렸다.**
재방문자는 세션이 여러 개라 전환 기회도 여러 번이다. 기회를 맞춰 세면
방향이 반대다.

| 세션 종류 | 세션 | 전환 | 전환율 | 95% 구간 |
|---|---|---|---|---|
| 첫 방문일 | 3,600 | 1,025 | **28.5%** | 27.0~30.0% |
| 재방문일 | 2,157 | 526 | **24.4%** | 22.6~26.2% |

`z=-3.38, p=0.0007` — 유의.

**한 번의 방문만 놓고 보면 재방문이 오히려 덜 전환한다.** 사람 단위
62.5%는 "여러 번 오면 언젠가 한 번은 누른다"는 누적 효과였지, 재방문
그 자체가 전환을 만든 게 아니다.

동작률도 같은 방향이다.

| 세션 종류 | 동작한 세션 | 세션당 중앙 | 평균 |
|---|---|---|---|
| 첫 방문일 | 1,616 / 3,600 (44.9%) | 2개 | 3.6개 |
| 재방문일 | 796 / 2,157 (36.9%) | 2개 | 3.9개 |

재방문 세션은 **더 자주 아무것도 안 하고 나간다**(63.1% vs 55.1%).
다만 동작을 시작하면 조금 더 깊게 본다(평균 3.9 vs 3.6). 확인하러 왔다가
바뀐 게 없으면 그냥 나가는 모양새다 — 데이터가 하루 한 번만 갱신되는
것과 맞물린다.

### 3.3 얼마 만에 다시 오나

2일 이상 온 471명 기준.

```
첫~마지막 간격  중앙 9일 (최대 29일)
방문 간 간격    중앙 2일
간격 분포       1일 699회, 2일 204회, 3일 107회, 4일 81회, 5일 62회, 6일 52회
```

**다시 오는 사람은 빨리 온다.** 간격의 최빈값이 1일이고 중앙값이 2일이다.
"주말에만" 같은 주기성은 안 보인다.

### 기능과 전환율의 관계 — 인과가 아니다

같은 명령이 "기능을 쓴 사람의 전환율"을 따로 낸다. `filters_apply`를 쓴
사람의 85.0%가 전환했지만(안 쓴 사람 35.6%), **이건 인과가 아니다.**
무엇이든 조작하는 사람이 링크도 누른다. 이 표는 "이 기능을 밀면 전환이
오른다"의 근거가 될 수 없다.

## 5. 이 지표로 무엇을 해야 하는가

우선순위는 손실 크기 순이다.

**① 첫 화면 무동작 57.9%를 줄인다.** 다른 모든 이탈을 합친 것보다 크고,
신규·재방문 양쪽에서 거의 같다(57.4% / 58.2%). 화면을 보고 판단이 끝나
버린다는 뜻이므로, 고칠 지점은 필터나 검색이 아니라 **첫 화면에 무엇이
보이는가**다. 검증: 첫 화면 구성을 바꾼 뒤 무동작 세션 비중이 내려가는지.

**② 재방문자에게 "바뀐 것"을 보여준다.** 재방문 세션이 첫 방문보다 덜
전환하고(24.4% vs 28.5%) 더 자주 무동작으로 끝난다. 확인하러 왔는데 어제와
같은 화면이면 나갈 이유가 된다. "오늘 새로 생긴 것" / "곧 끝나는 것"을
표시하는 것이 직접 대응이다. 검증: 재방문일 세션의 무동작 비중.

**③ 배너는 보이는데 안 눌린다.** 노출 89.9% 대 클릭 12.1%. 배너 자체를
더 띄우는 건 답이 아니다 — 이미 다 본다. 무엇을 띄우느냐의 문제다.

**④ 한 동작만 하고 나간 538세션(9.4%)을 본다.** 분류·펼침·필터를
건드렸는데 전환이 0인 무리다. 조작 의사는 있었으므로 "원하는 걸 못
찾았다"에 가깝다. 이 세션들의 다음 동작이 왜 없는지가 다음 질문이다.

**⑤ A/B는 아직 판정할 수 없다.** `a 40.2% / b 41.8%, z=0.48, p=0.63`.
상대 15% 차이를 잡으려면 갈래당 1,056명이 필요한데 현재 482/445다.
**"차이 없음"이 아니라 "표본 부족"이다.** 지금 트래픽으로는 큰 차이만
잡히므로, 작은 개선은 A/B 대신 경로·이탈로 판단한다.

## 한계

- **`visitorId`는 `localStorage` 난수다.** 한 사람이 여러 방문자로
  **쪼개지는** 오염(브라우저 데이터 삭제, 시크릿창, 기기 여럿)은 못 막는다.
  따라서 방문자 수는 상한, 재방문 층 규모는 하한으로 읽어야 한다.
  반대 방향(여럿이 하나로 뭉치는 것)은 없다.
- **봇 판별이 없다.** 지금 규모에서 큰 문제로는 안 보이지만 확인한 적은
  없다.
- **전환 이후는 안 보인다.** 앱으로 나간 뒤 실제 주문 여부는 우리 데이터가
  아니다. "전환"은 어디까지나 이탈 지점의 이름이다.
- **08-28은 하루치가 아니다**(원장이 00:39에 끊김). 추이에서 뺐다.
- 홍보일 제외는 매번 손으로 해야 한다. 도구 기본값으로 옮길지는 아직
  안 정했다.

## 뽑은 명령

```bash
python scripts/experiments.py audit                  # 개발 트래픽 판정
python scripts/experiments.py daily                  # 일별
python scripts/experiments.py segments               # 차원별 일람
python scripts/experiments.py compare --by returning # 신규 vs 재방문
python scripts/experiments.py paths --limit 40       # 실제 경로
python scripts/experiments.py paths --only returning
python scripts/experiments.py features               # 기능 수명
```

접속일수 분포·재방문 간격·세션 단위 비교는 `experiments.py`에 명령이 없어
따로 계산했다. 다만 **판정은 다시 구현하지 않았다** — 모듈로 불러
`load()`와 `looks_developer()`를 그대로 썼다. 개발 트래픽 규칙이 두 곳에
생기면 반드시 갈린다(§6-④).
