### 본문에는 "왜"를 적는다

무엇을 바꿨는지는 diff가 말한다. 본문은 **왜 그 선택이었는지, 무엇을
버렸는지**를 적는다. 특히:

- **실측 근거**: 언제 무엇을 확인했는지. `(2026-08-05 실기 확인)` 같은
  표시가 나중에 이 판단을 되짚을 때의 유일한 단서다.
- **버린 선택지**: 검토했지만 안 간 길. 안 적으면 다음 사람이 그 길을
  처음부터 다시 밟는다.
- **자기 실수**: 되돌리는 커밋이면 무엇을 잘못 봤는지 적는다. 같은 착오가
  반복되는 걸 막는 건 결과가 아니라 원인 기록이다.

예:

```
fix: 청년피자 땡겨요를 통째로 내린 걸 되돌린다 — 만료된 건 tiers 중 하나뿐

레코드에 쿠폰이 둘 있었다(tiers 9,000원 / 5,000원). 만료된 건 청피데이
9,000원이고 8월 상시 5,000원은 살아 있는데, expiresAt 하나만 보고 레코드를
통째로 지웠다. rawText가 "청년피자 5,000원 할인"인 것만 봤어도 알 수 있었다.

tier마다 만료일이 따로 없어서 생긴 일이기도 하다.
```

## 코드 주석

**주석은 코드가 말하지 못하는 것만 적는다.** 무엇을 하는지가 아니라 왜
이렇게 됐는지, 특히 **그렇게 안 하면 무엇이 깨지는지**.

```python
# 객체 동일성(`is`)으로 비교하면 안 된다 — _prefer는 이긴 쪽을 그대로
# 돌려주지 않고 진 쪽의 상세를 병합한 새 dict를 만든다. 그래서 이겼는데도
# 늘 "졌다"고 나온다(2026-08-05에 실제로 112건 중 60건을 틀리게 보고했다).
```

날짜와 실측 사례를 붙인다. "이럴 수 있다"보다 "이랬다"가 훨씬 강하다.

## 문서

- **수치는 코드·실데이터에서 뽑는다.** 손으로 옮긴 숫자는 다음 변경에서
  어긋난다.
- **줄 번호는 적지 않는다.** 한 번만 고쳐도 표 전체가 무효가 된다. 파일명과
  심볼명으로 가리킨다.
- **낡은 문서는 지우지 말고 상태를 바꾼다.** ADR은 `대체됨`으로 표시하고
  원문을 남긴다 — 그때 왜 그렇게 판단했는지가 다음 판단의 재료다.
