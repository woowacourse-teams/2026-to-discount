# 리워드 설문 — 왜 다시 오는지 묻는다

- 날짜: 2026-08-31
- 상태: 설계 확정, 구현 전

## 무엇을 알고 싶은가

**고정 사용자가 이 서비스에서 실제로 무엇을 얻는지.** 원장은 무엇을
눌렀는지까지만 안다. 왜 눌렀는지는 물어봐야 나온다.

지표만으로는 못 읽은 것이 이미 있다. 사람 단위로 재방문자 전환율이
62.5%라 "재방문이 전환을 만든다"로 읽었는데, 세션 단위로 보면 재방문
세션이 오히려 낮았다(24.4% vs 첫 방문 28.5%, z=-3.38, p=0.0007). 사람
단위 수치는 기회가 쌓인 착시였다. 같은 원장을 두 가지로 읽을 수 있다는
뜻이고, 어느 쪽이 맞는지는 데이터가 아니라 사람이 안다.

## 누구에게 묻는가

```
접속일 7일 이상  AND  전환(offer_link_click | banner_click) 5회 이상
```

실측(2026-08-29 원장, 개발 트래픽 제외): **41명(전체 3,166명의 1.3%),
그중 최근 7일에도 온 사람 34명.**

넓히지 않는 이유는 리워드다. 기프티콘을 주고 물으므로 응답률이 20~40%로
올라가고, 34명이면 **7~14건**이 나온다. 자유 서술을 읽기에 충분한 수이고,
더 넓히면 리워드 비용만 늘어난다.

## 무엇을 묻는가

한 문항. 객관식 셋과 직접 입력 하나.

```
어떻게 쓰고 계신가요?

  ○ 할인 정보 보려고        discount_info
  ○ 배달비 아끼려고         save_money
  ○ 앱끼리 비교하려고       compare
  ○ 직접 입력  [        ]   other + text
```

객관식이 먼저인 이유는 응답률이다. 자유 서술만 두면 쓰기 귀찮아 대부분
닫는다. 고른 사람은 토큰 하나만 남기고, 할 말이 있는 사람만 글을 쓴다 —
**문턱은 수로 보고 이유는 글로 본다.**

## 언제 보여주는가

**진입 즉시.** 대상 판정이 이미 필터라서 시점으로 또 거를 이유가 없다.

방해를 걱정할 수 있는데 실측이 반대를 가리킨다 — **재방문 세션의 63.1%가
아무것도 안 하고 나간다**(첫 방문 55.1%보다 높다). 대부분은 어차피 아무
동작도 안 하므로, 설문이 그 세션에서 유일하게 하는 행동이 될 수 있다.

### 다시 안 띄우는 규칙

```
답함        영구히 안 뜸
닫음 1회    3일 뒤 다시
닫음 2회    영구히 안 뜸
```

## 어디에 그리는가

**브랜드 카드 그리드의 첫 줄에 카드 한 장.** 크기와 모서리를 브랜드
카드와 같게 해서 이물감을 줄인다.

배너 슬롯에 끼우지 않는다. 배너는 4.3초마다 넘어가는데 설문은 머물러야
하고, 배너 클릭률(최근 7일 12.1%)에 설문이 섞이면 둘 다 못 읽는다.

진입 모달도 아니다. 하려던 일을 막는 방식이라 첫 화면 이탈(57.9%)을
키운다.

## 판정은 서버가 한다

앞선 초안은 프론트가 `localStorage`로 판정하게 했다. **리워드가 붙으면서
그 판정이 위조 가능해졌다** — `localStorage`는 사용자가 고칠 수 있고, 그
값이 기프티콘을 내주는 조건이면 누구나 받아간다.

원장이 서버에 있으므로 서버가 직접 센다.

```
GET  /api/survey                       지금 이 visitorId가 대상인가 + 남은 코드가 있나
POST /api/survey  {visitorId, choice, text}
     1. 원장에서 접속일수·전환수를 센다      (7일+ / 5회+)
     2. 이미 받았는지 본다                   (1인 1회)
     3. 남은 코드를 하나 꺼내 잠그고 응답을 원장에 적는다
     4. 코드를 응답으로 돌려준다
```

설문 제출은 하루 몇 건이라 매번 원장을 훑어도 부담이 없다(현재 38,791건,
1초 미만).

### 브라우저를 갈아치우면?

새 `visitorId`는 접속일 0일·전환 0회라 **대상 자체가 안 된다.** 다시
대상이 되려면 7일을 실제로 써야 하고, 그건 기프티콘 하나보다 비싸다.
조건 자체가 방어다.

## 기프티콘

서버 파일 하나에 둔다. 프론트 번들에 넣으면 누구나 읽는다.

```
gifticons.yml   [{code, issuedTo, issuedAt}, ...]
```

`export.json`·`banners.yml`과 같은 방식으로 jar 밖 경로를 물린다
(ADR-001). **저장소에 올리지 않는다** — 값을 가진 문자열이다.

**소진되면 설문이 자동으로 내려간다.** `GET /api/survey`가 남은 수를 같이
답하고, 0이면 프론트가 안 그린다. 줄 것이 없는데 묻는 일이 없다.

발급은 원자적이어야 한다. 서버가 단일 인스턴스이므로 파일 잠금 하나로
충분하다.

## 원장에 무엇을 남기나

새 이벤트 `survey_answer` 하나.

```
choice   discount_info | save_money | compare | other      고정 토큰
text     직접 입력. 200자 상한. other일 때만
```

`choice`가 토큰이라 세는 것은 안전하다. `text`만 거름을 탄다.

### 개인정보

이 서비스는 자유 입력 원문을 안 남겨 왔다 — 검색 계측이 `query`를 버리고
`inputLength`·`resultCount`만 적는다. 다만 그건 자유 텍스트라서가 아니라
**전화번호·주소가 섞여 들어올 수 있어서**였다(`EventControllerTest`가
`010-1234-5678`을 넣어 안 남는 것을 고정한다).

설문은 우리가 무엇을 물을지 정하므로 특정성이 들어올 통로를 설계로 막을
수 있다. 세 겹으로 막는다.

| 겹 | 무엇 |
|---|---|
| 묻는 방식 | 개인정보를 부를 질문을 하지 않는다 |
| 길이 상한 | 200자. 긴 사연이 들어올 자리를 주지 않는다 |
| 서버 거름 | 전화·이메일·주민번호 꼴을 잘라낸다 |

세 번째가 핵심이다 — 사용자가 실수로 넣어도 원장에 안 닿는다.
`brand_search_submitted`의 props 화이트리스트가 쓰는 자리와 같다.

### ADR-015와의 관계

충돌하지 않는다. 리워드는 **지출**이지 수익이 아니다. 그 ADR이 "비영리"로
막은 것은 광고·제휴 수수료이고, 뒤집을 조건도 "수익화하면 다시 본다"이다.

## 효과를 어떻게 재는가

**대상자를 가르지 않는다.** 41명을 반으로 쪼개면 응답이 한 자릿수 초반이
되어 주 목적이 죽는다.

대신 같은 대상자의 **전후 전환율 추이**를 본다. 순수 전후 비교보다 낫다 —
대상 정의가 고정이라 같은 사람들의 전후이기 때문이다.

**규칙 하나: 설문 배포일에 다른 변경을 같이 내보내지 않는다.** 이
프로젝트는 이미 한 번 밟았다 — 08-19 배너 도입 때 "재방문 전환 반토막"으로
읽었는데 `banner_click`이 그날 생겨 이전 구간이 구조적으로 0이었다
(ANALYTICS-CAPABILITY.md §5.2). 추이가 갈릴 때 원인이 하나여야 한다.

## 검증

- `verify-analytics-event-contract.mjs`가 `survey_answer`를 자동으로 잡는다
  — 프론트에 있는데 서버 화이트리스트에 없으면 CI가 실패한다
- `EventControllerTest`에 전화번호를 넣어 `text`에 안 남는 것을 고정한다
- 서버 판정(7일+/5회+)에 경계값 테스트: 6일·4회는 거절, 7일·5회는 통과
- 코드 발급이 두 번 나가지 않는 것을 동시 요청으로 확인한다
- 노출·닫기·응답 수는 기존 `experiments.py features`가 그대로 읽는다

## 안 하는 것

| | 왜 |
|---|---|
| 연락처 수집 | 묵명성이 깨지고 보관·삭제 절차가 필요해진다 |
| 여러 문항 | 길어질수록 응답률이 떨어진다. 한 문항으로 시작한다 |
| A/B 분할 | 모수 41명을 쪼개면 주 목적이 죽는다 |
| 서버에 닫기 상태 저장 | 개인 상태다. `visitorId`가 이미 지는 한계를 같이 진다 |

## 뒤집을 조건

- **응답이 3건 미만이면** 대상을 넓히거나(5일+/3회+ = 55명) 묻는 방식을
  바꾼다. 리워드를 걸고도 안 오면 질문이 잘못된 것이다.
- **전환율이 눈에 띄게 떨어지면** 진입 즉시를 접고 "앱에서 돌아왔을 때"로
  옮긴다.
- **기프티콘이 계속 남으면** 대상이 너무 좁은 것이다.
