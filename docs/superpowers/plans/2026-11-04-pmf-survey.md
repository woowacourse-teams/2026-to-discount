## 로컬 실행

저장소 루트에서 다음을 실행한다.

```bash
bash scripts/dev-pmf.sh
```

- 웹: `http://localhost:5173/`
- 화면만 확인: 오른쪽 위 `알림 안내` 버튼 아래 `설문 띄우기` 클릭.
- 서버 저장까지 확인: `http://localhost:5173/?pmfDemo=1`
- 새 서버 데모 사용자: `http://localhost:5173/?pmfDemo=1&pmfReset=1`
- API: `http://localhost:8081`
- API 메트릭스: `http://localhost:9091`
- 종료: 실행 터미널에서 Ctrl+C.
- 원장과 실행 로그: OS 임시 폴더의 `beggars-pmf-local/`.

기존 포트가 사용 중이면 스크립트가 중단한다. 기존 프로세스를 임의로 종료하지 않는다.
API는 local 프로필에서만 데모 사용자 생성 경로 `/api/survey/demo`를 등록한다.
데모 사용자는 전부 `dev=true`로 기록한다. 운영 원장과 쿠폰 저장값은 사용하지 않는다.
스크립트의 웹 API 주소는 localhost로 고정하고 PostHog와 푸시 전송을 끈다.
운영 설문은 기본적으로 종료 상태다. 모집 기간을 확정한 뒤 서버의 `discount.pmf.enabled`를 켜야 한다.

## 화면 후속 수정

- 모든 문항에서 항목 선택 전 다음 비활성, 선택 후 활성. 기타는 직접 입력까지 요구.
- 두 번째 문항부터 이전과 다음 또는 제출 버튼을 같은 줄에 동일 너비로 배치. 이전은 회색.
- X 아이콘을 모달 바깥 위쪽에 배치.
- 닫기 확인은 설문을 유지한 채 그 위에 표시하고 뒤 설문은 비활성 및 회색 처리.
- 실제 콘텐츠와 visualViewport 크기로 배율을 계산해 내부 스크롤 없이 표시.
- 360x568에서 가장 긴 문항과 기타 입력 영역의 모달 내부 스크롤 없음 및 외부 X 버튼 수용 확인.

## 문항별 크기 고정

- 모든 제목을 같은 폭에서 미리 측정하고 최대 선택지 수 7개를 기준으로 공통 영역 확보.
- 기타 직접 입력 122px, 건너뛰기 및 오류 안내 영역을 처음부터 예약.
- textarea 크기 변경 비활성. 기타 선택 전후에도 모달의 자연 높이와 배율 유지.
- 모달 배경에 overflow:clip을 적용해 숨겨진 스크롤 영역의 자동 포커스 이동도 차단.
- 360x800에서 1~3번 문항과 기타 선택 전후 모달 높이 724px, 상단 44px 및 버튼 위치 동일 확인.
- 360x568에서도 문항과 기타 선택 여부에 따른 모달 크기 및 버튼 위치 동일, 내부 스크롤 없음 확인.

## 진행도와 기타 선택 처리

- 진행 번호는 1/3부터 현재 문항을 표시하고 바는 0%에서 시작.
- 현재 문항 선택 시 한 칸 채움. 다음 문항에 진입한 것만으로 추가로 채우지 않음.
- 기타 직접 입력은 선택이다. 공백과 미입력도 다음 및 제출 가능하며 내용이 있을 때만 원장에 정제해 저장.
- 진행선 오른쪽 아래 번호 추가. 선택지, 기타 예약 영역 및 버튼 위 여백 축소.

## 최종 계측

기존 survey_impression, survey_open, survey_dismiss, 서버 survey_answer를 재사용한다.
닫기 확정은 survey_dismiss의 source=dock/card로 구분한다. 서버 survey_closed는 영구 닫기 복원용이다.
문항별 조작은 survey_interaction의 action으로 question_viewed, option_selected,
previous_clicked, next_clicked, skip_clicked, submit_step_clicked, submit_clicked,
close_requested, close_cancelled, close_confirmed, submit_failed, dismiss_failed를 구분한다.
문항 속성은 question, step, value이며 자유 입력 내용은 조작 이벤트에 싣지 않는다.
개발용 안내 미리보기도 preview=true로 설문 계측을 보낸다. 실제 응답은 저장하지 않고 완료는 survey_interaction의 action=preview_completed로 구분한다. 서버가 기록하는 실제 survey_answer는 미리보기에서 발생하지 않는다.
